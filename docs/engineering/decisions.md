# 现行设计决策

核对日期：2026-11-10。按产品、原生能力、交互和工程主题组织；不再使用阶段性 D 编号。整理前的全文在 `165caa4:docs/engineering/decisions.md`，更早材料见[历史追溯](#历史追溯)。

产品行为以[需求](../product/requirements.md)为准，实现约束在[架构](architecture.md)，完成状态在[路线图](../roadmap.md)。本文保留仍有效的理由、取舍和边界，已经撤销的方案仅通过 Git 查询。

## 1. 产品与开发顺序

### 原生会话是主体，先完成对话

**背景与选择：** 用户要集中使用本机多个 CLI 的项目和会话。先交付三个 CLI 的新建、续接、流式、中断与原生参数，权限交互遵循各自机制，再补配置，之后建设插件。

**理由与约束：** 只读列表是基础，能连续完成日常对话才是主流程。三种 CLI 已有对话与历史接线，真实模型回合仍须按来源单独验证。后续配置、插件和本地交付都沿用这一优先级；一个会话固定一个 CLI，不跨 CLI 转换上下文。

**替代：** 取代旧「同步到服务器后运行」主线和插件先行顺序；工作台不成为多 Agent 编排平台。

### Electron 加壳，沿用 Node 与 React

**背景与选择：** 正式入口是 Windows 桌面窗口。保留 Node.js + TypeScript + Fastify、React + Vite + Tailwind、前后端共享协议，由 Electron 管理本机服务和窗口。

**理由与约束：** 现有 CLI 适配与 SSH 都在 JavaScript 生态，重写语言无法直接改善当前主流程；Electron 已具备单实例和退出清理。后端只监听回环，渲染器不开放 Node 集成，系统能力通过窄接口；浏览器只作开发调试入口。当前选择 electron-builder 的本地 Windows x64 NSIS/portable 目标，签名、公开发布与自动更新不在此轮交付中。

**替代：** 不改用 Tauri、Go 或 Python 后端，不把 Node 打成另一个独立服务可执行文件。重计算不放进请求处理线程。

### 自有工作台插件，不兼容 DSH 插件包

**背景与选择：** 用户希望以后按需增加功能。采用 AgentDeck 自有插件接口，SSH Console 作为首个内置业务插件；v1 的本地安装、权限、页面及生命周期契约见[插件接口](workbench-plugins.md)。

**理由与约束：** 独立插件接口可以适配多 CLI 工作台，而无需持续模拟 DSH 的模块加载、Remote、槽位和内部服务。插件化须有明确入口、资源所有权、启停及兼容行为；成熟基础设施可复用，但不提前造市场或大框架。

**替代：** 明确放弃原样安装 DSH 插件和兼容层。旧项目工具保留原接口，通过 SSH Console 内的明确入口访问；其终端随插件停用释放，已有配置与任务不迁移或删除。

## 2. CLI 接入与数据归属

### 按原生能力接入，保留差异

**背景与选择：** CLI 的协议、工具、权限和配置层级不相同。每个适配器声明并核实实际能力，统一呈现不改变其语义。

**理由与约束：** 官方接口最清楚当前目录可用的模型、命令、技能和原生操作；不支持的能力应如实缺省，不能为统一外观补造。Claude 使用 SDK 作协议客户端；Codex 通过本机 app-server 的 `thread/*` 等接口，不自行编辑其 JSONL/SQLite。Antigravity 摘要从只读数据库获取，历史与管理使用经过隔离验证的本机内部服务，保留版本兼容边界。

**替代：** 不重刻 CLI 的 TUI，不提供终端画面作为协议失败兜底，也不做万能适配器。新 CLI 需有可驱动的非交互接口和可靠的会话身份/续接能力。

### 原生正文单一来源，身份不重建

**背景与选择：** 会话正文、工具事件与附件由 CLI 保存。AgentDeck 按 `(agent, sessionId)` 引用，只存必要索引、项目和偏好；历史读取及继续对话都复核原生目录。

**理由与约束：** 第二份 transcript 会造成跨客户端历史分歧，并让工作台成为唯一内容来源。续接使用原生 id，不重放整段历史给模型。归属按绝对路径规范化比较，Windows 不区分大小写，POSIX 保留；目录边界防止 `demo` 匹配 `demo-2`，多命中按项目顺序裁决。不能解析就返回无归属，不猜第一个项目。

**替代：** 不复制会话、不按标题分组、不用网页 id 替换原生 id。进程内传输缓冲可以存在，但不能落盘变成对话存储。

### 原生上下文、统计与会话操作

**背景与选择：** 恢复、压缩、改名、删除和分叉优先走 CLI 提供的原生路径；工作台归档仅补足缺少原生归档的来源，不改正文。分叉使用原生认可的结束点。

**理由与约束：** 官方操作会维护关联索引与元数据，自行改文件或按消息序号截断会破坏会话。可信分叉点由服务端给出，分叉后复核新 id 和目录；原会话与项目文件不回滚。原生用量与压缩状态没有报告时隐藏，不能把列表虚拟滚动当上下文压缩。

**替代：** 不自行总结并截断历史，不用复制记录实现分叉；删除必须明确确认，未接入动作不能返回伪造成功。

执行轨迹提供工具、文件、命令与耗时的统一视图，保留原生差异。token 统计必须有明确范围，平均输出速度不能冒充精确解码速度；上下文占比只采用当前报告与有效窗口。未知步骤作为活动呈现，历史没有统计就省略，不为了补齐 DSH 外观另存 transcript。首次评估及当时缺口通过 `3c8d0ac` 追溯。

### 运行状态与回合生命周期

**背景与选择：** 同一会话在本应用中只跑一轮，管理操作共用占用边界；耗时准备前就建立可取消的状态。前后端均按会话隔离，页面导航不再决定任务生命周期；不同会话可并行执行，用户随时返回待批准或已完成的任务。

**理由与约束：** 准备阶段也可能很慢，因此先登记本地会话身份，再绑定原生 id；离开页面后仍能停止。草稿和运行事件分别归属各会话，避免用禁止导航来维持唯一控制入口。长驻运行时可复用，模型、强度、目录或其他启动条件变化需重新核对；进程退出或崩溃即不可复用，关闭应用统一清理。历史读取和能力探测不借用正在生成的实例。

当前不能可靠探测外部 CLI 是否也在驱动同一会话，界面只声明本应用运行状态。后台回合通过进程内恢复缓存跨连接补收，浏览器页签锁隔离恢复身份；完整退出后不继续运行。事件与发送游标都有界且不落盘，不以自动重连触发再次执行。

**替代：** 不宣称跨进程全局锁，不把断线当成模型已停止，不自动重发结果不确定的回合。

会话管理优先使用可验证的原生操作。Antigravity 公开 ACP 缺少管理方法，但本机后端服务已经通过隔离会话验证分支和删除；工作台增加窄适配，不要求用户转去 CLI。该接口属于内部协议，字段或启动握手变化时明确失败；不通过私有数据库写入兜底。Claude/Antigravity 的归档由工作台索引补足，Codex 沿用原生归档，来源区别只在相关操作说明中呈现。

### 模型、权限和配置尊重原生作用域

**背景与选择：** 原生默认值保持原样，只有显式会话选择才传运行参数；持久变更写回对应 CLI 的配置。每项能力分别判断用户级、项目级、目录级或运行时作用域。

**理由与约束：** 三个 CLI 不存在通用的两层配置表，额外默认层会产生两个真相来源。原生要求审批时工作台负责展示和传递答复，不自行增加自动允许规则；Codex 未选择权限时不再固定 approvalsReviewer，保留原生自动审查配置；显式选择才同时映射沙箱、审批策略和审查对象。参数拒绝就显示错误，不降档或换模型重试。

配置保存校验语法、revision 与文件身份并原子写入，保留未知字段和格式；坏文件保留原文。只为实际需要提供启动环境白名单，敏感值加密且不回填；原生文件编辑与启动密钥状态接口分别设计。工作目录说明不写入用户项目，原生指令合并交给 CLI。

目录默认只列元数据，完整文件正文由用户显式打开。这样既能修复损坏配置、保留未知字段，也不会为画设置列表提前读取密钥；不采用将掩码占位符写回原文件的编辑方式。创建规则或 Skill 仅进入已知原生目录，现有文件的语义仍由 CLI 校验。

常用模型配置通过脱敏表单写入原生用户文件。Codex 自定义服务可选原生 bearer 字段或环境变量名，已有复杂认证保留；Antigravity 的模型/模式写原生设置，URL/Key 使用其真实支持的进程环境。工作台不仿造 CC Switch 的代理或私有 provider 数据库。保存后新进程读取更新，并清理能力缓存；字段依据见[配置说明](native-configuration.md#模型与服务连接)。

常用连接在同一页填写，存储方式由适配层处理。名称与上下文等字段遵循各来源真实含义：Codex 服务名不冒充模型名，Claude 压缩窗口不冒充上下文上限，Antigravity 默认强度通过模型变体选择。高级认证入口保留，但不要求普通用户理解启动环境的继承状态。

**替代：** 不保留网页侧模型默认覆盖，不强造项目级配置，不把未知 slash 命令改成普通消息，也不读取第三方切换工具的私有数据库。

### 本机版本与请求触发

**背景与选择：** 跟随用户本机安装版本，通过本地帮助、版本及 schema 探测能力。联网能力刷新和真实发送必须各有明确触发。

**理由与约束：** 版本号不能证明协议兼容；升级后只让失效的 CLI 降级，不拖垮其他适配器。探测四态为可用、未安装、接口变化、凭据未配置，合并 stdout/stderr 核对；`agy --help` 写 stderr 的事实不得丢掉。Claude 探测和驱动现已共用本机入口解析，不使用 SDK 平台程序兜底；Electron 运行脚本时必须解析真实 Node，不能把桌面可执行文件当解释器。

本机探测不检查账号。用户已选择在首次打开模型菜单时读取能力，成功后复用缓存并提供手动刷新；新建页面和后台轮询不触发账号检查，prompt 仍只由显式发送启动。失败不擅自重试、验证账号或发测试消息。

成功模型目录持久保存，重启优先复用；技能与命令保持目录与进程边界。Antigravity 获取目录使用隔离 profile，避开真实 MCP 和原生后台更新器的额外进程；依据本机验证的 TSV 格式与原生设置解析，账号模式不再因为目录缺口强制提示登录。

**替代：** 不锁死或打包 CLI，不写按版本号分支，不静默回退到另一份程序，不在启动或定时任务里调用模型。

### Antigravity 明确能力边界

**背景与选择：** 摘要库继续提供标题、时间和 `workspace_uris`；完整历史经本机原生服务读取。已有新建、原生 id 续接、流式输出、中断和软拒提示，历史新增白名单步骤映射与有界分页。

**理由与约束：** 原生服务已能读回隔离合成轨迹，继续固定返回 501 会遗漏实际能力；直接猜测数据库正文或保存网页副本则会破坏事实来源。内部 RPC 仅接已核对字段，身份、目录、分页或协议异常明确失败，不修改私有存储兜底。摘要过滤仍先探测列，不能把摘要异常降级为空列表的既有行为描述成完善的存储诊断。

`agy` 的流式入口、`--conversation` 与 stderr 软拒已按帮助和协议核对；这不等于真实账号回合已通过，也不能把退出码 0 当工具全部执行成功。配置页按已核实的全局 CLI 设置、项目 `.agents` 定制和目录规则接入，保持没有项目 settings 层的差异；具体入口及依据见[配置说明](native-configuration.md)。

**替代：** 历史固定不可回放的旧边界保存在 `3c8d0ac:docs/engineering/native-dialogue.md`。当前不伪造审批、不默认跳过权限；实时上下文与历史精确速度只有证据完整时才能接入，合成文本回放不证明所有生成元数据都可用。

## 3. 界面、SSH 与扩展

### DSH 式交互与可扩展展示空间

**背景与选择：** 界面直接对齐 DSH 的工作区导航、对话密度与灰阶。左栏贯穿窗口，上方集中新会话和插件入口，中央可切换对话与执行轨迹；右侧按需展示会话信息或步骤详情，服务器工具从插件进入。

**理由与约束：** 同一工作区的三 CLI 会话按时间混排，来源与原生能力差异通过图标、输入区和设置表达。SSH Console 从左上打开独立主页面；旧项目工具收进其中，不能因为旧偏好而自动占用对话空间。尺寸偏好保持有界，对话容器传递可用高度；隐藏区域不能保留可达焦点或误杀终端。布局切换和真实资源结束分别处理。

**替代：** 替代「所有服务器能力永久固定在右栏」的目标。成熟组件处理弹层、虚拟列表、终端、编辑器与分栏；不为统一外观裁掉原生能力。

### SSH Console 以独立工具体验为基准

**背景与选择：** M4 的首个插件对照已有 SSH Console：侧栏独立主页面、多服务器标签、概览/进程/只读文件预览/终端。优先复用 Node+ssh2 业务与 xterm。

**理由与约束：** 服务器操作本来独立于本地项目，用户不该为了连一台机器先创建项目。终端是用户手动的 shell；不向 CLI 注入 Agent→SSH 工具，不在服务器部署代理或监控常驻服务。只在当前可见目标采样，缺值不补零、旧值标过期，终端切页不销毁。

独立 SSH Console 已接入，原项目绑定式面板从控制台内访问，其 Slurm、服务器文件写操作与凭据存储按原有约束维护。停用提示明确包括项目工具终端，成功后清理临时标签及在途打开操作；服务器档案、密文、项目与旧任务继续保留。

**替代：** 新插件文件页采用只读目录和文本预览，远端写任务留在兼容工具；不通过复制 DSH 宿主来获得插件兼容。

### 本机入口、主机信任和凭据

**背景与选择：** 本机服务仍需防跨站调用，SSH 认证仍需验证远端身份。沿用严格同源握手、HttpOnly/SameSite Cookie、Host/Origin 检查，主应用不允许被外部 iframe 嵌入；受控插件 iframe 不获得主应用同源身份。

**理由与约束：** 回环监听本身不能防浏览器来源攻击，URL 令牌会留下历史和日志。未知主机确认指纹后才认证，密钥变化或吊销直接拒绝；密码认证不例外。服务凭据不进入日志、工作台普通配置、URL、命令行参数或模型上下文；原生配置按各 CLI 认证格式处理。浏览器仅可在 sessionStorage 保存不含服务凭据的随机恢复身份。

可选保存密码使用 Windows 当前用户加密并绑定真实目标身份；身份或认证材料变化后不能复用旧凭据。新控制台复用这一服务，启停不迁移或删除已有密文。

**替代：** 不关主机密钥校验，不把混淆当加密，不向渲染器开放任意 Node 能力。

## 4. 工程与演进

### 存储、迁移与资源隔离

**背景与选择：** 工作台配置与 CLI 原生数据分开，保留 `%LOCALAPPDATA%\AgentDeck`。旧目录迁移与字段转换是一次性过程，不维护两套正式业务格式。

**理由与约束：** 原子写入与 revision 检查防止覆盖用户外部修改，迁移不覆盖现有同名文件，不删除旧目录。绝对目录暂时离线不等于配置无效。旧 SSH 和文件任务保留数据及身份核对；无法确认结果时标记待核对，重启不重放写任务。

异步处理 Agent、SSH 与文件 I/O；同连接的 PTY/SFTP/exec 使用独立通道，单个失败不关闭共享连接，迟到结果按身份或代次丢弃。服务器脚本只用已有环境，缺依赖报告而不自动安装。

**替代：** 不清空坏配置来恢复页面，不用重试掩盖不确定写入，不在本机后端复制远端大数据做计算。

### 成熟依赖、增量验证与历史证据

**背景与选择：** 优先成熟且许可兼容的库，版本固定，按影响范围测试。文档保留现行规则，失效材料由 Git 追溯。

**理由与约束：** 自造基础组件和重复跑无关测试都会增加维护成本。关键行为测试应走真实调用链，夹具不写用户真实文件；前端渲染和系统交互需相应人工或浏览器检查。运行时复用、读取分组与分页等预算由架构统一维护，文档不复制散落阈值。

完整工程门禁不放宽覆盖率或复杂度来迁就改动；jsdom 保留在根开发依赖供 Vitest 解析。只在确有授权时执行真实模型或远端写入。未覆盖的模型/账号、服务器任务、输入法和安装场景继续保留验证边界，不把部分场景通过扩大为全部兼容。

**替代：** 不保留过时截图与过程流水充当当前证明，也不因删文档重写历史失败。旧同步、版本、镜像与每轮全量改动采集不会换名恢复。

### 项目变更和列表更新保持可追踪

**背景与选择：** 项目管理独立于服务器绑定；改名不检查旧目录在线状态，更换目录与移除需要活动占用门禁，原生资源保存和创建也持有项目租约。界面按提交时的选择代次处理成功结果，目录改变后清来源项目缓存并刷新摘要归属；同项目已切到其他会话也不由迟到结果覆盖。

**理由与约束：** 路径改变后继续展示旧历史容易从错误目录续接，而无条件切换又会丢用户新选择。服务端互斥控制保护本应用内部操作，不能被描述成锁住外部 CLI。其他目录的添加入口只接收可确认的本机目录，不凭标题或远程 URI 猜测。

用户在工作台进行对话时不会同时用 CLI 操作同一会话，因此列表按首次读取和应用内操作结果更新。原生会话继续共用，重新启动时直接读取最新原生记录；不建立同步副本，不保留目录监听、版本轮询和手动刷新机制。原来的监听方案保留在 `9fda867:docs/engineering/architecture.md` 供追溯。

**替代：** 不再把项目移除隐藏在 SSH 配置窗口里，也不将后台定时重读所有正文作为更新机制。

## 模块边界与扩展方式

保留四个顶层包，不为每个 CLI 复制应用，也不增加空的 application 层。CLI 差异放在各自适配目录，公共设置通过窄接口和静态注册编排；运行器仍保持各自原生协议。这样新增字段不会继续扩张公共配置分支，也保留原生作用域、未知字段和认证方式。

工作台插件宿主与 SSH 业务分离；注册项持有内置页面和生命周期，旧工具集中 legacy 并保留 URL/磁盘数据。平台文件、进程和密钥保护独立于业务，shared 按域提供子路径而不拆更多 npm 包。导入方向由 ESLint 检查，测试和构建资产随实现迁移。结构审查实施前版本可从 `cdcef47:docs/engineering/structure-review.md` 追溯，已执行计划的锚点为 `d6028db:docs/superpowers/plans/2026-11-06-workbench-structure.md`。

## UI 组件与交互层

正式界面沿用已确认预览的中性样式和轻量反馈，公共层提供 FieldSelect、FieldSuggestions、SegmentedControl、SpotlightSurface 及集中样式。业务只传状态和事件，模型目录、原生字段、会话草稿和运行状态仍由各功能模块管理。菜单和焦点依赖现有 Ariakit，动效使用 CSS；没有把独立预览的演示逻辑、组件源码和依赖复制到生产。

原生 dialog 位于浏览器顶层，因此字段浮层必须挂在所属 dialog 下并使用固定定位。打开菜单不能挤动布局，Esc 先取消浏览器关闭外层的默认动作；对话框不保留会改变 fixed 包含块的变换。输入焦点采用内侧标记，减少与相邻控件重叠。终端和编辑器继续各自适配，不用统一万能组件替换。
