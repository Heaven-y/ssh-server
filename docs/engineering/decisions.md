## 1. 产品与形态

### D1 产品转向：本机原生 CLI 会话工作台（2026-11-03）

背景：日常在 Windows 本机使用 `claude`、`codex`、`agy` 三个 CLI，会话分别落在 `~/.claude`、`~/.codex`、`~/.gemini/antigravity-cli`，要管不同项目的不同会话，只能在多个终端窗口之间来回切。旧主线「本地改代码 → rclone 同步 → 服务器上跑」已不是每天要做的事，用户习惯的是 Codex 桌面端、DSH 桌面端那样的形态。

选择：产品改为本机的会话工作台——打开是项目列表，点项目按 CLI 分组列出会话，点会话进入对话并接着聊。会话是 CLI 自己的会话，配置是 CLI 自己的配置；本程序不含模型引擎、不存对话正文、不另造配置体系。SSH 降级为旁边的工具，不再与对话耦合。

理由：用户每天真正要做的是「把会话管起来」，同步与版本那套占了原来一半重量却不再使用；直接驱动原生 CLI 能继承它的上下文、工具与历史，不必再维护另一套模型状态和一份正文。

约束：会话正文只来自 CLI 存储（D12）；一个会话只属于一个 CLI 和一个项目目录（D15、D16）；Antigravity 现在只在类型里占位，适配器与启动逻辑尚未实现，未跑过真实会话前，它的参数组合、事件映射与续接行为按未验证处理（D34）。

放弃方案：继续以网页同步工作台为产品主线；自建会话与消息存储。

### D2 桌面形态：Electron 壳，加壳不换栈（2026-11-03）

背景：产品是 Windows 桌面应用，不是「打开浏览器访问某个端口」。

选择：Electron 主进程与 preload 放在 `apps/desktop`，主进程拉起本机 Fastify 服务后用窗口加载它；后端仍然只监听回环地址；preload 只经 `contextBridge` 暴露少量系统能力；关窗退出时一并结束后端，单实例运行。

理由：仓库没有原生模块——`ssh2` 是纯 JS、SQLite 走 Node 22 内置的 `node:sqlite`、终端是 SSH 远程 PTY 而不是本机 `node-pty`，所以 Electron 最麻烦的原生模块重编译在这里不存在，加壳接近零成本。换成 Tauri 之类要用 Rust 重写适配层与上千个测试，收益只有安装包体积。

约束：浏览器打开同一地址仍可用于调试，但按设计它不是产品入口；`apps/desktop` 尚未创建（M1.5），打包、签名与自动更新留到 M4；从开始菜单启动时拿到的是登录会话的 PATH，找不到某个 CLI 时用可执行文件路径覆盖项补救，不静默回退到包内版本。

放弃方案：Tauri；把浏览器页面当产品入口；向渲染层整体暴露 Node 能力。

### D3 删除同步、版本与本地文件镜像三个域（2026-11-03）

背景：同步（rclone bisync、状态机、冲突与待确认）、版本（本地 git 快照、历史、恢复）、本地文件镜像（只读浏览、改动视图、行内反馈）在上一代占产品一半重量，本轮整体不再需要。

选择：三个域连同前端视图、路由、共享协议与 `@pierre/diffs` 依赖一起物理删除，不保留开关、备用路径或兼容格式；旧配置里的同步字段在读入时丢弃。

理由：留着开关会让两套模型长期并存；用户已确认不再需要这些能力，一次删净比维持灰度更省维护，数据模型也因此只剩一份。

约束：被删能力不再恢复，旧文档里相关条款按历史记录看待；少量同步残留（例如服务器文件的错误码文案）随工作区模型收敛一并清掉，不再扩展；服务器文件的新建、重命名、移动、复制、删除不在此列，那本来就是 ssh console 的能力（D29）。

放弃方案：保留开关或只删界面；把同步换个名字留下。

### D4 改名 AgentDeck 与一次性数据迁移（2026-11-03）

背景：仓库原名 `ssh-server`，与新定位不符。

选择：仓库目录、包名（`@agentdeck/*`）、导入路径、环境变量前缀（`SSH_SERVER_*` → `AGENTDECK_*`）、会话 Cookie 名与数据目录一并改名；数据目录迁到 `%LOCALAPPDATA%\AgentDeck`，启动时把旧目录 `%LOCALAPPDATA%\ssh-server` 的 `servers.json` 与 `workspaces.json` 复制过来。

理由：改名本身是一次性的路径迁移，成本低；不迁移就会让用户的服务器档案与项目列表凭空消失。

约束：新目录已有同名文件时不覆盖并写日志；旧目录原样保留不删；`sync/` 与 `file-editors.json` 属于已删功能，不在迁移清单里；单个文件失败只记错误，启动继续。这是路径迁移，与「兼容旧业务格式」是两件事，不派生持续的兼容层。

放弃方案：静默删除旧目录；长期同时读取两个目录。

### D5 界面：三段式、有界尺寸与视觉语气（2026-10-09，2026-11-03 修订）

背景：上一代是四段式停靠（工作区/会话｜对话｜资源｜文件），工具面板还试过自由浮窗；现在收敛为三段式——左栏项目与会话、主区对话、右侧服务器面板（可收起）。

选择：分栏使用 `react-resizable-panels` 的固定嵌套 Group；导航宽 200–320px，工具区按「只有资源 / 只有文件 / 两者」分别记忆像素宽；≥1600px 工具区横排，<1280px 自动收起导航；主题初次浅色，已存偏好优先，切换主题不销毁内容。

理由：分栏尺寸恢复必须等库更新完隐藏与尺寸约束之后再设，否则会丢掉目标像素与比例（真实浏览器验收里实际踩到过），所以统一用可取消的下一帧恢复，外层栏用库自带的像素保持模式；上限要接进 Panel 的实际约束，不能只在偏好里拒绝越界值。

约束：最小支持 960px；自动收起只写内存，不覆盖用户的持久偏好；偏好值有界，越界回落默认值；视觉沿用 DSH 桌面端的语气——中性灰阶、细边框、克制高亮、等宽字体用于路径与代码、CLI 归属用一个字母或色点；品牌图标取自 simple-icons（CC0），商标只用于指示所对接的原生工具。

放弃方案：自由浮窗与整页模态、强制四列停靠、跨页面持久化窗口几何。

## 2. 技术选型

### D6 后端：Node.js + TypeScript + Fastify（2026-10-02）

背景：本地后端要同时协调 Agent 子进程的流式事件、SSH 通道、文件任务与 WebSocket。

选择：Node.js ≥22 + TypeScript 5.9 + Fastify 5 + zod 4，用 `tsx` 直接运行。

理由：主要负载是异步协调而不是计算；官方 Claude SDK、Codex 协议与前后端共享类型都在 TypeScript 生态里，Fastify 满足模块化路由、入参校验与流式通信。

| 方案 | 适合的工作 | 本项目的判断 |
|---|---|---|
| Node.js + TypeScript + Fastify | 异步 I/O、Agent SDK、SSH 与流式消息集成 | 已选用，保留现有实现与共享类型；重计算交给子进程或服务器 |
| Python + FastAPI | 在 API 服务内直接用 Python 科学计算库 | 本机后端不做大规模计算，换语言只会让现有 TypeScript 接口多一层跨语言维护 |
| TypeScript + NestJS | 需要统一依赖注入与分层约定的较大服务 | 与现有栈兼容，但当前规模会多一层框架约定 |
| Go | 编译分发、网络服务与并发 | 现有 Agent 接口与 TypeScript 适配层要重写，单用户本地工具没有迁移依据 |

约束：请求路径上不跑阻塞命令，重计算交给子进程或服务器；并发目标是单用户多活动并行，不引入多用户服务；不新增独立可执行文件打包要求——桌面形态由 Electron 打包，不是把 Node 编成单文件。

放弃方案：Python + FastAPI、NestJS、Go，理由见上表。

### D7 前端：React 19 + Vite + 成熟组件（2026-10-05，2026-11-03 修订）

背景：界面要处理弹层可达性、可拖动分栏、命令面板、长列表与流式 Markdown。

选择：React 19 + Vite 8 + Tailwind CSS 4；Ariakit 负责弹层与标签页，cmdk 负责 `Ctrl+K` 命令面板，`react-resizable-panels` 负责分栏，zustand 管会话状态，`@tanstack/react-query` 管接口缓存，partysocket 负责 WebSocket 重连，lucide-react 提供图标。

理由：这些细节自造成本高、可达性容易做坏；成熟库能直接复用交互与缓存行为。WebSocket 关闭发送缓冲，避免重连后把旧消息重发一遍。

约束：命令清单按当前产品范围重列，不保留同步、版本与本地文件相关命令；前后端按功能分目录，通用部分才放 `lib` / `ui`，不额外造控制器、服务或仓储层；主题、侧栏与工具区尺寸属于有界的界面偏好，不写进产品设置。

放弃方案：自造弹层与虚拟滚动；引入完整设计系统及其主题体系。

### D8 时间线：虚拟滚动、读取工具分组与视图代次（2026-10-05）

背景：长会话与连续读取工具调用会把 DOM 撑爆，也会让自动跟随失效。

选择：用 `react-virtuoso` 渲染动态时间线，保持跟随到底与展开状态；读取类工具调用按白名单合并分组，每段最多 40 项；审批、执行与错误各自独立成卡；切换会话时按选择代次丢弃迟到的读取结果。

理由：40 项上限来自实际负载验收；白名单分组比按命令名猜测更稳；分开展示才能看清哪一步在等用户批准。

约束：不猜 shell 语义；受控的长历史展示不等于原生上下文压缩；工具卡片只显示原生事件给出的内容，不做推断（D24）。

放弃方案：全量渲染与无限追加；按命令名猜测工具类型。

### D9 终端与编辑器：xterm.js 与 CodeMirror 6（2026-10-03，2026-11-03 修订）

背景：服务器终端要跑全屏程序、要支持多标签；原生配置编辑要校验语法、要高亮。

选择：终端用 `@xterm/xterm` 与 `@xterm/addon-fit`；编辑器用 CodeMirror 6 与 `@uiw/react-codemirror`，只编辑约定的原生配置文件。

理由：两者都是成熟组件，符合仓库「有成熟库就直接用」的规则；CodeMirror 的搜索、按需加载与 JSON / TOML 高亮足以覆盖配置编辑。

约束：只在服务器上开 SSH PTY，不在服务器安装任何开发服务，也不引入 code-server 或浏览器 IDE；Pebrel 只参考终端的外观、多标签与分屏交互，不复制其 GPL-3.0 实现，也不以安装 `nvitop` 为终端前提；原生配置读取上限 256 KiB。

放弃方案：自造终端渲染；把 CLI 的 TUI 画面塞进界面。

### D10 Python：只在服务器已有环境执行（2026-10-02，2026-11-03 修订）

背景：服务器上有数据、权重与项目依赖，本机没有。

选择：需要在服务器上执行脚本时，只用服务器已有的解释器与标准库（当前用在服务器文件操作上的 `remote-helper.py`），统计或绘图依赖由服务器既有环境提供。

理由：把数据整份下载到本机再算既慢又占空间；在共享账号里装新环境会污染别人。

约束：服务器缺少需要的解释器或依赖时，报告缺失并说明可用环境，不自行安装；本机后端不承担大规模数据计算；不再有自动的远端分析——Agent 已不持有服务器工具，服务器侧动作只能由人点出来（D25）。

放弃方案：在服务器安装分析环境；把大数据下载到本机计算；由 Agent 自动发起远端分析。

### D11 测试环境：jsdom 固定在根开发依赖（2026-10-05）

背景：Vitest 从仓库根加载 jsdom 环境，网页包只声明 React 测试库。

选择：固定版本 jsdom 27.4.0 放进根 `devDependencies`，RTL 与 DOM 测试库继续属于网页包。

理由：干净 `npm ci` 的安装树也要能解析出环境。

约束：不改变覆盖率范围与门槛，不用旧安装树或降低门槛掩盖环境问题。

放弃方案：把 jsdom 留在网页包，让根 vitest 配置隐式依赖子包安装树。

## 3. 数据与协议

### D12 单一真相：会话正文只来自 CLI 存储（2026-11-03）

背景：产品要在本机管三个 CLI 的会话，但正文本来就在各自存储里。

选择：本产品不落库、不做事件投影缓存、不做导入导出；允许保存的只有会话索引（原生 id、所属 CLI、cwd、标题、最近活动时间）、界面偏好、项目与服务器档案、加密凭据。

理由：一旦复制正文，本产品就成了会话的唯一存放地，与「会话是 CLI 自己的」直接冲突；只有一份正文，也不会出现两个客户端看到不同历史。

约束：读历史走原生读取，继续会话用原生 id 续接，不把已经显示出来的历史重新提交给模型；原生存储格式变化时把该会话标为不可读，不崩溃、不伪造内容。

放弃方案：给 Antigravity 建网页侧 transcript；缓存正文以加快切换。

### D13 本机数据目录与产品偏好（2026-10-05，2026-11-03 修订）

背景：产品默认值（默认 Agent、资源采样间隔与超时）与原生默认不是一回事。

选择：数据放 `%LOCALAPPDATA%\AgentDeck\`，包含 `workspaces.json`（项目）、`servers.json`（服务器档案）、`product-settings.json`（产品偏好）、`credentials\`（加密凭据）、`remote-file-tasks\`（服务器文件任务）；产品偏好独立成文件，缺省即取默认值（`defaultAgent=claude`、资源 5 秒 / 8 秒）。

理由：产品默认、原生默认与显式选择必须能分开说清；独立文件不会污染原生配置。

约束：保存带 revision 校验与原子写入（同目录临时文件再 rename）；坏文件返回 503 并保留原文件；退休字段只在磁盘读取边界定点剔除，公开输入仍严格校验，不恢复通用旧格式兼容。

放弃方案：把产品偏好写进原生配置文件；自动迁移旧字段。

### D14 服务器档案：统一字段与引用保护（2026-10-07）

背景：上一代把认证方式散在工作区记录里，改一处要动多处。

选择：`servers.json` 统一保存地址、端口、账号、认证方式（密码或私钥）与可选私钥路径；alias 形如 `managed-ssh-<uuid>`；同一 hostname + 端口 + 账号只允许一条档案，最多 128 条；`~/.ssh/config` 只作为显式导入来源。

理由：档案是服务器面板的身份（D26），认证信息集中之后才谈得上连接复用与变更核对。

约束：连接入参只有 `SshTarget = { alias }`，认证方式从档案解析；修改或删除地址、端口、账号、私钥前检查工作区引用，已有引用不能静默换向；不支持的 ssh config 选项保留提示、不改写用户配置；生产解析不隐式回退到 ssh config。

放弃方案：把主机与认证字段内联进项目记录；运行时直接读 `~/.ssh/config`。

### D15 会话身份与归属：原生 id 与 cwd（2026-10-02，2026-11-03 修订）

背景：会话列表要按项目分组，但三个 CLI 的归属字段不一样。

选择：会话身份是 `(agent, sessionId)`，id 一律用原生 id（Codex 取 `thread.id`，不取分叉树根）；归属由会话的原生 `cwd` 与项目目录规范化后比较判定，不用目录名做字符串前缀匹配。Antigravity 没有 `cwd`，改按 `workspace_uris` 判定，为空或非 `file://` 时归入「其他目录」。

理由：按前缀猜会把同名前缀的不同项目混在一起；原生 id 才是 CLI 认得的那个身份。

约束：读取历史与继续会话时复核 id 与 `cwd`，不符就按「该 Agent 在当前项目目录中没有此会话」拒绝；列表的项目归属裁决尚未接入，当前一律按未归属上报，不猜；缺归属字段的会话不能被塞进第一个项目。

放弃方案：按目录名前缀或标题匹配归属；把会话映射成产品自己的 id。

## 4. 会话与原生 CLI

### D16 一个会话固定一个 Agent（2026-10-02）

背景：Claude 与 Codex 的原生协议、事件格式与历史存储都不同。

选择：会话在创建时就确定属于哪个 CLI，继续历史时保持原 Agent，不转换、不拼接上下文；需要另一个 CLI 就新建会话。

理由：跨 Agent 迁移上下文要自带一套转换与摘要，既不可靠，也会篡改原生历史。

约束：接入层按 Agent 注册 provider，缺失时按「该 CLI 适配器尚未接入」拒绝，不隐式猜 Claude；Antigravity 只有身份占位，没有适配器。

放弃方案：在一个会话里切换 CLI；按模型名反推 Agent。

### D17 官方上下文、续接与压缩（2026-10-02）

背景：上下文窗口、压缩与历史续接都是 CLI 自己的行为。

选择：沿用官方的上下文管理、`resume` / `thread/resume` 续接与原生压缩（例如 Codex 用 `thread/compact/start`），本产品不自行拼装历史、不估算上下文占用。

理由：维护第二套上下文会与 CLI 行为分叉，压缩之后两边还会对不上。

约束：界面只展示原生报告的用量与压缩状态，没有报告就隐藏对应控件；协议支持的控制动作要映射到真实接口，终端专用命令必须标注限制，不能当成普通聊天文本转发就宣称支持。

放弃方案：本产品自建上下文窗口与摘要压缩。

### D18 会话列表与原生操作走官方接口（2026-10-02，2026-11-03 修订）

背景：直接删会话记录文件会残留运行时元数据。

选择：列表、读取、改名、删除、归档与恢复一律走官方接口（Claude 用 SDK 的会话方法，Codex 用 `thread/*`），不直接解析 `~/.codex` 的 JSONL 或 SQLite；归档只对 Codex 开放。

理由：官方接口会同时维护索引与元数据，绕过它改文件会让 CLI 状态不一致。

约束：删除必须带 `confirmed`，标题 1–200 字符；所有原生操作在会话锁内执行，轮次进行中一律拒绝并给出原因；读取失败匿名化为不可用，不把原始诊断回给界面。

放弃方案：直接读写原生存储文件；批量删除时不逐条确认。

### D19 原生分叉语义（2026-10-09，2026-11-03 修订）

背景：用户想从当前处另开一条线，又不愿动原会话。

选择：分叉保留到服务端给出的可信结束点，源会话不变、不回滚项目文件；Codex 用 `thread/fork.lastTurnId`，Claude 用 `forkSession.upToMessageId`。

理由：只有原生返回的结束点才是真实的可分叉位置；按时间戳或消息序号自行截断会造出原生不认的历史。

约束：只接受服务端给出的分叉点，重复结束不补造；分叉后复核新会话 id 与 `cwd`，无效即按运行时失败拒绝；分叉与改名、删除、归档共用会话锁。

放弃方案：复制一份会话记录；由前端指定任意消息位置。

### D20 能力目录与 `/` 命令按原生能力接入（2026-10-02）

背景：用户希望沿用本机与项目里已有的技能和斜杠命令。

选择：能力信息从原生接口读取——Claude 用初始化元数据与 `supportedCommands()` 等 SDK 能力，Codex 用 `skills/list`，调用时使用官方 skill 输入结构。

理由：只有 CLI 自己知道当前目录下有哪些技能与命令。

约束：两类 Agent 不保证同一份命令列表；服务端只接受目录里的 ID 或精确 slash 名称，未知、禁用、歧义直接报错，不降级成普通文本；需要会话的命令在无 id 时拒绝；读取能力目录属于第二档动作，只在用户点「刷新能力」时发生（D32）。

放弃方案：本产品维护一份自己的命令清单；把未知命令当普通文本发出去。

### D21 工作区指令按会话注入（2026-10-02，2026-11-03 修订）

背景：Agent 需要知道当前项目目录，但不该把这个说明写进用户的项目文件。

选择：每轮把工作目录说明按会话注入（Claude 走 `systemPrompt` 的 `append`，Codex 走 `developer_instructions`），不写入项目目录。

理由：注入不污染仓库，也不会被提交进版本库；不同会话可以有不同的说明。

约束：与用户项目自带 `AGENTS.md` 的合并行为以 CLI 为准，本产品不另造合并规则；注入内容只描述工作目录，不注入远程工具或同步说明（MCP 桥已删除，见 D25）。

放弃方案：往项目里写 `AGENTS.md`；把远程工作流说明拼进提示词。

### D22 长驻运行时复用（2026-10-21）

背景：每轮冷启动约 0.3–0.6 秒（当时含 MCP 子进程 198ms 与 Codex `initialize` 160ms；MCP 桥随后已删除，但冷启动开销仍在），同一会话连续对话应该复用已建立的上下文与工具进程。

选择：`agents/claude-runtime.ts` 与 `agents/codex/runtime.ts` 承载会话级运行时，适配器按会话键缓存，空闲 5 分钟后回收；线程只建一次，续接时复核目录与身份。

理由：复用能省掉冷启动与重复握手，上下文与工具进程也不必重建。

约束：缓存键含工作区（id、目录、服务器、远端目录）、原生会话 id、模型与推理强度，模型或强度一变就换新运行时，避免沿用旧启动参数；新会话在首轮收尾才拿到原生 id，届时改登记，后续轮次才复用同一进程；一次只跑一轮，并发仍由会话锁拦截；进程退出或崩溃后标记不可复用，下一轮重建；历史与列表读取、能力探测走单轮运行时，跑完即关；关闭时统一 dispose 全部运行时。

放弃方案：每轮都起一个全新进程；把模型或强度变化当成同一运行时内的热切换。

### D23 模型与推理强度：原生默认 + 显式选择（2026-10-02，2026-11-03 修订）

背景：用户自己配端点与模型，各 CLI 的默认值和档位也不相同。

选择：默认模型与推理强度来自原生配置；会话内的显式选择只对本次运行生效、不写回原生配置；新建会话默认强度 `high`，`low / medium / high / xhigh / max` 直选，「自动」等于省略 `reasoningEffort`；模型菜单只列真实候选，没有报告就显示「默认模型」，不编一个名字。

理由：上一代用过网页侧 `defaultModels` 覆盖层，结果出现「网页设置」和「原生配置」两个默认源；也曾在目录里前置校验强度，逼用户每次先选模型。

约束：模型与强度只在显式选择时传给 CLI；原生拒绝就正常报错，不静默降级、不重试；上下文用量按原生报告展示，无报告时隐藏；运行中的轮次不切换模型。

放弃方案：网页侧模型覆盖层；按版本或目录首项猜模型 ID；用「未报告」占位撑版面。

### D24 回合不采集全量改动，界面不做改动视图（2026-10-21，2026-11-03 修订）

背景：上一代每轮前后各读一次工作区并建 Git 树，约 1.1 秒，而多数轮次并不改文件；用户只要求看到「改了哪个文件」。

选择：不再做每轮全量快照，不写 Git 对象、不读文件正文、不保留历史轮次；工具卡片只显示原生工具事件里的路径与「写入 / 编辑」动作，点开也只有路径，没有 diff 渲染或行内反馈。

理由：成本与收益不成比例；改动视图还要带一套 diff 组件与评论存储，而同步与版本域已经删除（D3）。

约束：不重建改动采集；不引入 diff 渲染组件；截断或解析失败时不伪造正文。

放弃方案：每轮 Git 树净差异与并排 diff；行内评论。

## 5. 服务器控制台

### D25 服务器是人的工具：Agent 不在服务器上运行（2026-10-02，2026-11-03 修订）

背景：服务器访问不到模型端点、多人共用；上一代还用 MCP 桥把服务器操作暴露给 Agent。

选择：Agent 只在本机项目目录里工作；服务器上只执行人点出来的操作——终端、只读采样、`squeue`、文件增删改移；Agent→SSH 的 MCP 桥整体删除，不再给 CLI 注入服务器工具。

理由：服务器因此零安装、零驻留，凭据与模型配置都留在本机；让 Agent 持有服务器工具会让「谁执行了什么」难以追溯，还会把命令黑名单这类防线变成必需品。

约束：服务器上不安装 Agent、不部署反向隧道或监控服务、不存放本产品数据；终端是用户本人的通用 SSH shell，不经模型、不受会话规则限制；以后若要恢复远端工具，作为独立插件重新评审。

放弃方案：在服务器部署代理；给 Agent 注入 `remote_exec` / `remote_peek`；用命令黑名单约束 Agent 的远端执行。

### D26 面板以服务器档案为身份（2026-11-03）

背景：当前终端、资源、Slurm 与文件四类路由仍以 `workspaceId` 为键，切换项目会打断服务器操作。

选择：服务器面板以服务器档案为身份——不绑定项目的服务器也能直接用，切换项目不打断已开的终端、文件浏览与资源采样，同一停靠区可以开多台服务器、标签显示主机别名；项目只提供默认服务器与默认目录。

理由：服务器能力与项目本来就是两件事，绑在一起会让「只想连台机器看看」变成必须先建项目。

约束：未绑定项目时默认目录是登录用户的 home，不是根目录；迁移要把终端与文件绑定的签名键、前端面板状态模型一起改；`agent-capabilities` 是例外，它按项目目录取值，继续以项目为键。这条尚未落地——代码里的终端、资源、Slurm 与文件仍按工作区为键，不能按已实现描述。

放弃方案：强制服务器必须挂在项目下；给服务器另造一套与项目重复的目录配置。

### D27 资源采样：只读、固定目标、独立于对话（2026-10-04，2026-11-03 修订）

背景：用户要随时看 GPU / CPU / 内存 / 磁盘 / 负载，又不想为看一眼状态占用模型。

选择：后端用服务器已有的 `nvidia-smi` 机器可读查询与 `/proc` 等只读命令采样；前端只在面板可见、页面可见、连接就绪时按设置间隔（默认 5 秒）请求，隐藏即停表并取消在途请求。

理由：只读采样不改变服务器状态，也不需要安装采集器；请求驱动比后端常驻定时器省资源。

约束：缺失值保留 `null`，不显示为零；失败保留最近读数并标记过期；缓存按真实目标共享宿主读数，磁盘再按目录隔离；网页不展示节点进程表，也不把共享账号下的全部进程算成当前用户的任务；登录节点与计算节点分离时不跨节点采集。

放弃方案：后端常驻采样时钟；在网页里做 `nvitop` 那样的全屏进程界面；按 Host 别名合并不同身份。

### D28 Slurm：单一固定文本查询（2026-10-09）

背景：上一代先走 JSON 解析，碰上不支持或字段缺失的集群就要回退。

选择：唯一命令是 `LC_ALL=C squeue --noheader --user="$(id -un)" --format="%.18i %.9P %.24j %.8u %.2t %.10M %.6D %R"`，8 秒总预算、stdout 与 stderr 共用 512 KiB、最多 200 行；空输出不补表头，非空补对齐表头；成功但 stderr 非空只转通用警告。

理由：固定 format 覆盖用户的格式环境，文本路径在更多集群上可用；单一协议省掉双路径维护。

约束：不解析 HTML、不推算时限、不做作业管理；首次或手动查询，不做定时轮询；结果短缓存 2 秒、最多 32 项，错误不缓存；认证身份变化后清缓存并取消旧查询。

放弃方案：`squeue --json` 与文本双路径；`sstat` 与高频调度器轮询。

### D29 服务器文件：直接操作、预检确认、不覆盖（2026-10-03，2026-11-03 修订）

背景：服务器上的数据、权重与输出不在本机，网页也不该做本地中转。

选择：浏览与操作都直连服务器（SFTP 读元数据，操作走服务器已有 Python 标准库与 `renameat2(RENAME_NOREPLACE)`）；新建目录、重命名、移动、复制、删除保留，文件下载移除；每层最多 10000 项或 4 MiB 元数据、每页 200 项，目录优先按自然序排序。

理由：直连不产生第三份副本，也不受本机磁盘限制；不覆盖同名目标、不跟随符号链接能少踩误删的坑；有序分页让大目录可用。

约束：操作前生成两分钟有效的预检方案，写盘前复验；按同身份相交路径排队，最多四项并行；任务记录先原子落盘再派发，后端重启不重放，结果不确定的标 `needs_check`；受保护根（项目目录及其祖先）不能移动、删除或覆盖。

放弃方案：先把文件下载到本机再上传来完成移动；覆盖同名目标；在前端一次性渲染整个目录。

## 6. 安全与边界

### D30 本机入口与同源握手（2026-10-07）

背景：后端只服务本机，但浏览器里任何来源都可能发起请求。

选择：只监听回环地址，启动时拒绝其他 host；网页先 `POST /api/local-session`（空对象），严格核对本机 Host、精确允许的 Origin 与 Fetch Metadata 之后下发 HttpOnly、SameSite=Strict 的会话 Cookie；业务组件与 WebSocket 在握手成功前不挂载。

理由：把令牌放进 URL 会留在历史记录与日志里；同源握手配合 Cookie 能挡住 DNS 重绑定与跨站请求。

约束：Cookie 名 `AGENTDECK_session`，比较用常量时间；`/api/*` 与 `/ws` 都要有效 Cookie；所有响应带 `X-Frame-Options: DENY` 与 `frame-ancestors 'none'`；开发来源必须显式放行；秘密不进入 JS 或 URL。

放弃方案：URL 令牌登录；只靠本机监听而不校验 Origin。

### D31 凭据与主机信任（2026-10-02，2026-11-03 修订）

背景：SSH 密码、模型服务令牌与网页访问令牌是三类不同的凭据；用户当前能免密连接，不能因此把产品写成只支持免密。

选择：正式支持账号密码与已有私钥；用户选择保存密码时，由 Windows 当前用户的系统加密能力保护独立凭据文件；主动断开只清理内存、保留保存项，取消「保存密码」时移除保存项并断开。

理由：已保存的密码不该在每次重连时重新输入，明文也不该进配置或日志。

约束：明文密码只进内存与密文，不写项目配置、不落磁盘明文、不进浏览器持久存储、日志、命令行参数或对话；凭据绑定目标身份，地址、端口、账号或私钥变化时一律拒绝复用旧值，不另设「忘记密码」入口；不因使用密码认证就关闭主机密钥校验——未知主机先确认指纹，密钥变化明确拒绝。

放弃方案：明文保存密码；把密码混淆当成加密；用 `StrictHostKeyChecking=no` 换方便。

### D32 绝不自动发请求（2026-11-03）

背景：用户配了自定义端点与密钥，代发一轮就是花真钱。

选择：任何会消耗额度或打到用户端点的动作都必须由用户明确点击触发，分三档——一档本机探测（`--version`、`--help`、`generate-json-schema`、读配置与会话）随时可跑；二档能力目录（斜杠命令、模型清单）只在点「刷新能力」时跑并缓存结果；三档真正的 prompt 只有点发送才发。

理由：三档把「能自动做的」与「必须授权的」分开，避免「打开页面就偷偷验证账号」。

约束：打开「新建会话」不算第二档授权；第二档失败降级为「能力未知」，不重试；不设任务完成观察器、完成通知或自动结果分析（D25 删除 MCP 桥之后也无从发起）；不读取其它工具的数据库，只认原生配置文件与启动环境。

放弃方案：启动时预读能力目录；定时轮询、自动续跑或自动分析结果。

### D33 跟随本机安装，按能力探测（2026-11-03）

背景：三个 CLI 都在自升级，接口随时会变。

选择：驱动本机安装的那份可执行文件，不打包、不锁定、不假设稳定；用 `--version` / `--help` / schema 探测实际能力，不写 `if (version >= x)`；探测失败就把该 CLI 标为不可用并给出原因，其余照常工作。

理由：界面显示的版本必须等于实际驱动的版本；版本号会骗人，能力不会。

约束：协议按核对过的版本实现，不为旧版本保留第二套协议栈；`codex app-server` 仍标 experimental，升级后要重新探测；已核对的证据只覆盖当时版本（Claude Agent SDK 0.3.286、Codex 0.156.1 与后续 0.160.0 的会话与审批核对），不能推导未来版本或所有模型服务；不静默回退到包内二进制。

放弃方案：打包 CLI 或锁死版本；按版本号判断能力；同时维护多套协议。

### D34 证据边界：未验证不写成通过（2026-10-09，2026-11-03 修订）

背景：文档与验收很容易被写成「应该没问题」。

选择：已有实现与真实运行记录的能力按实际记录；未观察到的能力（Antigravity 真实会话、真实集群上的 Slurm 成功输出、操作系统输入法、安装包与自动更新）明确标为未验证；历史失败不回写成通过。

理由：未验证项一旦写成通过，后续判断都建在假设上。

约束：已交付能力不因文档精简重新列为待开发；外部客户端（VS Code、CLI 界面）只是可选检查手段，不扩成产品交付门槛；受控夹具的结果不能当成真实链路证据；被删能力的证据随能力一起作废。

放弃方案：用受控测试推断真实链路；为改善报告重跑已经走过的链路。
