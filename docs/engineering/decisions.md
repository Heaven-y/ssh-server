## 2. 对话、skills 与命令的接入边界

- Claude 使用 `@anthropic-ai/claude-agent-sdk`；Codex 以本机 `codex app-server` 的 JSON-RPC 接口为主，不另写 CLI 会话历史解析器。
- 会话始终绑定原 Agent 与官方会话 ID。网页为显示历史读取消息；继续会话通过 `resume` / `thread/resume`，不把显示出来的全部历史重新提交给模型。
- Claude 的命令 / skill 信息来自初始化元数据及 `supportedCommands()` 等 SDK 能力；Codex 通过 `skills/list` 发现技能，调用时使用官方 skill 输入结构。
- 官方协议支持的控制动作要映射到实际接口，例如 Codex 的手动压缩使用 `thread/compact/start`。终端专用命令须明确标注，不能仅作为普通聊天文本转发就宣称支持。
- 本机已核对的接口版本为 Claude Agent SDK `0.3.286`、Codex CLI `0.156.1`。这是接口存在性的核对，网页集成和真实交互仍未完成。

## 3. 编辑、同步、版本记录与运行

目标流程：Agent 修改本地文件 → 同步成功 → SSH 运行 / 提交任务 → 拉回同步范围内的小文件 → 返回命令结果。普通消息/技能轮次结束再同步，纯上下文/压缩命令除外。用户编辑器的“保存文件”也进入同步流程。用户在服务器文件视图发起的移动等操作按源/目标是否涉及同步范围协调，不以全部下载后再上传实现。

“保存版本”只管理本地 git 历史。运行和同步不依赖 git 提交，服务器不需要 git。执行前存在未处理的相关删除或冲突时，不能悄悄运行服务器上的旧版本。

长训练使用服务器已有的后台方式或 Slurm 提交，提交成功不代表训练完成。用户稍后发消息要求检查时，Agent 再查询任务、读取日志或结果；大型结果保持在服务器，按需返回必要内容。

## 4. 轻量编辑器的选型

选用 CodeMirror 6 与 `@uiw/react-codemirror`，先在原生配置编辑中接入 JSON / TOML 高亮和搜索，按需加载编辑模块。后续 M3 的本地文件浏览、修改标记、保存和冲突处理复用这一组件；引入组件不代表 M3 已完成。

不引入完整 code-server / 浏览器 IDE，不在服务器安装开发服务。“本地代码”文件树使用同步范围内的副本；“服务器文件”视图列出远端实际目录并提供直接管理，不受本地编辑过滤隐藏大文件。未保存的编辑缓冲与 AI、同步或远端文件操作冲突时提示处理，不静默覆盖；远端管理不自动把大文件放入编辑器。

服务器内部移动/复制优先原生文件操作，跨文件系统使用已有工具并反馈进度和部分结果；默认不覆盖同名目标。下载为用户显式操作，与自动同步独立。界面提供右键菜单、目标选择器及拖动，保留可见按钮和键盘入口；细则见需求 F10、布局 5.4 和架构 5.12。

2026-10-03 确认：工作区固定本地/远端同步目录，服务器文件视图可浏览同一 SSH 账号有权限访问的其他目录。默认打开工作区根，提供“返回工作区”；浏览位置不改变同步范围，也不触发同步。跨越同步范围的实际移动/复制才进入影响预检和相关工作区协调。

## 6. 手动结果分析与实时资源显示

两者分别响应不同需求：

- 结果检查由用户发消息触发，可以读取远程日志、任务状态、结果表格并让 AI 分析；等待期间不自动检测任务完成。
- 资源显示由本地后端读取 GPU、CPU、内存和进程指标，更新网页，不发送对话消息或调用模型。
- 文件定时拉取只同步文件，既不推断任务完成，也不触发 Agent。

资源采样使用服务器已有的 `nvidia-smi` 机器可读查询以及 Linux 系统信息 / 命令，无须运行或安装 `nvitop`。显示采集主机、时间戳和不可用原因；共享账号下不把全部进程认定为当前用户或项目的任务。

2026-10-05 资源详情已接入：选择请求驱动 HTTP 与可见时5秒检查，宿主按实际认证身份共享、磁盘按目录隔离；使用成熟CSV解析器并保留物理GPU编号。缓存/退避/容量、隐私与连接复验等裁定见[资源决策 R01–R09](resources-decisions.md)，实际SSH和网页证据见[资源验收](../guides/resources-acceptance.md)。

登录节点与计算节点分离是某些 Slurm 集群的部署方式，和账号密码、私钥、免密登录没有因果关系。本项目默认读取当前 SSH 服务器；如果任务实际在其他节点，不能把登录节点的 GPU 指标标成训练节点指标，第一版不自动跨节点采集。

采样频率和开销在真实服务器上验证，多个工作区共用同一目标的采样结果。Slurm `squeue` / `sstat` 供按需查询；不设高频调度器轮询，`sstat` 可用字段取决于集群记账配置。

资料依据：[nvitop](https://github.com/XuehaiPan/nvitop)、[NVIDIA SMI](https://docs.nvidia.com/deploy/nvidia-smi/index.html)、[Slurm squeue](https://slurm.schedmd.com/squeue.html)、[Slurm sstat](https://slurm.schedmd.com/sstat.html)。资料核对不等于已验证用户服务器的工具与权限。

## 7. SSH 认证与凭据生命周期

SSH 密码 / 私钥、模型服务令牌、网页访问令牌是不同凭据。用户当前环境能免密连接，不能仅凭“不输入密码”判断其具体机制；文档不将其写成某种已验证的 SSH token 方案。

- 连接配置可以持久化地址、端口、账号、认证方式与已有私钥路径；明文密码不写入工作区配置。
- 用户可选择保存密码，由 Windows 当前用户的系统加密能力保护本机独立凭据文件。主动断开、退出清理内存但保留保存项；取消“保存密码”勾选时移除保存项并断开，不另设忘记入口，目标地址、端口或账号变化时不复用旧凭据。
- ssh2 和 rclone 使用同一组认证信息。明文密码不能放在命令行参数、日志、磁盘临时配置、Agent 或浏览器持久存储。
- 不将 rclone 的密码混淆当作加密或允许落盘的理由，不因密码认证关闭服务器主机密钥校验。
- 当前已实现内存密码、私钥认证、加密保存密码与同步基础；主动断开保留密文，取消保存删除密文。完整向导和终端基础已贯通，证据见向导/终端验收，完整串联边界见路线图。

## 8. 后端选型、分析位置与运行边界

### 8.1 本地后端选型

已选定 Node.js + TypeScript + Fastify，继续现有后端实现。它负责本机 HTTP / WebSocket、Agent 官方接口、SSH、同步、文件与版本操作的协调。TypeScript 可以沿用 Claude / MCP 的官方 SDK、Codex 生成协议和前后端共享类型，减少跨语言接口维护；Fastify 满足当前模块化路由、校验和流式通信需要。

| 方案 | 适合的工作 | 本项目的判断 |
|---|---|---|
| Node.js + TypeScript + Fastify | 异步 I/O、Agent SDK、SSH 和流式消息集成 | 已选用，保留现有代码和共享类型；重计算交给远程任务或独立进程 |
| Python + FastAPI | 在 API 服务内直接使用 Python 科学计算库 | 可实现相同网页服务，但主要分析在远端，无须因此更换协调后端；现有 TypeScript 接口仍需跨语言维护 |
| TypeScript + NestJS | 需要统一依赖注入、装饰器和分层约定的较大服务 | 与当前技术栈兼容，但本工具规模下增加框架约定，暂不替换 Fastify |
| Go | 编译分发、网络服务和 goroutine 并发 | 独立可执行文件有分发便利，但现有 Agent 接口和 TypeScript 实现需重新集成；当前单用户本地工具没有迁移依据 |

### 8.2 Python 分析的执行位置

用户要求分析远程结果时，Agent 通过远程工具调用服务器已有的 Python 解释器或项目环境，进行统计、绘图和结果处理。需要新分析脚本时先编辑本地小文件，经同步后在服务器执行；大数据继续留在原位置，只返回判断所需的摘要、日志、结果表或小图文件。

Python 项目不要求网页后端也用 Python。本地 Node.js 服务负责启动远程命令、收集输出和反馈状态，不承担项目的大规模数据计算。需要的 Python 或依赖在服务器不存在时应报告缺失并询问可用环境，不自行安装。开发 skill 使用本机 Python 是另一项按需依赖，不改变网页后端选型。

### 8.3 并发与分发边界

Node.js 的 JavaScript 主要在一个事件循环中执行，但异步 I/O 可以同时等待模型消息、SSH 通道、子进程输出和文件操作。当前目标是单用户本地工作区的多个活动并行：对话、终端、同步和资源刷新互不全局阻塞；同一会话只运行一轮，同一工作区的同步串行处理。Go 的 goroutine 是另一种并发机制，不能据此推断当前服务必须迁移，也不承诺未经测量的吞吐量。具体队列、超时和输出限制见 [架构](architecture.md)。

后端语言决定本机协调方式，不会直接加速服务器训练；训练耗时取决于项目算法、数据、依赖和服务器资源。当前保留 Node.js 本地启动方式，独立 `.exe`、安装器、Go 迁移和外部工具打包仅是比较话题，未加入第一版交付要求。即使 Go 后端可以编译成独立可执行文件，也不意味着 Claude / Codex CLI、git、rclone 等外部依赖自动被包含。

## D22 工作区配置移除与活动边界（2026-10-05）

选择拒绝活动写操作和未解决任务后移除配置。强制中断会留下不确定远端结果或编辑缓冲，要求先处理活动更便于判断实际状态。配置摘要绑定确认，写盘前复验；仅保存成功后关闭所属通道，共享 SSH、两端文件、Git、原生历史、凭据及磁盘任务/同步记录保留。外部客户端和服务器独立训练进程不受本机租约控制，关闭 PTY 不代表取消训练。

普通 HTTP 的 `Upgrade` 头不能证明真实升级，使用 Fastify 插件标记区分；租约释放同时等待 handler 与响应结束。网页删除成功是业务结果，即使弹窗卸载也须关闭宿主保留的所属面板。详细 L01–L13 与 Review 修复证据见[生命周期设计](../superpowers/specs/2026-10-05-workspace-lifecycle-design.md)及[验收](../guides/workspace-removal-acceptance.md)。

## D23 测试环境依赖位置（2026-10-05）

Vitest 从仓库根加载 jsdom 环境，因此将固定版本 jsdom 27.4.0 从网页包移至根开发依赖。干净 `npm ci` 的安装树也能解析环境；RTL 与 DOM 测试库继续属于网页包。保持已有覆盖率范围和门槛，不用旧安装树或降低门槛掩盖环境问题。
