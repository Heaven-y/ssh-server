# 原生 CLI 对话接入

核对日期：2026-11-10，代码基线 `165caa4`。本文记录已确认的产品方向与当前接入边界。旧设计、M1 计划及上一代验收原文通过提交 `c686ef2` 追溯，不将历史测试结果当成本轮证据。

## 1. 意图与顺序

核心工作是让用户按项目找到原生会话并继续工作。Claude Code、Codex、Antigravity 都属于主线。先完成三者的对话流程，再完善各自原生配置；AgentDeck 自有插件及 SSH Console 接入后置，不建设 DSH 插件兼容层。

保持现有 Electron、React、Fastify 与 TypeScript 架构。本文说明对话协议，SSH 入口与生命周期见[工作台插件](workbench-plugins.md)。对话正文只保存在各 CLI 的原生存储中；界面与传输过程可以持有内存状态，不能新增正文数据库。

## 2. 当前接入

- 在已有项目中选择三个 CLI，显式发送才新建会话；点击列表中的原生会话可以继续。
- Claude/Codex 展示历史、流式文本和工具事件，接住原生决定发出的审批，支持停止。
- Antigravity 读取摘要与目录归属，并通过原生服务回放已适配的文本、工具与活动步骤。新回合仍使用原生 id 续接，不把界面内容复制成另一个会话库。
- Antigravity 没有交互审批通道：实际发生软拒时显示说明；不伪造允许按钮，不默认绕过权限，也不常驻权限提醒。
- 模型和强度默认留空，参数省略表示继承 CLI。只显示本机能力报告的可选项；用户可显式填写模型标识。
- 模型目录可跨应用重启复用；首次无缓存时打开菜单获取，也可手动重新获取。技能与命令不写入模型缓存，显式打开技能入口后按实际目录获取；斜杠补全只读取已有目录。
- Claude 的探测与实际驱动采用同一份本机程序；找不到时明确失败，不回退到 SDK 自带程序。SDK 仅作为协议客户端。
- 对话与执行轨迹共用事件归并；原生用量、步骤耗时和上下文进入统一展示，平均速度按回合或步骤分别计算。完整字段及计量边界见[CLI 用量与执行轨迹](cli-observability.md)。

## 3. 运行边界

同一窗口可以并行运行不同原生会话。切项目、选择另一会话、新建或打开工具页面都不终止既有回合；前端为各会话保留可返回的运行状态和审批入口。一个原生会话仍一次只接收一轮，创建后不能改换 CLI。

WebSocket 通过恢复握手将页签与后端稳定连接身份关联，短暂断开不立刻中断回合或拒绝审批。重新连接按序号补收，刷新可从缓存重建当前及后台回合；恢复前取消冲突的历史请求。缓存缺失时提示重读原生记录，不重复执行原输入；完整退出应用仍清理子进程，预算见[架构](architecture.md#44-历史与前端状态)。

历史加载失败时不得在未知上下文上继续发送；提供重读动作。旧适配器的不可回放响应仍有兼容处理，但当前 Antigravity 不再固定返回该状态。CLI 返回的会话身份须与当前项目和预期原生 id 一致。

## 4. 接口与实现选择

既有 `ChatView`、`Composer`、工具卡片、审批卡片及 `TurnManager` 继续复用。`SessionPane` 将当前项目接入对话视图；新建按钮列出三个 CLI，未选会话时提供新建输入。

能力接口保持 `/api/workspaces/:id/agent-capabilities`：GET 仅读缓存，并通过 discovered 区分尚未获取和已获取的空结果；POST 用于首次打开模型菜单或手动刷新。既有会话传可选 `sessionId`，服务核实其原生目录后读取该目录能力，前端缓存区分会话；普通文本无需能力目录。

模型持久缓存按实际 cwd 与 CLI 区分，项目记录 id 变化不导致重复发现；命令就绪使用独立 commandsDiscovered 标记。配置保存立即作废同 CLI 的内存、磁盘和在途发现。失败保留已有可用模型，不让新响应之外的旧结果重新落盘。

三种来源先枚举全局摘要，再按项目路径规则确定归属。`GET /api/sessions?agent=...` 专供显式查看其他目录，仅返回无归属摘要，零项目也能使用。共享在途枚举不缓存正文，取消一个查询不终止其他订阅者。

读取、续接、管理及分叉都复核原生目录。会话位于项目子目录时使用原生 cwd 执行，项目根只用于归属；多目录摘要无法唯一归属时拒绝操作。启动环境解析后重新核对实例容量，原生配置写入与项目换目录通过活动租约互斥。

`/ws` 沿用 `chat.send`、`chat.interrupt` 和 `permission.respond`。非法发送请求若带有效 `clientTurnId`，错误须回传该关联字段，避免界面永久处于等待状态。

Antigravity 使用本机 `agy --input-format stream-json --output-format stream-json`，输入为 `{"event":"user","message":{"content":"…"}}`。依据是本机帮助和[官方 headless 协议](https://antigravity.google/docs/cli/headless/)。每轮关闭 stdin，下一轮用 `--conversation` 续接；不依赖猜测的常驻控制接口。输出按 `event` 与嵌套载荷解码，处理 `init`、`step_update`、`result` 和 stderr。续接用摘要验证目录，成功结果仍等待真实进程退出；超时请求停止并保持占用，不能伪造退出成功。

AGY 1.5.1 的新摘要通常在进程 close 后才完整落库。本页通过已发送会话补充工作区导航，原生摘要到来后合并；不提前生成原生记录。公开 `agent_response.text_delta` 按增量显示，隐藏思考与签名不公开；原生可能从工具公开参数中删除 `toolSummary`，此时仅显示已知动作与参数。

普通 stderr 不再直接当作错误。明确认证失败、HTTP 500、503 / UNAVAILABLE、权限软拒用固定脱敏说明，result、工具错误与 stderr 的同类提示去重；未知失败在排空双流并确认进程退出后兜底。500 只说明服务内部错误，不推断凭据错误或配置未保存。原生 auto 不支持且已回退时显示权限模式活动，不替用户改模式或重新请求。工具软拒也读取 `denied_actions`，原生 SUCCESS 仍保持原生结果语义。持续重试而未报告原因时只能显示等待，不能凭空判定 503。

Windows 冷启动后的终端闪现已定位到原生 CLI 自行创建的后台更新器，父进程的 `windowsHide` 无法控制该更新窗口。工作台对话、管理和发现子进程使用 `AGY_CLI_DISABLE_AUTO_UPDATE=true`；当前 1.5.1 不识别值 `1`。此开关只进入工作台启动的进程，不改用户原生配置或全局环境，独立 CLI 的更新操作仍由原生程序管理。临时配置实机对照出现一次更新器控制台，启用开关后及重新创建正式运行器的两轮对话均无新增可见控制台；不据此承诺用户命令或外部 MCP 程序永远不创建窗口。

当前 AGY 的累计 result 在失败后成功续接时可能仍带历史 ERROR。已用真实 CLI 和本机模拟服务复现退出码 3/0/3 的失败、成功、再次失败三轮。显式续接、身份一致、新输入边界、最后公开答复完成、自然退出 0 且无本轮终止失败共同成立时，直接校正历史错误。标准 TOOL_ERROR 可由模型继续处理，之后确实完整回复时不阻止此校正，工具自身仍显示失败。

若自然退出后仍有累计错误，且实时完成证据不足，则在可信、唯一的本轮输入索引上只读复核原生轨迹，最多等待 5 秒。原生记录须属于同一会话和目录、已经空闲，输入后的所有步骤完整结束、没有另一输入及拒绝/超时/压缩失败，最后公开答复非空并覆盖已收到的最大步骤索引。这样可补齐缺少文本增量或中间状态未形成可靠终态的情况。取消、非零退出、强制清理、已发出的当前轮错误、未知输入边界或读取失败都保留原错误；核验可中断且不发送模型消息。最终 result 诊断等核验完成后才显示，当前工具与 stderr 的明确错误仍即时展示。HTTP 524 继续表示真实模型服务超时，单个工具完成不足以判定整轮成功。

Antigravity 模型目录在临时 home/cwd 中执行原生 models，只复制模型白名单，不加载用户 MCP、Hooks 或插件；临时更新检查标记避免原生后台更新器闪出终端。Gemini Key 与 ADC 认证分别沿用原生入口；账号模式交给 CLI 读取系统凭据，获取失败保留配置模型，不据此断言账号未登录。当前 1.5.1 两列 TSV 已隔离验证，格式变化会失败而不猜测字段；系统已登录的正向流程及文件回退认证尚未验证。真实对话的规则与插件继续由 CLI 加载。

Antigravity 命令及内建技能使用禁止外部请求的临时 Gemini 配置读取 `/help` 与 `/skills`，不走账号模式的交互登录分支；工作区与全局技能由只读 `GetAllSkills` 获取名称、路径与禁用标记。1.5.1 已核对工作区、CLI 私有、Shared 和普通全局的同名优先顺序。原生界面命令只列出实际接入状态，不伪装成模型提示词；模型、强度、权限与配置已有工作台入口。可调用技能在发送前重新核对身份和路径，再传斜杠名称，由原生 CLI 展开正文。版本变化导致目录格式或接口失配时停止对应能力读取。

历史读取复用 Antigravity 原生服务的 `GetCascadeTrajectory` 和步骤分页接口，并沿用会话 ID、唯一目录、非内部子代理及空闲检查。用户输入与公开助手文本、已知工具、压缩和原生活动按白名单映射，内部签名、隐藏载荷及诊断正文不直接暴露；读取预算见[架构](architecture.md#44-历史与前端状态)。此入口属于内部协议，隔离合成数据验证不等于所有 CLI 版本或真实生成记录兼容。

Claude 上下文沿用 summary 查询，回合用量取原生结果；计时在结果到达时截止，排除之后的上下文查询。Codex 总量仅在基线连续时计算回合增量，恢复但缺基线时不补造首轮用量。Antigravity 先保留已知步骤统计，不将不确定的 result 累计值当单轮结果。历史只展示能够读到的原生数据，旧会话缺少计时时不能还原精确生成速度。

Claude 子代理历史通过 SDK `listSubagents` 与 `getSubagentMessages` 按需读取。会话路由追加 `/subagents`，无查询时列出原生 ID，带 `agentId` 与可选 `cursor` 时返回该子代理一页消息。目标页长 100 条，末尾同一 API 回复的多块内容整体留到下一页；单次回复超过页长时扩读，完整回复最多 1,000 块，超限明确失败，不静默截断。游标按实际返回的原生消息数量推进。先复核父会话的唯一项目归属，再要求子代理 ID 存在于原生目录，拒绝路径形式标识。嵌套子代理保留 parent_agent_id；独立视图解除父引用过滤但移除分叉点，不把其正文、统计或详情选中状态并入父会话。关闭视图释放查询缓存，打开时重新读取原生记录。

Claude 历史恢复 `assistant.message.usage` 为模型步骤用量，按 API message.id 合并同一次回复的多块记录，统计只放在最后可显示块之后；不把 transcript 完成时间当成生成耗时。SDK 0.3.286 的历史入口不返回完整上下文报告；当前 Codex thread/read 契约没有 tokenUsage；Antigravity 历史已提供上下文估计，但只有单次完整生成的索引、执行身份和用量均一致时才显示生成计时与均速。这些是读取契约边界，界面显示未知值，不用模型名称猜窗口或用时间戳差值补统计。

原先禁止运行中切换的临时限制已移除；导航只改变当前展示，运行事件继续归属原会话。断线保留受恢复预算约束，长期离线仍会中断。

### 4.1 会话引用读取

稳定引用格式为 `agentdeck://session?workspace=<项目ID>&agent=<CLI>&id=<原生ID>`。共享解析器严格校验协议、字段和身份，兼容已有 HTTP(S) 网页片段；解析不会访问链接指向的网站。引用只定位本机工作台中已登记的工作区，不承担跨机器共享正文或改变会话归属。

`session-tools/main.ts` 提供本机 stdio MCP `read_session({reference,cursor?})`，复用三种原生历史提供方以及完整项目归属裁决。工具只返回公开用户、助手、工具与活动内容，不返回隐藏思考、系统消息、权限与诊断事件，也不写第二份正文数据库。历史正文是被引用资料，不构成当前用户授权；正文中原有的工具输入等内容不承诺全面脱敏。

每页最多 32 个片段、页 JSON 最多 8 KiB，以适应 AGY 原生工具返回长度限制。长条目按 `index` 与 `offset` 拼接 `content`，`complete` 标记条目结束；工具及活动项完整拼接后为 JSON。读者必须沿 `nextCursor` 读取后续页。签名游标绑定规范引用、项目目录和可见历史快照，历史变化或 MCP 重启使旧游标失效，明确要求重新读取。三种 CLI 均在此入口保留原生长工具内容，普通页面仍沿用原显示预算；原生自身未保存的内容无法恢复。

## 5. 验证

常规自动验收使用受控运行器和合成原生事件验证发送、续接、审批、停止、错误、权限软拒及进程清理；本机 `--help` / `--version` 可运行。真实模型请求仅在用户明确授权后按既定预算单独进行，使用隔离目录，不修改用户原生配置或 SSH 数据。

前端验证须覆盖三个 CLI 可选、历史失败禁发、原生步骤回放、目录缓存复用、默认参数省略、输入法与停止，以及运行中导航后的事件和审批归属。执行轨迹另核对跨轮 ID 复用、右栏详情、审批、缺失统计与速度口径；使用隔离的本机服务检查页面，不把受控测试写成真实模型验收。

类型、代码质量、构建及相关回归通过后记录命令与证据；原生 CLI 升级后协议仍可能变化，失败只影响对应适配器。

最新源码验收、实际 URL/Key 结果和账号模式暂缓状态集中在[路线图](../roadmap.md#已有验收证据)。2026-11-09 的有限真实闭环与旧 AGY 参数错型实验保存在 `165caa4:docs/engineering/native-dialogue.md`，不得描述成当前服务均可完成任务。

原生主模型、标题和安全检查可能使用不同模型渠道，主模型成功不代表辅助请求可用。工具参数错型由原生 schema 拒绝；工作台不修写响应、不替换辅助模型或放宽原生安全判定。

## 6. 会话管理接入

会话菜单在应用内提供已接入的管理操作，使用同一项目归属校验、空闲锁、确认与分支对话框。Claude 使用 SDK，Codex 使用 app-server；Antigravity 借助本机 agy 启动的原生会话服务完成操作，不要求打开终端，也不手动复制轨迹或删摘要行。

主界面通过 `GET /api/sessions/page` 分页，scope 区分活动、归档与无归属；search 检索未加载的原生摘要，cursor 继续读取。旧项目列表保留兼容，分页预算见架构。读取和写入统一以 `/api/projects/:id/sessions/:agent/:sessionId` 定位，写入分别追加 `/actions`、`/fork`；旧 `/api/workspaces` 下的会话路由删除，SSH 的旧路径不在本轮迁移范围。动作、历史和分叉不接受查询字段，响应统一禁止缓存。

归档页同时查询三个来源。Codex 仍按原生归档/恢复执行；Claude、Antigravity 使用工作台身份标记，不改 CLI 历史。归档会话必须恢复后续聊或创建分支。删除需确认实际范围；会话忙时拒绝管理。分支成功只在原选择代次仍有效时打开新记录，其他情况刷新来源列表。

Antigravity 的公开 ACP 初始化目前没有 fork/delete 能力，已验版本 1.5.1 的原生服务则包含 `ForkConversation`、`DeleteCascadeTrajectory`、`UpdateConversationAnnotations`。适配器通过自己启动的 `agy acp` 引导本地服务，只接受该进程日志中匹配 PID 的 HTTP 回环端口。管理请求限固定方法，不发模型 prompt，不连接其他进程或用户提供的地址；内部协议升级失配时返回操作失败，不尝试修改 SQLite 兜底。

写入前用原生轨迹核实会话 ID、唯一工作目录、空闲状态和非内部子代理身份。创建分支按已完成原生步骤执行，再核对新 ID、目录、父引用和摘要落库；删除轨迹后以 `JetboxDeleteSummary` 清原生索引，确认两者均已移除。若轨迹已删而摘要清理中断，重试必须重新验证摘要身份与目录，且只有明确的原生 not_found 响应才进入补清理；接口不存在或通信错误不能当作会话缺失。

管理器关闭自己的进程、请求和临时日志，应用退出时统一取消待启动操作。隔离验证用原生空会话与合成已完成步骤，不能代替真实账号模型回合验收。

## 原生权限模式

输入区权限菜单只覆盖当前会话后续轮次，所属会话运行/准备/管理及权限读写期间禁用。已保存的选择在重新打开时恢复；没有工作台选择时，由 CLI 决定新建默认或恢复原生会话权限，不默认完全访问或开启自动审查。权限读写失败阻止按未知选择发送，成功不弹提示。工作台选择不改写 CLI 文件，也不设为其他新会话的默认。

`GET/PUT /api/projects/:id/sessions/:agent/:sessionId/permission` 独立于历史正文读取，校验项目目录和原生身份；PUT 在会话空闲锁与项目租约内保存。续接未显式传入权限时，TurnManager 读取该身份的已存选择，显式参数优先。新会话只在收到并核实原生 ID 后持久化本轮显式选择，保存尝试完成再结束轮次；没有原生 ID 不创建记录，元数据写失败单独提示，不重试模型任务。存储格式见[会话权限偏好](native-configuration.md#会话权限偏好)。

| CLI | 菜单选择 | 原生映射 |
|---|---|---|
| Claude | 手动审批、接受编辑、自动审查、计划模式、不询问、跳过权限检查 | SDK permissionMode: default、acceptEdits、auto、plan、dontAsk、bypassPermissions |
| Codex | 请求批准 | workspace-write + on-request + user |
| Codex | 帮我批准 | workspace-write + on-request + auto_review |
| Codex | 完全访问 | danger-full-access + never；不创建自动批准回调 |
| Antigravity | 接受编辑、自动模式、计划模式 | --mode accept-edits / auto / plan |
| Antigravity | 跳过权限检查 | 显式 --dangerously-skip-permissions |

Claude 仅显式 bypass 时设置 SDK 的 allowDangerouslySkipPermissions。auto 使用 Claude 原生分类器；Codex 自动审查也由原生执行，不在网页静默回答权限请求。Antigravity headless 仍没有交互批准通道，不把软拒伪装成已允许。

Codex 的 MCP 工具确认也进入现有批准/拒绝流程：仅接收带 `codex_approval_kind: mcp_tool_call` 的原生空对象表单，按 `accept`、`decline` 或 `cancel` 返回本次决定。具有输入字段、组合约束或 URL 登录流程的请求不能当作简单工具确认；取消后迟到的批准无效，不增加持久授权。工具说明与参数由原生请求提供，不能因为菜单允许某种模式就自动批准。

AGY 实时工具以 `DONE` 或 `ERROR` 结束；失败及时回填工具结果，保留原生错误和耗时，不再等到回合结束后仅显示“未完成”。无结构 stderr 只判断诊断类别，不从句子中猜工具名。其通用 `call_mcp_tool` 在 1.5.1 对 Arguments 缺少对象类型约束，模型返回 JSON 字符串时会直接传给 MCP，标准服务会拒绝。原生按工具 `eager` 加载可避开这一包装，设置方式见[原生配置](native-configuration.md#antigravity-mcp-工具加载)；不由工作台私自更改用户 MCP 规则或修写模型返回参数。

Codex 已有会话会恢复历史权限，所以用户显式选择“沿用原生配置”使用单独的 native 动作：先创建不持久化的空线程，让原生解析当前有效配置，读取审批策略、审查对象及权限 profile/沙箱后取消订阅，再显式用于正式会话续接。空线程不发送 turn/start 或模型 prompt。必要字段缺失就停止，不能省略字段后误回到历史的完全访问。无选择的普通续接仍尊重原生会话，不强改其权限。

菜单列出已核对协议支持的模式；组织策略、账号/模型可用性与 CLI 版本仍由原生校验，不能把菜单可见当成账号已获权限。原生拒绝时本轮停止并显示错误，不降级策略、不换模式重发。Codex 权限字段拒绝使用固定说明，不泄漏原始 RPC 错误中的路径、配置或凭据。高级自定义 permission profiles、Claude rules 和其他原生细项仍走原生配置，常用预设不覆盖未显式选择的值。

依据：[Claude 权限](https://code.claude.com/docs/en/permissions)、[Agent SDK 权限](https://platform.claude.com/docs/en/agent-sdk/permissions)、[Codex 权限模式](https://learn.chatgpt.com/docs/permission-modes)、[Codex 自动审查](https://learn.chatgpt.com/docs/sandboxing/auto-review)、[app-server](https://learn.chatgpt.com/docs/app-server)。本机 SDK 类型、Claude/agy --help 和 Codex 生成 schema 已核对；这不等于真实模型回合验证。
