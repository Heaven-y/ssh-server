# 架构

更新于 2026-11-06。本文记录原生 CLI 工作台、配置、插件和桌面交付的实现边界。会话协议见[接入说明](native-dialogue.md)，验收范围见[路线图](../roadmap.md)。重整前的实现说明保存在 `c686ef2:docs/engineering/architecture.md`。

## 1. 分层与职责

```text
Electron 主进程（apps/desktop）
  └─ 本机 Fastify（apps/server）
       ├─ HTTP + WebSocket → React 页面（apps/web）
       ├─ 项目、原生会话、CLI 适配、配置与能力目录
       ├─ 工作台插件注册、权限与静态页面服务
       └─ SSH Console 与兼容工具共享 SSH 池、信任和凭据
共享协议与校验（packages/shared）
```

Electron 负责入口、生命周期及本机目录选择。目录选择只暴露窄 IPC，核对主窗口、主 frame 和同源页面；导航或销毁后丢弃返回值，插件 iframe 无权调用。业务服务与浏览器调试共用一份实现。CLI 在本地项目目录执行，模型请求由 CLI 发起；服务器操作经 SSH 由用户触发。

会话和工具各自持有运行状态。自有插件宿主管理内置 SSH Console 与本地安装的静态页面插件；外部插件只通过声明权限的固定接口访问宿主，没有通用 Node 执行能力。包和消息契约见[工作台插件接口](workbench-plugins.md)，不包含 DSH 兼容层。

## 2. 技术栈

| 层 | 当前选型与职责 |
|---|---|
| 运行环境 | Node.js 22+、TypeScript 5.9，开发服务使用 tsx |
| 桌面 | Electron、electron-vite、electron-builder；隔离渲染进程与本地 Windows 打包 |
| 后端 | Fastify 5、WebSocket、zod 参数和配置校验 |
| Claude | Agent SDK 作为协议客户端；本机可执行程序作为驱动目标 |
| Codex | 本机 `codex app-server`，stdio JSON-RPC |
| Antigravity | 本机 `agy` 流式子进程与独立原生管理服务；Node 内置 SQLite 只读摘要 |
| SSH | `ssh2`，exec、SFTP 和远端 PTY 共用连接但独占通道 |
| 前端 | React 19、Vite 8、Tailwind 4、Ariakit、cmdk、react-resizable-panels |
| 状态与通信 | zustand、TanStack Query、partysocket |
| 消息与编辑 | streamdown、react-virtuoso、CodeMirror 6 |
| 终端与字体 | xterm.js/fit/search、系统界面字体与随包分发的 JetBrains Mono |

精确依赖版本由各 `package.json` 和锁文件维护，选用理由见[现行决策](decisions.md)。不因服务器使用 Python 而改写本地后端；涉及统计或分析时使用服务器已有环境，不自动安装依赖。

## 4. 项目、会话与回合

### 4.1 项目及归属

项目存储串行读写，保存时校验 schema 与唯一 id，再用临时文件原子替换。新增或修改目录必须确认存在；更新其他字段和导入离线目录不能丢掉有效记录。现有服务器别名与远端目录须成对，目标别名由服务器档案验证。

`ownership.ts` 只比较规范化路径，不访问磁盘。Windows 盘符/UNC 使用 Windows 语义，POSIX 路径保留大小写；Antigravity URI 只接受 `file://`，支持 JSON 数组、单值及换行/分号列表。归属顺序和无归属行为定义在需求 F2。

会话列表从各原生来源枚举全局摘要，再统一投影 `projectId`。项目路由保留当前项目和无归属条目；全局 `/api/sessions?agent=...` 只返回无归属摘要，零项目时也可显式发现。并发读取共享同来源的在途请求，最多 6 个枚举、每次 100000 条摘要；没有跨请求结果 TTL。订阅者独立取消，全部取消才终止底层读取。前端按 CLI 与原生 id 去重，正文仍需选中后单独读取。

单条读取、续接和管理先核实原生目录，再验证其唯一项目归属。项目包含子目录时，运行器与能力刷新使用会话的真实目录，不能替换为项目根；Antigravity 多目录摘要没有唯一归属则拒绝续接。

会话摘要可携带经原生字段解析的单一本机 `directory`，用于添加项目预填；该字段不作为授权依据。目录变更与项目移除和活动回合、原生资源写入、文件任务互斥，锁内修改防止检查后又开始新操作。前端换目录后清该项目的会话与能力缓存、取消旧历史，并按选择身份决定是否重置当前主区；新增、换目录、移除项目均刷新全部会话摘要，及时更新无归属及重叠项目的归属。

### 4.2 CLI 接入

| CLI | 原生来源 | 已接入运行路径 |
|---|---|---|
| Claude | SDK 会话列表、历史、改名/删除/分叉 | 探测与回合共同定位本机程序；SDK 仅作为协议客户端，界面承接原生审批 |
| Codex | app-server 原生会话、工具与审批 | 省略未选择的参数，按需加载能力，回合和管理均绑定原生身份 |
| Antigravity | SQLite 摘要、时间和 `workspace_uris`，历史不可回放 | 新建、续接、流式、中断；后台会话服务提供改名/分支/删除 |

探测运行本地版本/帮助命令，Codex 另检查生成的协议 schema；每个 CLI 单次探测超时为 5 秒，输出有独立上限。stdout 与 stderr 一起核对，四态结果不意味着登录成功或真实模型请求已通过。

`runProcess` 用 `shell: false` 和隐藏窗口启动，支持 stdin、独立环境、AbortSignal、输出上限和超时。长期对话管道由各适配器管理，prompt 不写进命令行参数。

### 4.3 回合控制与原生参数

`TurnManager` 在准备前建立轮次，用 Agent+原生会话 id 占用会话；改名、删除、归档与分叉复用同一占用边界。停止取消准备或交给运行器中断，错误和结束都必须释放资源。

本轮前端在运行期间阻止切项目、切会话、新建及通过导航或命令打开插件主页面，保持停止/审批控制可达；后端保留会话隔离基础，但不把后台多会话界面当成本轮交付。断线按本轮设计中断所属回合，不自动重发；跨连接事件续传尚未承诺。

Claude/Codex 的既有运行时按会话复用，空闲回收预算为 5 分钟。缓存身份含项目、原生 id 与启动参数；关键输入变化后重新启动，崩溃实例不得再次复用，关闭应用统一 dispose。Antigravity 每轮关闭 stdin 并结束进程，下一轮用原生 id 续接；已有会话的启动环境快照独立保留，显式重启后刷新。

模型/强度未选则省略参数。原生权限配置决定是否请求审批，宿主只承接答复。Antigravity 没有同等审批通道，软拒输出独立显示。能力 GET 返回缓存；模型菜单首次无缓存或用户重新获取时发 POST，失败不循环重试；既有会话带 `sessionId` 解析原生目录。模型缓存按规范化 cwd 与 CLI 落盘到 model-cache，每 CLI 至多 32 个目录、每目录 512 个模型、文件 256 KiB，只保存模型字段和目录摘要。commandsDiscovered 区分本进程命令目录，避免重启恢复模型时误用旧技能。保存配置作废内存与磁盘缓存，并拒绝失效请求回填。启动环境异步解析完成后再次核对实例预算，防止并发准备越过 32 个实例上限。

能力发现前检查目录；既有会话在原生归属读取前先检查项目根，再按已核实的会话目录发现。失效目录返回专用错误码并连接更换目录操作。模型反馈与技能反馈分别输出，避免一个分支失败影响另一分支的界面状态。

### 4.4 历史与前端状态

zustand 持有当前项目、CLI、会话和回合状态，TanStack Query 管项目、历史、设置等服务数据。选择变化取消旧请求，并用会话身份/代次防止迟到结果串线；历史失败禁止在未知上下文上续聊，Antigravity 501 则单独表达能力限制。

左栏占满窗口高度，中央标题栏随对话或插件切换；右栏只展示当前会话信息，每次启动关闭，不沿用旧服务器栏的展开偏好。SSH Console 经左上导航首次打开后保持挂载，隐藏期间暂停观察。具体尺寸与窄窗互斥规则见[界面约定](../product/ui-layout.md)。

实时视图复用 ChatView、Composer、审批和工具组件。既有时间线采用 react-virtuoso，读取工具白名单分组每段最多 40 项；审批、执行与错误独立成卡。原生只读历史与实时界面的验证不能互相替代。

partysocket 退避从 1 秒到 15 秒，关闭发送缓冲，防止断开时积压消息在重连后发送。历史与事件只在前端/进程内暂存，服务器没有正文数据库。

原生存储是会话的唯一事实来源。列表在首次挂载时读取；新会话返回 id、回合结束、重命名、分支、归档、恢复或删除后，取消同 CLI 的在途摘要请求并使相关列表失效，避免首次加载中的旧结果覆盖新状态。项目变更仍重新计算全部摘要归属。没有目录监听、revision 轮询或会话刷新接口；重新打开应用会读取 CLI 已保存的记录，工作台不维护第二份正文。

## 5. 存储与配置

### 5.1 工作台数据

默认目录为 `%LOCALAPPDATA%\AgentDeck`，可由 `AGENTDECK_CONFIG_DIR` 指定。非 Windows 的默认位置回退到用户 `.local/share`。项目、服务器档案、产品偏好、加密凭据、插件注册与安装副本、启动环境和旧文件任务均属于工作台数据；CLI 原生会话及配置保持原位置。

迁移先复制旧 `ssh-server` 目录的配置，再转换 `localDir`/`sshHost` 等旧字段。新目录已有文件不覆盖；转换前保留 `.bak`，旧目录不删，异常明确报告。当前格式只保留有效业务字段，不恢复同步与策略域。

产品偏好只含默认 CLI 与当前资源设置；退休字段在磁盘读取边界定点剔除，公开写入仍严格校验。坏配置保留并返回错误，不用空对象掩盖损坏。

### 5.2 原生配置

资源目录由各 CLI 的已知文件和有界扫描生成，浏览器只提交服务端资源 id 和可选项目 id，不提交任意绝对路径。Claude 区分用户、共享项目与个人项目；Codex 配置、规则、共享 Skills 保留各自位置；Antigravity 不补造项目 settings。具体入口见[原生配置说明](native-configuration.md)。

`safe-file.ts` 逐层核对目录和文件身份；内容按 UTF-8 读取，revision 使用 SHA-256，同目录原子替换前再次校验。JSON/TOML 检查语法，其余规则原文留给 CLI 解释。目录 GET 只返回元数据，显式 POST open 才读取完整正文，保存响应不回显内容；旧两文件接口与资源接口共用按路径串行队列。扫描、文件大小与创建约束由原生配置说明维护，当前没有自动备份目录。

工作台归档使用 `session-preferences.json`，仅保存 agent 与原生会话 id，不复制标题或正文。读写共用文件身份检查和路径事务；坏索引不覆盖。列表在原生枚举后按标记过滤，恢复撤销标记；已归档会话拒绝从旧选择继续发送或创建分支。原生删除成功后清理本地标记，附属清理失败不将已完成删除误报成失败。

启动环境对每种 CLI 单独限定变量，所有显式值使用系统加密，不修改本机服务的全局 `process.env`。新运行器持有启动快照，保存不终止现有会话；显式重启仅在空闲时释放该 CLI 运行器，使后续发送重新启动。状态响应不包含旧值，原生文件编辑器则仅在显式打开期间持有正文。

模型设置接口提供白名单字段表单，与原文编辑复用同一资源服务。保存后撤销对应 CLI 的能力缓存和在途发现；前端查询取消与刷新代次共同防止旧结果回填。字段映射、认证保护、TOML 定点编辑和密钥存储区别集中记录在配置说明中。

### 5.3 启动配置

| 变量或参数 | 用途 |
|---|---|
| `AGENTDECK_HOST`、`AGENTDECK_PORT` | 本机监听，默认 `127.0.0.1:4317`；端口可用 0 申请系统分配 |
| `AGENTDECK_CONFIG_DIR` | 工作台配置目录 |
| `AGENTDECK_TOKEN` | 进程内部会话秘密；缺省随机生成 |
| `AGENTDECK_DEV_ORIGIN`、`--dev-origin` | 显式允许 Vite 开发来源 |
| `AGENTDECK_CODEX`、`CLAUDE_CODE_EXECUTABLE` | 选择本机已有 CLI 程序 |
| `CLAUDE_CONFIG_DIR`、`CODEX_HOME` | 原生数据和配置根；不把文件复制到工作台 |

可执行文件覆盖口用于寻找已有程序，不自动安装或升级 CLI。Antigravity 当前从启动环境的 PATH 解析 `agy`，没有单独的可执行文件覆盖变量。

## 6. HTTP、安全与桌面生命周期

启动拒绝非回环 host。前端先调用 `POST /api/local-session`，校验本机 Host、精确允许的 Origin 与 Fetch Metadata 后获得 `AGENTDECK_session` Cookie；HttpOnly、SameSite=Strict，秘密比较使用常量时间。业务组件在握手成功后才挂载，握手等待上限 10 秒。

API 和 WebSocket 继续校验会话及来源；主应用禁止被 iframe 嵌入，开发来源必须显式放行。外部插件页面运行在无同源权限的受控 iframe 中，不能继承这些会话权限。普通 HTTP body 与对话 WS 上限为 1 MiB；原生文件等有独立预算的路由显式覆盖限制。日志只输出必要状态与版本，诊断避免携带完整配置或凭据。

| 接口域 | 当前路径与作用 |
|---|---|
| 项目 | `/api/projects` 与 `/:id`，列表/新增/修改/移除 |
| 会话 | `/api/projects/:id/sessions` 与 `/:agent/:sessionId`，原生读取；`/api/sessions?agent=...` 发现无归属摘要 |
| 原生管理 | `/api/projects/:id/sessions/:agent/:sessionId/actions`、`/fork`，来源及项目均在路径中 |
| 探测与能力 | `/api/agents/probes`；项目下 `agent-capabilities` 缓存与显式刷新 |
| 设置 | `/api/settings/product`、`/environment`、`/launch-environment/:agent`，原生文件由 `/api/native-resources/:agent` 提供 |
| 模型设置 | `/api/settings/models/:agent` 读取与保存表单；`/catalog` 的 GET 只读缓存，POST 原生获取，工作目录由可选 projectId 解析 |
| 插件 | `/api/plugins/*`，安装注册、启停、静态页面与权限内的设置存储 |
| 对话 | `/ws`，发送、停止、审批答复及回合事件 |
| SSH 档案 | `/api/ssh-targets`、`/api/ssh/*`，档案、认证、信任 |
| SSH Console | `/api/ssh-console/:serverId/*`，alias 定位资源、进程、只读文件和终端 |
| 现有服务器工具 | `/api/workspaces/:id/terminal*`、`/resources`、`/slurm`、`/remote-files/*` |

会话正文和管理只使用项目路径，全局发现不提供正文或写入入口；`/api/sessions/archived?agent=...` 汇总各来源的归档，恢复和删除仍走项目身份校验；旧工作区会话别名返回 404，服务器工具路径暂时保持。会话接口在进入解析前设置 no-store，写入确认和原生会话锁仍由服务层维护。前端构建由 Fastify 托管，接口路径不回退为 HTML。

安装版与静态预览的 Electron 主进程用端口 0 启动服务后加载实际地址；preload 仅暴露窄系统信息，`nodeIntegration: false`、`contextIsolation: true`。单实例锁让第二次启动聚焦已有窗口，关窗和退出都先释放服务，最长关闭等待 8 秒。后端清理终端、资源/Slurm、SSH、轮次和 HTTP；进程退出不留下后台业务实例。

桌面开发通过 Vite 加载源码页面，后端使用固定端口接受同源代理。React/CSS 采用热更新，preload 重建触发整页刷新，主进程及后端源码重建触发应用重启；这是开发工作流，不提供在途模型任务无中断迁移。开发监听范围和使用方式见[开发指南](../guides/dev-environment.md#3-启动与隔离验证)。

桌面后端与启动诊断通过专用 Console 输出；stdout/stderr 的异步 EPIPE 单独处理，接收日志的终端退出不再触发主进程错误弹窗。其他流异常继续抛出，业务异常仍由原启动失败与窗口流程报告，不安装全局异常吞错处理器。

## 7. SSH 基础与兼容模块约束

档案、信任和凭据由独立控制台与旧面板共享。本节的项目绑定终端、资源和文件任务约束仍适用于兼容入口；新的 alias 控制台约束见第 8 节。

### 7.1 档案、连接与凭据

服务器档案最多 128 条，hostname+端口+账号去重，alias 为产品生成的稳定 id。连接只接受 `{ alias }`，目标与认证材料来自档案；修改和移除前核对项目引用。`~/.ssh/config` 当前仅显式导入，未支持选项保留提示，不自动改写。

连接按真实身份与认证材料、信任记录复用。断开、改凭据或重连增加认证代次，迟到结果不能回填新身份；exec、SFTP 和 PTY 独立通道，单通道错误只释放自己。

未知主机先做不带凭据的握手，返回 SHA256 指纹和一次性挑战；挑战有效 2 分钟，最多 32 个，确认后记入 known_hosts。变更或吊销主机直接拒绝。密码仅内存或 Windows 当前用户 DPAPI 密文，编辑时按需读取并 `no-store`；凭据目录/文件保持相应访问权限。加密子进程使用环境白名单、stdin 传值，10 秒超时。

### 7.2 终端

打开终端前生成 5 分钟 HMAC 绑定票，绑定项目、服务器、目录、主机身份和认证代次。当前每项目最多 8 个会话、全局 32 个，单标签最多 4 个窗格。

终端独立升级通道复用 HTTP 服务，base64 输入单帧 32 KiB，控制帧 64 KiB，输出缓冲 1 MiB。输入输出分别背压，排空后报告退出；EOF 不是可靠退出码，未知退出码保持 null。

xterm 实例与布局槽位分离，切视图或收起不销毁 PTY；关闭窗格才结束对应 shell，多行粘贴先确认。断线保留输出并停止输入，新连接创建新 shell，不宣称恢复原进程。

### 7.3 资源与 Slurm

旧项目工具保留已有采样配置：默认间隔 5 秒、超时 8 秒；这些兼容参数不再展示在产品设置中。独立 SSH Console 使用共享插件常量：每 2 秒刷新、采样超时 25 秒，与参考插件的默认行为一致。只在面板和页面可见、连接就绪时请求，隐藏立即取消在途采样。命令使用 `/proc`、`df`、`ps` 与 `nvidia-smi` 等只读接口，不安装采集器。

GPU 与 GPU 进程查询各有 3 秒预算；系统进程取前 50 项。缺值为 null，失败保留最近值并标过期。缓存按真实身份共享主机读数，磁盘按目录分开；成功保留 5 秒，失败指数退避不超过 30 秒，空闲 60 秒淘汰。

Slurm 单一路径为 `LC_ALL=C squeue --noheader --user="$(id -un)" --format=...`。总预算 8 秒，合计输出上限 512 KiB，最多 200 行；未安装、空输出、失败分别处理。仅首次或手动查询，不管理作业、不轮询调度器；成功缓存 2 秒，最多 32 项，认证变化取消查询并清理旧缓存。

### 7.4 服务器文件与任务

浏览绑定当前项目和真实 SSH 身份；每项目最多 32 个浏览会话，空闲 15 分钟过期。单层最多 10000 项或 4 MiB 元数据，每页 200 项，目录优先并自然排序。只浏览元数据，不向本机下载文件。

现有写操作生成有效 2 分钟的预检方案，派发前复核目标，以已有 Python 标准库和 `renameat2(RENAME_NOREPLACE)` 执行，不覆盖同名目标、不跟随链接；项目根及祖先受保护。同身份相交路径排队，最多 4 项并行。

任务记录原子落盘后派发；损坏记录保留并阻断，重启不自动重放。派发后断线或取消可能已改变远端，结果不确定用 `needs_check`，读取核对后处理，不能把取消写成回滚。`sync-scope.ts` 仅为当前文件列表过滤，不恢复已删除同步域。

## 8. 工作台插件与独立控制台

插件注册表与自身设置采用 revision 校验。外部静态包复制入工作台目录，安装不执行脚本；启用后只可通过声明权限访问自己的 JSON 设置、当前项目摘要和命令通知。页面校验入口摘要，sandbox 不给予同源、任意网络或 Node 权限；关闭页面与停用/卸载各有独立处理。详细配额和消息边界见工作台插件接口。

SSH Console 只以服务器 alias 定位，不伪造 Workspace。overview、processes 只对当前可见目标请求；只读文件使用 SFTP。后端 PTY registry 保存通道和有界输出，HTTP 读返回 base64 原始字节与 `nextSeq`，前端消费后才推进游标；读取被裁剪的旧区间时明确 reset。隐藏暂停浏览器读取但不结束 shell，重新打开先取终端列表；关闭单终端才释放其通道。

旧项目工具只能从控制台内“项目服务器工具”进入，保留 Slurm、文件写任务与绑定式终端。停用插件会结束控制台及项目工具终端，取消待打开操作并清空旧标签，防止重新启用时由过期标签自动启动新 shell；档案、密文、项目、文件任务和共享连接保留。

xterm 按需加载，复制、粘贴和回滚查找在当前窗格内执行；输出字节直接写入，避免逐块 UTF-8 解码损坏字符。查找依赖 SearchAddon，不向服务器发送命令。插件页面关闭时 SSH 页面保持挂载并暂停观察，外部 iframe 则卸载。

## 9. 本地打包与验证

electron-builder 定义 Windows x64 NSIS 和 portable 目标，默认禁止签名和发布。桌面主进程及业务依赖随包提供，静态前端置于 resources/web；用户 CLI、原生认证及工作台数据不打入程序。包内路径按 `process.resourcesPath` 解析，程序安装位置与配置目录分离。构建和卸载规则详见[本地安装指南](../guides/local-installation.md)。

验证区分模块行为、受控进程、浏览器、包内启动与真实链路。三 CLI 账号与模型、真实 SSH/Slurm、输入法以及安装卸载均需各自证据；安装包生成不代表签名、发布或自动更新完成。阶段结果仅在路线图登记，历史失败不会因文档刷新转为通过。
