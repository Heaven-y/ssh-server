## 核查方法与覆盖

本轮按模块进行文件发现、兼容/迁移/重复入口检索、关键源码和调用方核对、对应测试分析；不是逐行审查所有文件，也不以关键词命中等同缺陷。

| 范围 | 核查结论与整理 |
|---|---|
| Agent/聊天/原生会话 | 双适配器保留；删除缺Agent默认、旧runTurn注入与仅为旧替身存在的可选控制/管理方法；当前官方多类事件、审批和错误处理保留 |
| HTTP/工作区 | 创建和移除仅正式验证/确认路径；删除无人调用且绕过专用事务的通用PATCH；不保留纯store备用CRUD |
| SSH/资源 | 内部目标只用对象；资源采样只用选项对象；私钥/密码、信任校验、取消和共享缓存保留 |
| 同步 | 共用固定版本检查；只读当前combine-v1基线，不提供旧布局确认升级；当前删除/冲突/中断恢复保留 |
| 远端文件任务 | 当前持久字段必填，坏目录/坏记录不能当无任务放行；同/跨FS操作与当前结果恢复不重放保留 |
| 工作区持久配置 | 只有ENOENT空配置；其他读错或坏数据不自动清空、过滤或覆盖 |
| 前端/共享协议 | 清理旧创建封装与隐式Agent参数；创建字段保护移入正式入口；下载只保留选择器流式写入，无能力明确不可用 |
| 配置/本地编辑/版本/策略/远程工具 | 未找到有证据的独立旧版本实现；保留默认值、并发/身份保护、官方API与现行恢复，不作无收益重写 |
| 脚本/依赖/工程工具 | 开发脚本随当前接口更新；固定依赖、质量阈值和双平台CI保留，验收脚本各自验证不同链路，不因名称相似合并 |
| 文档 | README等当前入口与历史记录分离；旧状态、原始验收失败和选型取舍保留供复盘，外部界面检查不再阻塞产品交付 |

详细约束见[本轮设计](../superpowers/specs/2026-10-07-current-implementation-cleanup-design.md)，实施状态见[计划](../superpowers/plans/2026-10-07-current-implementation-cleanup.md)。

## 保留项的理由

- 两类Agent和两种认证是功能选项，不是重复方案。
- Codex官方npm入口/平台程序定位、Claude当前SDK可选数据字段，以及CodeMirror legacy-modes语言高亮仍属于当前依赖的真实接口；不凭名称删除。
- 无数据显示不可用、差异渲染失败保留文本、存储不可用时的内存UI偏好是正常故障处理，不是旧版本兼容。
- 同步初始化与中断恢复、Git恢复和远端任务核对是当前数据保护，不能随旧数据迁移代码删除。
- Linux CI用于检验路径/协议等代码正确性，不据此新增一套Linux产品或平台适配承诺。
