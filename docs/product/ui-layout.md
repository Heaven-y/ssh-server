# 界面布局

更新日期：2026-11-04。产品名 **AgentDeck**（原 `ssh-server`）。本文描述 M1 已交付的界面；能力编号与验收条件以[需求](requirements.md)为准，视觉取舍见[设计决策](../engineering/decisions.md)，文档入口见[索引](../README.md)。

> M1 是运行在本机的网页界面：左栏项目与会话、主区只读历史、右侧服务器面板。**主区没有输入框**，发消息属于 M2；Electron 窗口属于 M1.5。界面里没有同步、版本、本地文件镜像、改动视图与行内反馈，也没有分步向导。

## 0. 视觉规范

### 0.1 形态

- 当前入口是浏览器访问本机后端，开发期指向 Vite 端口；地址栏暂时仍在，M1.5 换成 Electron 窗口后不再需要记端口。
- 界面只保存界面偏好与会话选择；正文从 `~/.claude`、`~/.codex`、`~/.gemini/antigravity-cli` 读出后直接渲染，不写副本。
- 参考 Codex 桌面端、DSH 桌面端的信息架构与 CloudCLI 的项目/会话组织；只借鉴交互，不逐像素对齐，也不复制 CloudCLI（AGPL-3.0）或 Pebrel（GPL-3.0）的代码。
- 不引入看板、多 Agent 编排、内置浏览器或第四段面板。

### 0.2 视觉方向

- 中性灰阶打底、细边框、克制高亮；路径、代码与会话 id 用等宽字体。默认浅色，可切深色，已存偏好优先。
- CLI 归属用字母或色点，不用大色块；状态同时有文字或图标，不只靠颜色。
- 字体：正文 IBM Plex Sans，中文回退系统中文字体；代码与路径 JetBrains Mono；字体本地打包。
- 图标用 Lucide；动效只保留 150–250ms 的细微过渡，并遵守 `prefers-reduced-motion`。

双主题共用一套语义变量，深色主题的关键值如下（浅色主题由 `styles.css` 的另一组变量覆盖）：

| 语义 | 深色值 | 用途 |
|---|---|---|
| background / card | `#101114` / `#18191E` | 页面与面板底色 |
| muted / muted-foreground | `#282A32` / `#A2A6B3` | 次要背景与文字 |
| foreground / border | `#EEEFF3` / `#30323B` | 主文字与分隔线 |
| border-strong | `#747A89` | 输入框与可交互边界 |
| accent | `#9CB5FF` | 主操作与焦点 |
| success / warning / destructive | `#81CBA4` / `#F0C77F` / `#E66F7A` | 状态，不与主操作混用 |

## 1. 主界面：三段式

```text
┌──────────────────────────────────────────────────────────────┐
│ AgentDeck · 项目名     [搜索与操作]     终端 服务器 主题 设置  │
├──────────────┬───────────────────────────────┬───────────────┤
│ 项目          │ 会话标题 · Claude · ~/proj     │ 服务器面板     │
│  ▸ 项目 A     │                               │  终端 / 资源   │
│    Claude 3   │  …只读历史时间线…              │  文件          │
│    Codex 2    │                               │               │
│    Anti 1     │  （没有输入框）                │               │
│  ▸ 项目 B     │                               │               │
└──────────────┴───────────────────────────────┴───────────────┘
```

- 左栏：项目树与按 CLI 分组的会话（第 3 节）。
- 主区：会话头与只读历史（第 4 节）；没有输入区。
- 右侧：服务器面板，终端 / 资源 / 文件三个视图共用一条宽度，可收起（第 5 节）。

### 1.1 断点与尺寸

- 最小宽度 960px；断点取 1280px。整页不出现横向溢出（A14）。
- 左栏默认 240px，可调 200–320px；小于 1280px 时默认自动收起，用户仍可手动展开。
- 主区常规最小 480px；窄窗且用户主动展开左栏时允许压到 320px，此时右侧面板让位。
- 右侧面板默认 420px，可调 360–720px；收起时不占宽度。面板只有一条宽度，三个视图不并排。
- ≥1280px 首屏默认展开右侧面板；窄窗不强开。左栏与右侧面板的宽度、展开状态分别记忆，越界值回落到默认值。

### 1.2 停靠与收起

- 终端、资源、文件是同一停靠区的三个互斥视图；Slurm 查询位于资源视图内，不单独占标签。
- 切换视图与收起面板不重建已挂载的内容：已开的 PTY 不释放，已打开的浏览路径不丢失。
- 终端与文件在第一次打开时才挂载；未打开前显示入口说明，不预建连接。
- 切换项目会按新项目的绑定重建资源与文件视图（它们以项目与绑定目录为键），终端标签作为独立会话保留，不因切项目被关闭。M3 把面板改成以服务器档案为身份后，这条限制才会解除。
- 分隔线支持鼠标与键盘调节；隐藏的分隔线不可聚焦。标题栏的「复位」只恢复面板宽度，不改主题与左栏宽度。

## 2. 顶栏与命令面板

### 2.1 顶栏

顶栏只保留：侧栏开关、品牌、当前项目、搜索与操作、终端、服务器、主题、设置。没有同步摘要、版本横条、改动数量或下载入口。

| 元素 | 说明 |
|---|---|
| 当前项目 | 显示项目名与目录；空间不足时名称省略，目录与连接状态保持可用 |
| 搜索与操作 | 打开 `Ctrl+K` 命令面板 |
| 终端 | 展开右侧面板并切到终端视图 |
| 服务器 | 打开服务器档案管理，与设置页内的入口是同一界面 |
| 主题 | 浅色 / 深色切换，记住选择；默认浅色 |
| 设置 | 打开设置页（第 6 节） |

- 本机服务连接正常时不占位置；WebSocket 断开时显示「本机服务已断开」与重连按钮。
- 项目绑定服务器且已连接时，顶栏显示该服务器的连接状态；未绑定时不显示伪造的连接状态。

### 2.2 命令面板

`Ctrl+K` 与顶栏「搜索与操作」是同一入口。命令清单按 M1 范围重列：

| 命令 | 说明 |
|---|---|
| 新会话 | 清空当前会话选择并回到未选中状态；M1 没有输入框，因此不会真的开启一轮对话 |
| 打开终端 | 展开右侧面板的终端视图 |
| 查看资源详情 | 展开资源视图 |
| 打开设置 | 第 6 节 |
| 切换浅色 / 深色主题 | 与顶栏主题按钮等价 |
| 折叠 / 展开侧栏 | 与顶栏侧栏按钮等价 |
| 切换项目 | 列出全部项目 |
| 搜索会话 | 列出当前项目的 Claude 与 Codex 会话；Antigravity 不在面板里，从左栏进入 |

上下键移动高亮，Enter 执行，Esc 收起并恢复焦点；输入法组字期间不执行。同步、版本、本地文件相关命令已删除，不保留灰项。

## 3. 左栏：项目与会话

### 3.1 项目

- 项目行显示名称、会话数量与目录；目录用等宽小字，长路径截断但保留完整提示。当前项目高亮。
- 「添加项目目录」打开一个对话框：填本机绝对路径（名称留空时取目录末段），提交后由后端校验目录存在并加入。没有分步向导，也没有服务器目录选择、同步规则或绑定票据；失败在原处说明并保留输入。
- 没有项目时显示空态与「添加项目目录」按钮；不渲染伪造的会话骨架。
- M1 只有「添加项目」这一个写入口：改名、移除与服务器绑定表单都还没接入，所以界面新建的项目一律不带服务器绑定。已绑定的项目来自迁移过来的旧配置，或直接编辑 `workspaces.json`；接口本身支持改名、改目录、绑定与移除（F1）。

### 3.2 会话列表

- 项目展开后按 Claude / Codex / Antigravity 分组；组标题显示字母徽标、名称与本组数量。没有会话的 CLI 不显示空组。
- 行内是单行标题与相对时间；标题缺失时写「未命名会话」。运行中的行会显示旋转图标；M1 不能发消息，所以实际不会出现运行中的行。
- 组内按最近活动时间倒序，不做置顶；完整时间放在悬停提示里。
- 归属规则与无归属会话的行为见 F2；解析不出项目的会话默认不进列表。
- 左栏底部有「显示其他目录的会话」开关。打开后，无归属会话集中显示在「其他目录」区，可点「加为项目」；它们不会混进已有项目。
- 加载中显示「正在读取会话…」；某个 CLI 读取失败只影响该组，不阻塞整个侧栏。

### 3.3 会话选择与操作

- 点击会话行即选中并在主区读取历史；切换会话会取消上一次读取。
- 行内「更多」菜单在 M1 只提供重命名入口，其余会话管理动作（删除、归档、分叉）留给 M2 与后续任务，不在 M1 验收。
- 运行状态只表达「本应用正在驱动该会话」；不声称外部进程已被锁定。M1 没有回合，这条状态栏在会话头与左栏都保持空闲。

## 4. 主区：会话历史

### 4.1 会话头

- 显示 CLI 徽标、标题、探测到的版本、项目目录与运行状态。
- 版本来自本机探测；M1 没有真实回合，因此它是「本机装的那份 CLI 的版本」，不宣称与某一轮实际驱动完全一致。Claude 的对话由 SDK 平台包内的程序驱动，探测读的是 PATH 上的 `claude`，两处版本可能不同；M2 接对话前要把这两处的来源对齐。
- 探测为「接口变化」「未安装」「凭据未配置」时，会话头给出与设置页一致的原因，不静默换版本。
- 会话固定属于创建它的 CLI，不提供切换 CLI 的入口。

### 4.2 时间线

- 历史事件来自原生记录：用户消息、助手文本、工具调用与工具结果；Markdown 与代码块按只读方式渲染。
- 工具卡片显示工具名、关键参数、状态与结果；结果默认折叠，长输出可展开。只显示原生事件给出的路径与动作，不生成 diff。
- M1 的时间线是普通滚动容器，一次渲染全部行，没有虚拟列表、贴底跟随或「回到底部」按钮——这些属于 M2 的实时对话。历史很长时性能未做优化，属于已知限制。
- 底部常驻一行说明：「只读浏览原生会话记录；M2 接入对话后可以在这里继续发送消息。」
- 界面不出现「本轮改动」聚合卡片、行内反馈、待发送评论或单文件放弃入口（F3.3）。

### 4.3 状态

- 未选中会话：主区显示「选择一条会话查看历史」，不画空对话框。
- 加载中：显示读取状态与取消语义；切换会话后旧结果不覆盖新选择。
- 空历史：说明原生存储里没有可显示的消息，不伪造内容。
- 读取失败：在原位置给出原因与「重新读取」；不整页遮罩。
- 不可回放：Antigravity 会话显示私有轨迹说明，标题、时间与归属照常保留（A9）。

## 5. 右侧服务器面板

### 5.1 身份与目标

- M1 的面板以**已绑定服务器的项目**为入口：项目同时有 `server` 与 `remoteDir` 才能新建终端标签，资源与文件视图也才有数据。界面没有绑定表单，所以能用的只是迁移过来的已绑定项目。
- 未绑定时面板本身仍可打开：终端视图提示「当前项目没有绑定服务器」且「新建标签」不可用；资源与文件视图显示同样的绑定提示，不显示可点击的假连接。
- 切换项目会把面板目标切到新项目的绑定：资源与文件视图按新目标重建，终端标签保留（每个标签绑定创建时的服务器）。同一停靠区同时开多台服务器属于 M3。
- 服务器档案管理从顶栏「服务器」或设置页进入，支持密码与私钥、主机指纹确认与 Windows 加密保存。

### 5.2 终端

- 多标签与分屏 SSH 终端：新建、左右/上下分屏、关闭、最大化、收起。每个标签绑定打开时的服务器与起始目录。
- 收起、切标签、切项目不释放 PTY；关闭窗格才断开该 shell。
- 断线后停用输入并保留已显示内容；「新建连接」明确创建新 shell，不承诺恢复原进程。
- 复制、粘贴、输入法与 PTY 尺寸按实际程序验证；多行粘贴先确认。

### 5.3 资源与 Slurm

- 资源卡显示 GPU、CPU、内存、磁盘与负载；缺失值留空，不补零。失败时保留最近一次读数并标过期。
- 默认 5 秒采样，可在设置里改为 2–60 秒；单次超时 2–30 秒，默认 8 秒。只在视图可见且连接就绪时采样，隐藏即停表并取消在途请求。
- Slurm 查询位于资源视图底部，只在首次激活与点「刷新」时读取；不自动轮询、不提交或取消作业。
- 结果按固定文本表格展示，超长输出截断并说明；空输出、未安装与查询失败各有独立文案。

### 5.4 文件

- 只展示服务器文件，没有本地镜像或本地代码子视图。顶部显示主机与当前绝对路径。
- 目录按需展开、分页读取；文件与目录行只显示名称与大小，目录体积在点击后计算。
- 操作：新建目录、重命名、移动、复制、删除；全部在服务器上执行，内容不经本机中转。
- 操作先预检再确认，同名目标默认拒绝；删除使用带明确动词的确认区，写明主机、路径与影响范围。
- 下载入口目前仍在（F6.3），移除完成前不把它写成已删除能力。

## 6. 设置

- 设置分三个分类：对话与模型、服务器资源、运行环境；分类只切换可见内容，草稿与统一保存由外层持有，切换分类不丢值。
- 对话与模型：只放「新会话默认值」里的默认 Agent；它是产品偏好，不写回任何 CLI 的原生配置。
- 服务器资源：资源检查间隔（2–60 秒）与单次超时（2–30 秒）；页面隐藏时暂停采样。
- 运行环境：三个 CLI 的探测状态、版本与重新检测入口，与顶栏探测同源。
- 原生配置编辑目前在界面上只覆盖 Claude `settings.json` 与 Codex `config.toml` 的局部能力，完整文件清单、项目级配置与 Antigravity 配置属于 M3，不在 M1 验收；界面不宣称已覆盖全部原生配置。
- 启动环境注入尚未交付（M3）；M1 不显示可编辑的变量列表，也不暗示已经注入。
- 服务器档案管理从顶栏进入，与设置页入口共用同一界面；保存与连接是两个独立动作，不自动认证。

## 7. 状态与反馈

- 正常状态安静：探测与读取不弹提示、不占常驻位置。
- 空态用短句并给出下一步；CLI 不可用时写原因与可执行文件路径覆盖入口。
- 读取显示进度；切换项目或会话时自动取消旧请求，迟到结果不覆盖当前选择。
- 本机服务断开时顶栏提示并允许重连；重连后重新读取当前项目与会话，不自动发消息。
- M1 可达的危险操作只有删除服务器文件：先预检再确认，写明主机、路径与影响范围。删除会话、移除项目、覆盖保存的确认流程在组件与接口里已有，但 M1 界面没有入口，不在本轮验收。
- 错误在原位置说明；密码失效、资源过期、文件任务结果不确定各有独立状态，不用一个通用错误覆盖。

## 8. 可访问性

- 项目树、会话列表、命令面板、面板标签与分隔线都可用键盘到达；焦点可见，收起的分隔线不可聚焦。
- 停靠区不是焦点陷阱；只有确认对话框限制焦点，关闭后回到触发元素。
- 状态不只靠颜色：CLI 徽标带字母，运行状态带文字，资源过期与失败带说明。
- 图标按钮有可访问名称；只读历史目前没有流式播报区（`aria-live` 只存在于尚未挂载的对话时间线），M2 接输入时要补上，资源数值的频繁刷新也不逐条播报。
- 输入法组字期间不触发命令面板或列表快捷键；`Ctrl+K` 与终端内部快捷键保留各自语义。
- 文字与背景对比度满足 WCAG AA，遵守 `prefers-reduced-motion`；完整无障碍仍需人工用辅助技术验证。
