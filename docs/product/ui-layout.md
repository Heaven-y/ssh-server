# 界面布局

更新日期：2026-11-03。产品名 **AgentDeck**（原 `ssh-server`）。本文描述当前产品的界面结构与呈现规则；功能编号 F1–F8、验收 A1–A29 以[需求](requirements.md)为准，信息架构与设计取舍见[设计文档](../superpowers/specs/2026-11-03-native-cli-workbench-design.md)，文档入口见[索引](../README.md)。

> 产品形态是 Windows 桌面应用（Electron 壳），界面只有三段：项目与会话、对话、服务器面板。这里**没有同步、没有版本、没有本地文件镜像、没有改动视图、没有行内反馈、没有服务器文件下载**，也没有分步向导；会话正文只来自三个 CLI 自己的存储。

## 0. 视觉规范

### 0.1 形态与参考

- 产品是一个 Windows 桌面应用：双击打开窗口，**没有浏览器地址栏、没有标签页、不用记端口**。窗口关闭后后端进程随之退出，单实例运行（A1）。后端仍只监听回环地址；用浏览器打开同一地址只是调试手段，不是产品入口。
- 界面只保存界面偏好与会话簿记（原生 id、所属 CLI、标题、时间、归属目录），**不存对话正文**。正文在 `~/.claude`、`~/.codex`、`~/.gemini/antigravity-cli` 里，本产品只负责读出来画在屏幕上。
- 参考 Codex 桌面端与 DSH 桌面端的信息架构（项目 → 会话 → 对话），CloudCLI 的项目与会话组织，[Pebrel](https://github.com/Kuddev/pebrel) 的紧凑终端标签与分屏。只借鉴交互与布局，配色自定，不逐像素对齐参考截图。
- 不引入看板、多 Agent 编排、内置浏览器、双会话分屏或营销页结构；不复制 CloudCLI（AGPL-3.0）或 Pebrel（GPL-3.0）的代码。许可与依赖规则见[开发指南](../guides/dev-environment.md#11-代码规范)。

### 0.2 视觉方向

沿用 DSH 桌面端那种语气：中性灰阶打底、细边框、克制的高亮、等宽字体用于路径与代码、紧凑但留白的密度、**深浅双主题默认跟随系统**。CLI 归属用一个字母或色点区分，不用大色块，避免界面变成调色板。

风格采用极简（Minimalism & Swiss）：高对比、网格对齐、少装饰；信息密度高（间距 8–32px）。

颜色使用双主题语义变量，下方为深色主题配色与对比度测量（浅色主题的验收数值另行记录）。深色正文、辅助文字和状态色对 background/card/muted 的最小对比度分别为 12.45、5.89、7.50 以上，可交互边界 border-strong 最小 3.33:1：

| 语义 | 值 | 用途 |
|---|---|---|
| background | `#101114` | 页面背景 |
| card | `#18191E` | 卡片、面板 |
| muted / muted-foreground | `#282A32` / `#A2A6B3` | 次要背景与文字 |
| foreground | `#EEEFF3` | 主要文字 |
| border | `#30323B` | 装饰性分隔线 |
| border-strong | `#747A89` | 输入框、按钮等可交互边界 |
| accent / accent-foreground | `#9CB5FF` / `#152044` | 主操作与焦点；按钮文字对比度 7.92:1 |
| success / warning | `#81CBA4` / `#F0C77F` | 成功 / 待确认，不与主要操作混用 |
| destructive | `#E66F7A` | 危险操作与错误边界 |
| destructive-foreground | `#FFB0B8` | 错误文字 |

- 字体：正文 IBM Plex Sans，中文明确回退到系统中文字体；代码 / 终端 / 路径 JetBrains Mono。字体本地打包，不从 Google Fonts 加载。对话正文 15px，行高 28px。
- 图标：Lucide（SVG），不用 emoji 当图标。
- 动效：只用细微过渡（150–250ms），遵守 `prefers-reduced-motion`。
- 状态不只用颜色：CLI 徽标的字母、运行状态的字样与图标始终同时存在（见第 8 节）。

## 1. 主界面：三段式

```text
┌──────────────────────────────────────────────────────────────┐
│ 工作台 · 项目名      [搜索与操作]     终端 服务器 主题 设置    │
├──────────────┬───────────────────────────────┬───────────────┤
│ 项目          │ 会话标题 · Claude · ~/proj     │ 服务器面板     │
│  ▸ 项目 A     │                               │  终端 / 资源   │
│    Claude 3   │  …对话正文与工具卡片…          │  文件 / Slurm  │
│    Codex 2    │                               │               │
│    Anti 1     │ ╭ 输入框 + 模型/强度 发送 ╮    │               │
│  ▸ 项目 B     │                               │               │
└──────────────┴───────────────────────────────┴───────────────┘
```

- 左栏：项目列表，展开后按 CLI 分组列会话（第 3 节）。
- 中间：对话区，会话头、正文时间线、输入区（第 4 节）。
- 右侧：服务器面板，终端 / 资源 / 文件 / Slurm 四个视图共用停靠区，可收起（第 5 节）。
- **对话区没有改动视图**：没有「本轮改动」聚合卡片、没有 diff 渲染、没有行内反馈（F8.3）。这是设计要求里明写的一条，不是尚未实现的缺口。

### 1.1 断点与尺寸

- 最小支持宽度 960px；断点取 960 / 1280 / 1600，整页不出现横向溢出（A29）。
- 左栏（项目 + 会话）：默认 240px，可调 200–320px。
- 对话区：常规最小 480px；窗口较窄且用户主动展开左栏时允许压到 320px，此时右侧面板必须收起，避免三段互相挤压。
- 右侧服务器面板：默认 420px，可调 360–720px；收起时不占宽度。四个视图是同一停靠区里的互斥标签，不并排显示，面板只有一条宽度。
- ≥1280px：三段并排，右侧面板默认展开，各段宽度按记忆恢复、对话区占用余量；不新增第四列（1600px 与 1920px 同样如此）。
- 960–1279px：左栏可自动收起；右侧面板首屏不强开，按需展开；主动展开不变成模态、不锁住对话焦点。
- 左栏宽度、右侧面板宽度与展开状态分别记忆，都有上下界；窗口变窄只压缩可用空间，不改写用户记住的偏好。

### 1.2 停靠与收起

- 终端、资源、文件、Slurm 是同一停靠区的四个视图，互斥切换，不叠盖、不自由拖动；标题保留「复位」与「收起」。
- 收起、切换视图、切换项目都不重建内容父子树：不释放已开的 PTY，不丢弃资源采样快照，不丢失已打开的文件路径。
- 分隔线支持鼠标与键盘调节；隐藏的分隔线不可聚焦。收起只隐藏，真正断开连接另有明确入口（关闭终端窗格、断开档案）。
- 「复位」只恢复面板尺寸与位置，不改主题与左栏宽度。

## 2. 顶栏

顶栏只保留：当前项目、搜索与操作、终端、服务器、主题、设置。没有资源横条，没有同步与版本摘要，没有地址栏与页面标签。

| 元素 | 说明 |
|---|---|
| 项目 | 显示当前项目名与目录；通过左栏或命令面板切换。空间不足时名称省略，状态与按钮保持可用 |
| 搜索与操作 | 打开命令面板，与 `Ctrl+K` 同一入口，不与对话输入区的「+」或 `/` 能力混用 |
| 终端 | 右侧面板「终端」视图的快捷入口；面板收起时点它展开并切到终端视图，不是独立的按项目终端 |
| 服务器 | 打开服务器档案管理（与设置页内的入口是同一个界面） |
| 主题 | 浅色 / 深色 / 跟随系统，带文字与可访问名称，记住选择；默认跟随系统 |
| 设置 | 打开设置页（第 6 节） |

- 本机服务连接正常时静默，不占常驻位置；连接中断时在顶栏显示简短状态与「重新加载界面」，重新加载后按会话重新挂载继续收流，不自动发起新回合。
- 顶栏不出现同步状态、版本摘要、改动数量或任何下载入口。

### 2.1 命令面板

`Ctrl+K` 打开，与顶栏「搜索与操作」是同一个面板。命令清单按本产品范围重列，不保留任何同步、版本、本地文件相关命令。

| 命令 | 说明 |
|---|---|
| 新建会话 | 选 CLI 与项目 |
| 切换项目 | 列出全部项目 |
| 切换会话 | 当前项目的会话 |
| 打开终端 | 打开右侧服务器面板的终端视图，等价于顶栏「终端」 |
| 打开资源 / 打开文件 | 打开右侧面板对应视图 |
| 服务器 | 打开服务器档案管理 |
| 刷新会话列表 | 手动触发，替代目录监听失效时的兜底 |
| 刷新能力 | 触发能力目录读取（会启动 CLI 检查，面板内明示） |
| 设置 | 打开设置，含原生配置与启动环境 |
| 切换主题 | 浅色 / 深色 / 跟随系统 |

键盘上下移动高亮、Enter 执行、Esc 收起并恢复焦点；输入法组字期间不触发执行。项目与会话名同样可按名称搜索。

## 3. 左栏：项目与会话

### 3.1 项目

- 一个项目就是一条本地绝对路径，必填且必须真实存在（F1.1）。当前项目高亮。
- 「添加项目目录」是**一个动作**：选一个本地目录（系统目录对话框，或直接输入绝对路径），校验存在即加入。没有分步向导，也没有双端目录浏览、服务器目录选择、同步规则预览、验证票与绑定票据。
- 项目行提供重命名与移除。移除只删本工具的配置，不动磁盘上的任何文件、不动 CLI 的原生会话；确认框写明这一点（F1.3）。
- 项目可选择性绑定一台服务器档案与默认远端目录（F1.2）。绑定只决定服务器面板的默认目标与默认目录；不绑定也能正常对话、也能用服务器面板。
- 项目列表与服务器档案分开存储、分开展示，互不牵连；切换项目不打断已开的终端、资源采样与文件浏览（F1.4）。
- 改名前的旧数据（`servers.json`、`workspaces.json`）在首次启动时由后端一次性迁移，只取仍成立的字段；界面不提供迁移向导，也不就同步相关字段做任何提示（F1.5、A27）。
- 没有项目时显示空态：一句引导 +「添加项目目录」按钮，不显示伪造成骨架的会话区（F8.5）。

### 3.2 会话列表（按 CLI 分组）

左栏顶部固定「新建会话」：先选 CLI 与项目，选完即进入对话；这是唯一可以选 CLI 的地方（F3.1）。

- 项目展开后按 CLI 分组：Claude / Codex / Antigravity，组标题用 CLI 徽标（字母或色点）与名称。三条来源分别枚举本机真实存在的会话，不导入、不复制、不另存，单条失败只影响该组（F2.1）。
- 组内置顶优先，其余按最近活动时间倒序；行内单行标题 + 相对更新时间，完整时间在提示中；标题为空或缺失时显示明确占位文案，不显示空白行（F2.4）。
- 行内显示运行状态（仅表达「本应用正在驱动该会话」）与置顶图标；不显示模型名，也不用「模型未报告」这类占位。
- 归属由会话的原生 `cwd` 判定，与项目目录规范化后比较，不按目录名字符串猜；一个会话只属于一个项目、一个 CLI（F2.2）。
- 每个项目内有「显示其他目录的会话」开关（F2.3）：打开后列出该 CLI 存储中 `cwd` 不属于任何已配置项目的全部会话，按规范化绝对路径分组，分组标题可一键「加为项目」。范围是「不属于任何项目的全部会话」，不是只显示子目录，也不是全机扫描。Antigravity 解析不出归属的会话归入「其他目录」分组（F2.5）。
- 列表实时性：监听各 CLI 的存储目录，500ms 去抖后合并成一次刷新；监听失败退回手动「刷新会话列表」，不弹警告。

### 3.3 会话操作

「更多」菜单按 CLI 的实际能力提供动作。运行中的会话不允许管理（F3.6），这些动作此时给出原因，而不是静默变灰。

| 动作 | 行为 |
|---|---|
| 重命名 | 走 CLI 官方接口，成功后刷新该组；失败保留原标题并说明原因 |
| 置顶 / 取消置顶 | 存进界面偏好，按 项目 + CLI + 原生 id 隔离 |
| 分叉会话 | 从原生末尾创建独立会话；确认框说明保留范围，源会话不变 |
| 删除 | 二次确认，写明会删掉原生记录（含其子会话）；等待期间禁用重复提交与关闭 |
| 归档（Codex） | 仅在该 CLI 提供时出现；归档后可恢复，恢复才能继续或改名，不隐式恢复 |

- 分叉成功只在「用户没有切换选择且当前空闲」时打开新会话；迟到结果不覆盖当前选择，请求未确认时提示先刷新列表核对，不自动重试。
- 时间线里可信的已结束位置另提供「从此处分叉」，分叉点只接受服务端给出的位置，界面不补造（F3.5）。

## 4. 对话区

### 4.1 会话头

显示 CLI、实际驱动的版本、模型、`cwd`、运行状态。危险开关打开时常驻红色标记（F3.4）。会话固定属于创建它的 CLI，不提供切换 CLI 的入口（F3.1）。

- 版本号必须是本机实际驱动的那个版本：界面显示的版本与实际用的二进制对不上，比不显示更糟。
- 运行状态只表达一件事：**本应用正在驱动该会话**。不用「已锁定」暗示外部已被阻止——外部进程（终端里的 CLI、Codex 桌面端）是否也在驱动同一会话无法可靠探测；把同时驱动的风险写在提示里即可（F3.8）。
- 探测结果是「接口变化」「未安装」「凭据未配置」时，会话头给出与设置页一致的原因，并指向可执行文件路径覆盖入口，不静默换版本。

### 4.2 正文时间线

- 用户消息、助手文本（Markdown，代码高亮）、思考摘要（默认折叠）。历史正文直接来自 CLI 的原生存储：Claude 与 Codex 完整可读，Antigravity 见 4.5。
- 工具调用卡片：工具名、关键参数、状态、结果（默认折叠，长输出可展开）。连续至少两项明确的读取/搜索类工具合并成「读取/搜索了 N 项」，始终显示完成、失败、运行、未返回计数，内部保留每项原结果；不根据 shell 命令猜只读。
- 审批卡片（Claude / Codex）与软拒提示卡（Antigravity）见 4.3。
- 原生已结束的分叉边界：只由服务端可信位置产生，提供「从此处分叉」，未报告位置不补造按钮。
- 长对话使用动态高度虚拟列表；贴底时跟随流式增长，用户上翻时停止并显示「回到底部」；工具/思考/分组的展开状态在虚拟卸载后保留；切换或重开会话清空视图选择。
- **没有 diff 渲染，也没有行内反馈。** 工具卡片照常显示原生工具事件里的「写入 / 编辑了哪个文件」，点开只看路径，不是差异视图；界面上不存在「本轮改动」聚合卡片、行号评论框、待发送反馈或单文件放弃这类入口（A28）。
- 同一会话同时只允许一个回合；回合进行中再次发送被拒绝并说明原因，其他会话不受影响（F3.7、A10）。
- 回合按会话持有而不是按连接持有：事件在服务端内存里按会话缓冲，窗口重新加载后重新挂载到该会话继续收流；缓冲不落盘，进程退出即丢。

### 4.3 审批、权限模式与软拒

三种权限模型按 CLI 的真实行为分开画，不强行统一（F3.3）。

**Claude / Codex：回合内审批**

- 「哪些工具会问」由 CLI 自己的原生配置决定（`~/.claude/settings.json` 的 `permissions`、`~/.codex/config.toml` 的 approval/sandbox 策略），本应用只把 CLI 决定要问的弹出来，不加自己的放行规则。
- 批准 / 拒绝后显示等待后端确认并禁用重复操作；处理完成、超时、中断或原生取消后关闭审批入口，不重复答复（A8）。
- 「始终允许」是一次显式操作，写进原生配置文件并先确认；它不变成界面内存里的临时规则。

**Antigravity：权限模式条 + 软拒**

- 不画审批卡片，改在输入区上方**常驻权限模式条**：显示当前 `--mode`（accept-edits / auto / plan 等）与 `--dangerously-skip-permissions` 是否开启。
- 被拒的工具会被静默跳过，通知只从 `stderr` 出来，进程仍以 0 退出。**`stderr` 的软拒说明是一等界面信息**：解析成提示卡，写明哪个工具被拒、怎么放行，并给「去改 `permissions.allow`」入口（A9）。否则用户会看到「任务完成」，而命令根本没执行。
- `--dangerously-skip-permissions` 要显式勾选、按会话记忆，会话头常驻红色标记，默认关闭。

### 4.4 输入区与会话级设置

- 正文 Enter 发送，Shift+Enter 换行；运行时发送按钮切换为「停止」，停止后等待原生确认，无响应时 5 秒强停；空输入、加载中、不可用时保持对应的禁用状态。
- 输入区上方：Antigravity 的权限模式条常驻；另外两个 CLI 没有这一条。
- 输入底栏：左「+」打开「技能与命令」，与 `/` 补全共用同一份可执行过滤（需要会话前置条件的命令照常显示条件），选中后显示可移除的标签；右侧是模型、强度与发送/停止。控制行在窄空间允许换行，不出现附件入口。
- `/` 补全只使用当前 CLI 的实际能力目录：消息开头输入 `/` 展开候选，上下方向键移动高亮，Enter 只确认选择、再次 Enter 才发送，Esc 收起并保留原文；输入法组字期间不触发选择或发送；只补全首个命令名，路径、正文与参数区保持普通编辑；候选最多显示 20 项。
- 能力目录**只在用户点「刷新能力」时读取**，按钮旁写明「会启动 CLI 检查账号与模型清单」；「打开新建会话」不算授权。没有缓存时显示自由文本输入，没有斜杠补全与模型下拉；失败降级为「能力未知」，输入框照常可用，不重试、不阻塞（A25）。
- 会话级设置分两类（F3.4）：

| 类别 | 可调项 | 作用范围 |
|---|---|---|
| 原生参数 | Claude：模型、强度、权限模式。Codex：模型、审批策略。Antigravity：模型、强度、代理、模式与项目 | 只影响本次运行，不写回原生配置；下次打开会话按原生默认值重新开始 |
| 危险开关 | Antigravity 的 `--dangerously-skip-permissions` | 按会话记忆在界面偏好里（不含密钥），会话头常驻红色标记，默认关闭 |

- 要让原生参数长期生效，走 6.2 的原生配置编辑器，不在会话里偷偷写文件。
- 模型与强度按 CLI 独立保留；没有显式选择时沿用原生默认值，不猜一个写进配置。选择菜单支持 Enter 确认、Esc 收起与焦点恢复，手填模型名时 Enter 不发送正文。

### 4.5 空态与不可读

- 没有会话时显示空态：「新建会话」按钮 + 一句说明。新建会话先选 CLI 与项目，选完即固定归属。
- 没有项目时对话区保持空白并说明先去左栏添加项目，不渲染假的会话骨架。
- Antigravity 的历史轨迹读不出时，标题、时间、归属照常显示，正文区写明「此会话的历史记录由 Antigravity 保存在本机，当前无法读取；可以继续对话」——不假装空白，也不编造内容（A4）。界面发起的回合在本次进程存活期间可回看，重启后同样落到这句话。
- CLI 未安装、接口变化或凭据未配置时，该 CLI 标记为不可用并说明缺什么、缺哪一项，同时给「可执行文件路径」覆盖入口；另外两个 CLI 照常工作（A26）。

## 5. 右侧服务器面板

服务器面板是独立工具，不与对话耦合：不向 CLI 注入服务器操作工具，不需要同步，也不因为切项目而换目标（F6.2）。

### 5.1 身份与目标

- 面板以**服务器档案**为身份，不以项目为身份。不绑定项目的服务器也能直接用；同一停靠区可同时打开多台服务器，以主机别名区分。
- 项目只提供默认服务器与默认远端目录；切换项目不打断已开的终端、文件浏览与资源采样（A20）。
- 未绑定项目时，文件浏览与资源采样的默认目录是登录用户的 home（`~`），不是根目录，也不是上次某个项目的目录（F6.3、A19）。
- 四个视图共用停靠区与目标；切换视图不重建连接，也不重复查询已有快照。

### 5.2 终端

- 多标签与分屏 SSH 终端：新建、左右/上下分屏、关闭、最大化、收起。首版每标签最多 4 个窗格，空间不足时只显示活动窗格，其他连接保持。
- 每个标签绑定打开时的服务器档案，窗格固定显示 Host 与「起始目录」；该路径是标签的起始位置，不随 shell 内 `cd` 变化。新增分屏沿用原标签目标，另一台服务器由明确入口新建标签。
- 收起、切标签、切项目、调停靠尺寸都保留 PTY；关闭窗格才断开该 shell，确认后执行。
- 断线立即停用输入并保留已显示内容；「新建连接」明确创建新 shell，不重发旧输入，也不承诺恢复原进程。
- 顶栏「终端」只是这个视图的快捷入口，不另开一套按项目的终端；终端只在右侧面板里，不占对话区底部。
- 复制、粘贴、输入法与 PTY 尺寸同步以实际程序验证；多行粘贴先预览确认。用户手动 shell 不受任何命令限制，不调用模型。

### 5.3 资源与 Slurm

- 资源：友好目标、逐卡 GPU（利用率、显存已用 / 总量，可用的温度与功耗）、CPU（两次采样）、内存、磁盘、负载；缺失值留空，不补零。
- 默认 5 秒采样一次，可在设置里调：采样间隔 2–60 秒，单次超时默认 8 秒、范围 2–30 秒；过期阈值取 15 秒与 3 倍间隔的较大值。
- 只在视图可见时采样：视图隐藏、窗口最小化或连接中断时暂停并取消在途请求，恢复后仍只有一个控制器。失败保留最近一次结果并标过期，更新时间、不可用与暂停状态都附文字说明。
- 高利用率不自动告警；资源卡用独立蓝/青与少量紫色，橙红只用于警告与错误。
- Slurm：只在首次激活与点「刷新作业」时读取；重新展开已有快照不再自动查，与资源的时间、错误互相独立。
- 唯一查询是当前 SSH 账号的固定格式 `squeue` 文本；后端 8 秒超时、512 KiB 合计输出上限，最多展示 200 行。非空输出补匹配列宽的英文表头，等宽纯文本区最大高 480px、内部双向滚动；超字节拒绝整份，超行准确标「仅显示前 200 行」。
- 空态分三种：无警告的空输出是「暂无作业」；成功但有警告保留警告，空输出是「本次查询没有返回内容」；不可用与失败仍可操作。
- 不自动轮询作业、不查全用户、不遍历节点、不展示节点进程表，也不提交或取消作业、不安装环境、不发训练完成通知。列出的是该账号可见的作业，含他人任务。
- 资源与作业绑定固定服务器与真实连接；档案或认证变化后清掉旧快照并要求手动刷新，迟到结果不串到其他目标（F6.7）；不需要先开 `nvitop`。

### 5.4 文件

服务器文件视图只有服务器文件一个来源：没有本地代码子视图、没有只读本地镜像、没有改动对比、没有同步范围标记。

```text
文件 · my-server · ~/projects/demo            [复位] [收起]
[终端] [资源] [文件] [Slurm]
~/projects/demo                                   [刷新]
名称（文件夹优先）                    [新建文件夹] [?]
run1/                                                …
weights.bin                            100 GB        …
右键或 Shift+F10：重命名、移动、复制、删除、属性
```

- 明确显示 Host 与实际绝对路径；长路径在区内换行或滚动，不撑宽整页；宽窄窗口共用同一内容子树。
- 目录展开按需取下一层、分批显示；提供返回上级、返回目标根目录与输入路径；离开默认目录时标注「目标外」。当前层按文件夹优先、名称自然排序；每页 200 项，超过 10000 项或 4 MiB 元数据时拒绝不完整列表并提示进入具体子目录。
- 文件与目录行只紧凑显示名称与大小，大小与目录体积区分，后者仅点击后计算；选择不自动展开属性。
- 操作：**新建目录、重命名、移动、复制、删除**，全部在服务器上执行，内容不经本机中转。这套操作与现有 ssh console 保持一致，也是本视图操作的全集（F6.4、A21）。
- **没有下载。** 界面里不存在下载入口、下载菜单项、保存对话框、下载任务与进度；服务器文件下载已从产品中移除，是本面板相对现有 ssh console 唯一的能力收缩。选中文件不产生本机副本，也不进入任何「本机中转」流程。
- 拖入目录表示同一服务器内移动，突出目标并在提交前展示源/目标路径；「移动到…」「复制到…」复用目录选择器，默认定位当前目录，可输入同一目标的其他路径。不把拖动解释为下载或跨本机传输。
- 操作先预检再确认：同名目标默认拒绝，不自动合并目录；删除与覆盖使用带明确动词的确认区，写明主机、路径与影响范围。
- 快捷键：单击选择、双击或 Enter 打开目录、F2 重命名、Delete 打开删除确认、Ctrl+Shift+N 新建目录。目录行菜单在 hover/focus 时显现，右键与 Shift+F10 同样可打开；顶部只保留导航、刷新、新建与帮助，不常驻一排操作按钮。
- 操作任务在面板底部折叠显示排队、执行中、完成、失败、部分完成或结果未确认；无可靠总量时使用不定进度。取消只作用于所选任务，不关闭共享 SSH 连接；面板收起后已提交任务继续，重开可查询，隐藏时停止轮询。
- 断线后禁用新提交，保留待核对结果；重连不自动重试移动、复制或删除。
- 服务器文件可查看元数据并直接操作；大文件只显示信息，不自动加载正文，也不提供下载。
- SFTP 读取完成即释放句柄；已打开的路径与选择在切换视图、切换尺寸后保留。

## 6. 设置页

### 6.1 分类与通用规则

- 分类：原生配置、启动环境、服务器档案、CLI 与探测。复用 Ariakit Tabs，只挂载当前分类内容，但外层共用草稿、revision 与保存状态。
- 切换分类不丢值；隐藏的错误在切回该分类时自动展开并聚焦字段。
- 保存 409、离开、Esc、外部重读、切到原生配置编辑器都有未保存保护；失败保留输入，不把值回退成看起来保存成功的样子。
- 密钥规则按对象分开（见 6.2、6.3），只有一条不分对象：日志、错误信息与接口响应里一律不出现明文。

### 6.2 原生配置

直接编辑 CLI 的原生配置文件。界面按「用户级」与「当前项目」两层分组（F4.1）：

- 用户级：各 CLI 的全局设置与说明文件——Claude 的 `settings.json`、`CLAUDE.md`，Codex 的 `config.toml`、`AGENTS.md`，Antigravity 的 `settings.json`、`mcp_config.json` 与 `config.json`。
- 项目级：当前项目目录里的说明、MCP、技能、代理、命令与 Antigravity 的 `.agents/` 定制声明。完整的文件清单与路径以需求 F4.1 为准，这里不重复列举。
- 编辑器用 CodeMirror 独立视图，同一时间只挂一个 dialog；条目列表与编辑视图之间保留未保存保护。
- 读时带 revision（内容摘要），保存时校验 revision 未变、语法合法、原子写入；语法错误拒绝保存并定位到出错位置，冲突拒绝并提示重读（F4.3、A12）。
- 保留未知字段与格式，不做格式化重排；区分「文件不存在」「空文件」「读取失败」三种状态，不混为一谈。
- 不监听配置文件变更：外部编辑器改了同一个文件，保存时因 revision 冲突被拒——这是有意的，避免两个进程互相覆盖。
- Antigravity 的项目级定制根同时接受 `.agents/`、`.agent/`、`_agents/`、`_agent/`。展示优先 `.agents/`：存在就用它，四种都不存在时新建也建 `.agents/`（F4.2）。
- 项目级条目跟着当前打开的项目走，同一个文件在不同项目下是不同条目（F4.4）。
- **掩码**：字段名像 key / token / secret / password 的默认折叠成掩码，点「显示」可展开完整内容——那是用户自己的文件，他有权看（F4.5、A15）。这一条与启动环境的值规则不同（见 6.3）。
- 保存不代表认证通过，也不代表模型可用；不实现模型验证。
- 不提供界面侧配置覆盖层：要么改原生文件，要么不改（F4.6）。

### 6.3 启动环境

配置文件不是全部，三个 CLI 的凭据落地方式不一样（F5.1）：

| CLI | 端点与密钥落在哪 | 本产品要做什么 |
|---|---|---|
| Claude | `~/.claude/settings.json` 的 `env` 块（`ANTHROPIC_BASE_URL`、`ANTHROPIC_AUTH_TOKEN` 等），CLI 自己读 | 什么都不用做，继承即生效 |
| Codex | `~/.codex/config.toml` 的 `[model_providers.*]`，CLI 自己读 | 什么都不用做，继承即生效 |
| Antigravity | **不写进 CLI 自己的设置**，只在启动时注入环境变量（`GOOGLE_GEMINI_BASE_URL`、`GEMINI_API_KEY`、`GEMINI_MODEL`） | **必须在启动 `agy` 时注入**，否则会用默认身份，且不会有明显报错 |

- 每个 CLI 一组可选环境变量，保存后在该 CLI 的子进程启动时注入；值用 Windows 当前用户加密保存；界面一律掩码，只显示变量名与状态（F5.2）。
- 四种状态必须一眼分清：`继承中` / `已显式配置` / `已停用（继承）` / `未设置`。**值永不回传前端**，没有「显示」这个功能，要改就重新填一个（F5.3）。
- 四种操作各有不同后果（F5.4）：
  - 新增或修改：写入或替换变量的值，覆盖同名的继承值；下次启动该 CLI 时生效，正在跑的回合不受影响。
  - 停用：保留密文但不注入；同样等下次启动生效，已启动的进程按老环境跑到该回合结束，界面写「已停用（下次启动起退回继承）」。
  - 删除：抹掉密文并停止注入，不可恢复；删除前确认要删哪个变量、之后退回继承值还是变成未设置。
  - 恢复继承：清掉所有显式配置，回到「什么都不配、全跟后端进程环境」的初始状态。

- 「立即生效」只提供一个出口：设置页的「重启该 CLI 进程」按钮。点了才会杀掉当前进程并按新环境重拉；正在进行的回合会被明确提示并中断，不静默执行。
- 只允许白名单变量名：不接受 `PATH`、`NODE_OPTIONS`、`PYTHONPATH` 这类会改变进程加载行为的变量，避免把「配个密钥」变成「注入任意代码」。用户只能改值、停用、删除，不能自加变量名（F5.5）。
- 删除真的抹掉密文，不是留一个标记位；删完之后磁盘上不再有那个值，界面也不再显示「已设置」（A17）。
- 删除与停用分开：临时切回官方身份用停用（A18）；确认不再需要，才用删除。
- 每个变量都标明来源是继承还是显式配置；界面只给变量名与状态，不给值。
- `GEMINI_API_KEY` 被删除后，`agy` 的探测结果要变成「凭据未配置」，而不是报一个看不懂的网络错误（F5.6）。

### 6.4 服务器档案

- 统一界面以列表展示友好名称、目标、认证方式、连接与凭据状态；选中只查看详情，不触发连接，也不新增列表轮询。顶栏「服务器」与设置页内的入口打开同一个界面。
- 编辑、保存、连接、断开分别是独立动作；保存与 SSH 连接分离，不自动认证。保存后引导下一步确认指纹并连接。
- 支持密码与私钥；凭据用 Windows 当前用户加密保存。保持主机密钥校验，不因使用密码而跳过 `known_hosts`：未知主机提示确认指纹，密钥变化明确拒绝静默连接（F6.5）。
- 明文密码不写入项目配置、磁盘上的普通文件、界面持久存储、日志、命令行参数或对话记录；只有用户选择保存时才写入当前用户加密的独立凭据文件（F6.6、A23）。
- 编辑表单按需读取已保存密码并填回，默认掩码，眼睛按钮可查看 / 隐藏与修改；取消、关闭、换目标清理表单，迟到结果不回填。
- 主动断开保留加密凭据；取消保存才移除该凭据并断开。失败保留状态并可重试。

### 6.5 CLI 与探测

- 每个 CLI 一行：安装状态、实际驱动的版本、上次探测时间、重新探测。探测结果四种，并写出缺了哪一项（A26）：

| 状态 | 判定依据 |
|---|---|
| 可用 | 命令能跑、版本能解析、关键能力齐全 |
| 未安装 | 找不到可执行文件 |
| 接口变化 | 能跑，但关键选项或 RPC 方法缺失；列出缺了哪一项，并显示双方版本 |
| 凭据未配置 | 该 CLI 需要的变量在「继承 + 显式配置」里都没有（不联网、不推断登录态） |

- 探测只跑第一档白名单：`--version`、`--help`、`codex app-server generate-json-schema`，全部是本地操作，不建立任何到模型端点的连接，也不发起模型请求（A24）。
- 「可执行文件路径」覆盖项：装完 CLI 后没重启过、PATH 里找不到它时在这里指定。`CLAUDE_CODE_EXECUTABLE` 是 Claude 的手动覆盖口。探测失败时界面直接给出这个入口，而不是只说「不可用」（A26）。
- 不做「未登录」判断：只按启动环境解析结果说「凭据未配置」；真正的登录失败由第一次真实回合报出来，界面原样展示 CLI 的报错。
- 版本常驻显示；CLI 自升级后，下次探测发现版本变了就重新探测能力，并按能力而非版本号决定提供哪些功能。
- 能力目录（斜杠命令、模型清单、账号状态）不在这里自动读，只在对话区点「刷新能力」时读（第二档），结果按 CLI、项目目录、版本与启动环境指纹缓存。
- 某个 CLI 的读取失败不会拖垮整个界面，只影响它自己的分组。

## 7. 状态与反馈

- 正常状态安静：第一档探测（`--version`、`--help`、读会话与配置文件）不弹提示、不占常驻位置。空态用短句，详细帮助按需展开。
- 空态：没有项目 → 引导添加项目目录；没有会话 → 「新建会话」；没有选中会话 → 一句说明先选项目与会话，不画空对话框；CLI 不可用 → 写原因并给路径覆盖入口。
- 加载：会话列表、读历史、目录浏览、资源采样都显示进度且可取消；切换会话时取消旧读取，加载期间禁止发送，迟到结果不覆盖当前选择。
- 运行状态：左栏会话行与会话头显示同一份状态；运行中尝试分叉、删除、重命名被拒绝并说明原因（A11）。
- 本机服务连接中断：顶栏简短提示 + 「重新加载界面」；重新加载后按会话重新挂载，不自动发起新回合。
- 某个 CLI 的驱动崩溃或超时：结束该回合、把会话标回空闲，已缓冲事件保留到进程退出，不静默重试。
- 原生存储异常：该会话标为不可读，不阻塞其他会话；目录监听失效退回手动刷新。
- 第二档动作必须明示：点「刷新能力」前说明「会启动 CLI 检查账号与模型清单」，失败降级为「能力未知」且不重试（A25）。
- 危险操作（删除会话、删除服务器文件、移除项目、覆盖保存、恢复归档）一律二次确认，并写明影响范围。
- 分别反馈：对话、终端、资源、Slurm 与文件操作各自报进行中 / 失败 / 已完成；文件操作提交成功只报启动信息或任务编号，不提前标完成。
- 错误在原位置说明，不用整页遮罩挡住无关活动：密码失效请求重新输入，资源失败标过期，文件操作失败保留待核对结果。

## 8. 可访问性

- 全部关键路径可用键盘完成，焦点可见：项目与会话列表、会话操作菜单、对话输入区与 `/` 补全、命令面板、面板视图切换与分隔线、文件操作菜单。
- 停靠区不是焦点陷阱、不是整页遮罩；分隔线具名并支持方向键调节，收起后不可聚焦，「复位」始终可达。只有真正需要确认的对话框才限制焦点，关闭后回到触发元素；嵌套确认取消不误收起外层。
- 状态不只用颜色：CLI 徽标同时有字母、运行状态同时有图标与文字、资源过期与失败有文字说明、危险开关有红色标记加文字。
- 流式回复区域使用 `aria-live="polite"`；图标按钮带可读的可访问名称。
- 资源数值的频繁刷新不逐条触发屏幕阅读器播报；连接失败、采样失败、过期等状态变化提供可读提示。
- 输入法：组字期间不触发命令补全、不发送、不执行命令面板；`Ctrl+K`、xterm 内部与已有原生模态保留自己的快捷键。
- 文字与背景对比度满足 WCAG AA；遵守 `prefers-reduced-motion`。
- 完整的无障碍验证需要用辅助技术手动测试，不能只靠自动化检查。
