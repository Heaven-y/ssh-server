## UI UX Pro Max 的适用内容

本轮查询得到的 Minimalism & Swiss Style 适合工具界面：减少装饰、清楚的字号和间距层级、中性色与单一主操作强调色、细微 hover、可见键盘焦点。初次综合生成还返回了营销页结构和紫色配色，与当前工作区目标不匹配，未采用或保存为设计系统。

技能提供的是设计规则与可访问性检查，项目截图提供的是具体布局参考。二者结合使用；不照搬其中的手机端或营销页建议，本项目仍以桌面工具为目标。

## 改版前的问题

1. SSH 和同步各占大块常驻区域，正常状态、说明文案、设置与危险操作同时呈现，挤压了对话。
2. 深蓝背景、亮边框与绿色按钮在多个区域同时强调，主操作不突出。
3. 小字号、技术说明和重复状态偏多；正文、路径、辅助信息的层级不够清楚。
4. 连接、同步、文件和会话像独立表单拼在一起，缺少一致的工作区导航和面板组织。

## 建议采用的方向

以 T3 Code 的简洁对话工作区为主，结合 CloudCLI 的项目/会话组织和 Vibe Kanban 的侧面板关系。

- **左侧导航**：工作区与其会话形成连续层级，新建入口集中；当前会话用轻背景区分。
- **顶部状态**：服务器、连接、同步压缩为一行。正常时只显示状态和时间；异常显示可操作的摘要。详细 SSH 配置、同步规则和恢复确认进入对应面板。
- **中央对话**：始终是主区。减少容器边框，给正文合理行宽与留白，工具输出折叠，输入区保留一个明确的发送/停止主按钮。
- **右侧面板**：文件、同步、后续改动/历史/资源按任务切换，默认收起；编辑文件时保留足够空间。终端接入时可扩展到底部。
- **视觉**：优先中性灰黑或中性浅色，少量蓝色用于主要操作；绿色只表达成功，红色只表达危险和错误。正文使用清楚的系统中文字体，等宽字体限于代码与路径。
- **状态与文案**：收起低频说明，保留必要错误、保存/同步结果及危险确认；不能为了简洁隐藏执行被阻断的原因。

本轮沿用既有深色模式并采用推荐的中性配色；浅色偏好尚未收到选择，不冒充用户已经确认。布局与交互继续遵循已有需求，不新增看板、自动 AI 任务或完整 IDE。
