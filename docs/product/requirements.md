# 需求

## 1. 背景

- 本地是 Windows 电脑，已安装并配置好 Claude Code、Codex。模型、服务商、密钥由本地配置决定（可能经由 cc-switch 切换）。
- 服务器可以联网，但访问不了 LLM 服务，只能和本地通信；本地通过 SSH 免密登录服务器。
- 服务器多人共用，同一个账号可能有多人使用，没有 root，没有 git。
- 服务器上的项目目录体积很大（数百 GB 到 TB 级），主要是数据、模型权重、输出文件；代码本身很小（几十 MB）。

## 2. 目标

做一个只在本机运行的网页。在网页里和本机的 Claude Code 或 Codex 对话，让它们修改和运行服务器上的项目。

## 3. 功能需求

### F1 工作区

- F1.1 新建工作区时选择三项：本地文件夹、SSH 服务器（从 `~/.ssh/config` 读取 Host）、服务器目录。
- F1.2 本地文件夹和服务器目录都可以在网页里逐级浏览选择，也可以手动输入路径。服务器目录体积按需计算（点击后才执行），避免对大目录自动扫描。
- F1.3 新建前测试 SSH 连通性和目录是否存在。
- F1.4 每个工作区有唯一 ID，同名项目互不干扰。
- F1.5 删除工作区只删除本工具的配置，不删除本地或服务器上的任何文件。

### F2 对话

- F2.1 每个会话选择 Claude Code 或 Codex。
- F2.2 流式显示回复、工具调用及结果、文件改动；可以中断正在进行的回复；可以继续历史会话。
- F2.3 Agent 请求需要确认的操作时，在网页上批准或拒绝。
- F2.4 模型默认"跟随本地配置"，此时不向 SDK 传任何模型、地址或密钥参数，cc-switch 切换后新对话自动生效。也可以从下拉框选择或手动输入模型；Codex 可以选推理强度。
- F2.5 会话中显示实际使用的模型名，用于确认切换是否生效。

### F3 远程执行

- F3.1 Agent 能在服务器的工作区目录下执行命令（运行、训练、测试、查看数据），返回标准输出、标准错误和退出码。
- F3.2 Agent 能查看未同步的大文件信息（大小、目录占用、头尾内容）。
- F3.3 执行前自动把本地改动同步到服务器，执行后把服务器上新增或修改的小文件同步回本地。
- F3.4 命令黑名单：默认禁止 `sudo`、`su`，对 `/`、`~` 或整个项目目录的 `rm -rf`，`mkfs`、`dd`、`shutdown`、`reboot`、`kill -9 -1`、`chmod -R 777`，改写 `~/.ssh/authorized_keys` 等。每个工作区可追加规则或停用某条默认规则；命中时拒绝执行并在对话中说明原因。
- F3.5 Agent 可以在本地执行命令（如 `git diff`、`grep`、格式化），但运行、训练、测试、查看数据须使用远程执行工具，由注入给 Agent 的指令约束。

### F4 网页终端

- F4.1 在网页里打开服务器的交互式终端，默认进入工作区对应的服务器目录，支持 `sinfo`、`squeue`、`nvidia-smi`、`nvitop`、`htop` 等全屏程序。
- F4.2 可同时打开多个终端标签。
- F4.3 终端是用户本人操作，不受命令黑名单限制。

### F5 同步

- F5.1 只同步代码和小文件。排除规则由扩展名列表（如 `*.pkl`、`*.pt`、`*.pth`、`*.joblib`、`*.npy`、`*.RData`、`*.zip`）和大小阈值（默认 10 MB）组成，可在网页上调整。
- F5.2 新建工作区时预览：将同步的文件数和总大小、被排除的大文件统计。
- F5.3 同步时机：执行远程命令前后、每轮回复结束后、手动点击、工作区打开期间定时拉取。
- F5.4 本地 `.git` 不同步到服务器。
- F5.5 不做任何备份或服务器端快照。
- F5.6 防误删：同步前检查本地删除了哪些文件，有删除时暂停该部分同步，在网页上列出，由用户确认后才删除服务器上的文件；用户拒绝则从服务器把文件恢复到本地。
- F5.7 两端同时修改同一文件时不自动覆盖，保留双方版本并提示冲突。
- F5.8 显示最近同步时间、结果和待确认事项。

### F6 版本记录

- F6.1 本地副本使用本地 git，仓库就在工作区的本地文件夹里。文件夹已经是 git 仓库时直接复用，不新建。
- F6.2 只在用户点击"保存"时提交，没有改动不提交；界面显示未保存的改动文件数。
- F6.3 超过大小阈值的文件不提交，并给出提示。
- F6.4 可查看提交历史和 diff，可把单个文件或整次提交恢复回去，恢复后经同步回到服务器。

### F7 会话记录

- F7.1 网页显示 Claude Code 和 Codex 本地已有的会话记录，按工作区筛选，网页本身不另存对话。
- F7.2 删除会话：Codex 使用官方接口 `thread/delete`；Claude 使用 Agent SDK 的 `deleteSession`。删除前确认会话不在运行中。
- F7.3 Codex 支持归档和恢复（`thread/archive`、`thread/unarchive`）。

## 4. 约束

- 服务器上不存放任何 LLM 配置、密钥或对话记录，也不安装任何软件，只使用已有的 SSH 账号。
- 网页只给本人在本机使用：后端只监听 `127.0.0.1`，校验访问令牌和请求来源。
- 不复制 CloudCLI（AGPL-3.0）的代码，基于官方 Claude Agent SDK 和 Codex 自行实现。
- 不修改用户全局的 Claude Code、Codex 配置，需要的参数按会话注入。
- SSH 使用本地已有的配置和密钥，不保存密码。
- 仓库公开，文档和代码中不出现真实的服务器地址、端口、用户名。

## 5. 第一版不做

- 文件树编辑器（代码在本地副本中，用户可以用自己的编辑器）
- 多用户、登录系统、数据库
- 服务器端快照和备份
- 接入不兼容 Anthropic / OpenAI 接口的模型
- 手机端适配

## 6. 验收标准

| 编号 | 场景 | 通过条件 |
|---|---|---|
| A1 | 新建工作区后让 Agent 在服务器上执行 `hostname` | 对话中返回服务器的主机名 |
| A2 | 让 Agent 修改一个文件后在服务器上运行它 | 服务器上运行的是修改后的版本 |
| A3 | 工作区包含大于阈值的文件 | 这些文件不出现在本地，也不进入 git |
| A4 | 在本地删除一个已同步的文件 | 服务器上的文件在用户确认前保持不变；拒绝后文件恢复到本地 |
| A5 | 点击"保存"后恢复某个文件的历史版本 | 本地和服务器上都恢复为该版本 |
| A6 | 用 cc-switch 切换服务商后新建会话 | 新会话使用切换后的模型，界面显示的模型名一致 |
| A7 | 对 Codex 重复 A1、A2 | 结果与 Claude 相同 |
| A8 | 在网页上删除一个会话 | 网页、VS Code 插件、命令行中都看不到该会话 |
| A9 | 完成一次完整使用后检查服务器 | 除工作区目录内同步的文件外，没有本工具产生的任何文件 |
| A10 | 在网页终端运行 `nvitop` 和 `sinfo` | 显示正常，可交互、可退出 |
| A11 | Agent 尝试执行黑名单命令 | 命令被拒绝，对话中显示原因 |
