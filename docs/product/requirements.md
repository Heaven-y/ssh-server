# 需求

更新日期：2026-11-03。产品名 **AgentDeck**（原 `ssh-server`）。本文描述当前产品规则；设计与取舍见[设计文档](../superpowers/specs/2026-11-03-native-cli-workbench-design.md)，选型记录见[设计决策](../engineering/decisions.md)，文档入口见[索引](../README.md)。

> 本轮是产品转向，不是增量修改：原来的主线「本地改代码 → rclone 同步 → 服务器上跑」整条移除，改为「**在本机桌面应用里，统一管理 Claude Code / Codex / Antigravity 的原生会话**」。SSH 能力作为附带工具保留，范围与现有 ssh console 一致（仅移除文件下载）。

## 1. 背景

- 日常在 Windows 本机使用三个 CLI：`claude`（Claude Code）、`codex`（Codex CLI）、`agy`（Antigravity CLI），均已配置自定义服务端点与密钥。
- 每个 CLI 的会话各自存放在自己的目录里（`~/.claude`、`~/.codex`、`~/.gemini/antigravity-cli`），要管理不同项目的不同会话，只能在多个终端窗口之间切换。
- 用户习惯桌面端形态（Codex 桌面端、DSH 桌面端），不喜欢用命令行管理会话与项目。
- 另有 SSH 需求：连服务器看进程、看资源、看文件、跑终端。这部分已有一个自用的 ssh console 插件，本产品要保持同等能力。
- 服务器上不跑 Agent、不存模型配置，SSH 纯粹是人的工具。

## 2. 目标

做一个**只在本机运行的 Windows 桌面应用**：打开就是项目列表，点项目按 CLI 分组列出会话，点会话进入对话，能接着聊。

- 会话是 CLI 自己的会话，配置是 CLI 自己的配置。本产品**不含模型引擎、不存对话正文、不另造配置体系**，只负责把原生内容摆整齐、画出来、能交互。
- 每个会话明确归属：属于哪个 CLI、哪个项目目录。
- 在同一处编辑各 CLI 的原生配置（用户级 + 项目级），不另建一层覆盖。
- 服务器面板保持现有 ssh console 能力，作为独立工具，不与对话耦合。

## 3. 功能需求

### F1 项目

- F1.1 项目由**本地绝对路径**标识，必填且必须真实存在。一个目录就是一个项目，不按名字猜。
- F1.2 项目可选择性绑定一台服务器档案与默认远端目录，用于服务器面板的默认目标；不绑定也能正常使用对话功能。
- F1.3 项目可新增、重命名、移除。移除只删本工具的配置，**不动磁盘上的任何文件，不动 CLI 的原生会话**。
- F1.4 项目列表与服务器档案分开存储与展示，互不牵连。切换项目不打断已打开的终端、资源采样与文件浏览。
- F1.5 改名前的数据（`servers.json`、`workspaces.json`）在首次启动时**一次性迁移**：只取仍成立的字段，新目录已有同名文件时不覆盖，旧目录原样保留不删。同步相关字段直接丢弃。

### F2 会话发现与归属

- F2.1 枚举本机真实存在的会话，三个 CLI 各自通过其原生存储或官方接口读取，不导入、不复制、不另存。
- F2.2 **归属由会话的原生 `cwd` 判定**，与项目目录规范化后比较，不按字符串前缀或目录名猜测。一个会话只属于一个项目、一个 CLI。
- F2.3 不属于任何已配置项目的会话默认不进列表，避免噪音。每个项目提供「显示其他目录的会话」开关：打开后列出该 CLI 存储中 `cwd` 不属于任何项目的全部会话，按目录分组，分组标题显示规范化绝对路径，可一键「加为项目」。
- F2.4 会话标题为空或缺失时显示明确的占位文案，不显示空白行。
- F2.5 Antigravity 的归属字段与其他两个不同：它没有 `cwd` 列，只有 `workspace_uris`。按 `workspace_uris` 判定归属，为空或非 `file://` 形式时归入「其他目录」分组。
- F2.6 列表显示 CLI 徽标与最近活动时间，按会话分组、组内置顶优先、其余按更新时间排序。会话正文不进入本产品的任何存储。

### F3 对话

- F3.1 会话固定属于创建它的 CLI，**不能中途切换 CLI**，不转换、不拼接上下文。需要另一个 CLI 就新建会话。
- F3.2 流式显示回复、工具调用与结果。可以中断正在进行的回合，可以继续历史会话。
- F3.3 审批模型按 CLI 各自的真实行为处理，不强行统一：
  - **Claude / Codex（交互式审批）**：CLI 请求确认时在界面上批准或拒绝，提交后等待后端确认，不重复答复。超时、中断或原生取消后关闭审批入口。
  - **Antigravity（软拒）**：被拒绝的工具**静默跳过**，通知从 `stderr` 出来，进程仍以 0 退出。`stderr` 必须作为一等界面信息呈现，不能当垃圾丢掉。没有回合内审批卡片的 CLI 在输入区上方常驻权限模式条。
- F3.4 会话级参数（模型、强度、权限模式等）只对本次运行生效，**不写回原生配置**；下次打开会话按原生默认值重新开始。唯一的例外是危险开关（如 `--dangerously-skip-permissions`）按会话记忆在界面偏好里，会话头常驻红色标记，默认关闭。
- F3.5 支持重命名、删除、分叉。删除走各 CLI 的官方接口；分叉点只接受服务端给出的可信位置，源会话不变、不回滚项目文件。
- F3.6 回合进行中，该会话的分叉、删除、重命名全部拒绝并给出原因。
- F3.7 **同一会话同时只允许一个回合**，不同会话互不阻塞。
- F3.8 界面只呈现「本应用正在驱动该会话」这一种确定状态。不声称「已锁定」——外部进程是否也在驱动同一会话无法可靠探测，这是能力边界，界面上说明同时驱动的风险即可。

### F4 原生配置编辑

- F4.1 直接编辑 CLI 的原生配置文件，覆盖两层，界面按「用户级」与「当前项目」分组：

| 层 | 文件 |
|---|---|
| 用户级 | Claude `~/.claude/settings.json`、`~/.claude/CLAUDE.md`；Codex `~/.codex/config.toml`、`~/.codex/AGENTS.md`；Antigravity `~/.gemini/antigravity-cli/settings.json`、`~/.gemini/config/mcp_config.json`、`~/.gemini/config/config.json` |
| 项目级 | Claude `CLAUDE.md`、`.mcp.json`、`.claude/skills`、`.claude/agents`、`.claude/commands`；Codex `AGENTS.md`；Antigravity `GEMINI.md`、`AGENTS.md`、`.agents/` 下的 `rules/`、`skills/`、`plugins/`、`hooks.json`、`skills.json`、`plugins.json` |

- F4.2 Antigravity 的项目级定制根同时接受 `.agents/`、`.agent/`、`_agents/`、`_agent/` 四种写法。展示优先 `.agents/`，四种都不存在时新建也建 `.agents/`。
- F4.3 保留未知字段与格式，保存前校验语法，外部修改后要求重新加载。区分「文件不存在」「空文件」「读取失败」三种状态，不混为一谈。
- F4.4 项目级条目跟着当前打开的项目走，同一个文件在不同项目下是不同条目。
- F4.5 **掩码规则分对象**：配置文件内容默认把名字像 key / token / secret / password 的字段折叠成掩码，**点「显示」可以展开完整内容**——那是用户自己的文件，他有权看。日志、错误信息、接口响应里一律不出现明文，这一条不分对象。
- F4.6 不提供「本产品侧配置覆盖层」：要么改原生文件，要么不改。

### F5 启动环境

- F5.1 三个 CLI 的凭据落地方式不同，必须区别对待：

| CLI | 端点与密钥落在哪 | 本产品要做什么 |
|---|---|---|
| Claude | `~/.claude/settings.json` 的 `env` 块 | 无需处理，继承即生效 |
| Codex | `~/.codex/config.toml` 的 `[model_providers.*]` | 无需处理，继承即生效 |
| Antigravity | **不写进 CLI 自己的设置**，只在启动时注入环境变量（`GOOGLE_GEMINI_BASE_URL`、`GEMINI_API_KEY`、`GEMINI_MODEL`） | **必须在启动 `agy` 时注入**，否则会用默认身份且无明显报错 |

- F5.2 每个 CLI 一组可选环境变量，保存后在该 CLI 子进程启动时注入。值用 Windows 当前用户加密保存，界面一律掩码，只显示变量名与状态。
- F5.3 四种状态必须一眼分清：`继承中` / `已显式配置` / `已停用（继承）` / `未设置`。**值永不回传前端**，要改就重新填。
- F5.4 四种操作的后果要分清：新增/修改覆盖同名继承值；停用保留密文但不注入；**删除真的抹掉密文**（不是标记位）；恢复继承清掉所有显式配置。除「重启该 CLI 进程」按钮外，改动都在下次启动生效。
- F5.5 **只允许白名单变量名**，不接受 `PATH`、`NODE_OPTIONS`、`PYTHONPATH` 这类会改变进程加载行为的变量，避免把「配个密钥」变成「注入任意代码」。用户只能改值、停用、删除，不能自加变量名。
- F5.6 `GEMINI_API_KEY` 被删除后，`agy` 的探测结果要变成「凭据未配置」，而不是报一个看不懂的网络错误。

### F6 服务器控制台

- F6.1 独立面板，能力与现有 ssh console 一致：多标签与分屏 SSH 终端、资源采样（GPU / CPU / 内存 / 磁盘 / 负载）、Slurm 作业查询、服务器文件浏览、服务器档案管理（密码 / 私钥、主机指纹确认、Windows 加密保存）。
- F6.2 **面板以服务器档案为身份，不以项目为身份。** 不绑定项目的服务器也能直接用；切换项目不会打断已开的终端、文件浏览与资源采样；同一停靠区可开多台服务器，标签显示主机别名。项目只提供默认服务器与默认目录。
- F6.3 未绑定项目时，文件浏览与资源采样的默认目录是登录用户的 home（`~`），不是根目录。
- F6.4 服务器文件支持新建目录、重命名、移动、复制、删除，在服务器上执行，内容不经本机中转。**不提供下载**——该能力已从产品中移除。
- F6.5 保持主机密钥校验，不因使用密码就跳过 `known_hosts`；未知主机提示确认指纹，密钥变化明确拒绝静默连接。
- F6.6 明文密码不写入项目配置、磁盘、浏览器持久存储、日志、命令行参数或对话记录；选择保存时仅允许本机系统加密后的独立凭据文件。
- F6.7 终端是用户本人操作，不受任何命令限制。资源与 Slurm 绑定固定服务器与真实连接，目标变化或迟到结果不能回填新身份。

### F7 桌面应用形态

- F7.1 产品是 Windows 桌面应用（Electron 壳），不是「打开浏览器访问某个端口」。主进程启动本机后端并让窗口加载它。
- F7.2 后端仍只监听本机回环地址，拒绝非本机地址。浏览器访问同一地址仍可用于调试，但那不是产品入口。
- F7.3 关窗口后后端进程随之退出，不留孤儿进程。单实例运行。
- F7.4 需要系统能力的场景（原生保存对话框等）通过 `preload` 暴露的窄接口调用，不把 Node 能力整体暴露给渲染层。

### F8 界面与外观

- F8.1 三段式布局：左栏项目与会话，主区对话，右侧服务器面板（可收起）。
- F8.2 视觉语气沿用 DSH 桌面端：中性灰阶打底、细边框、克制的高亮、等宽字体用于路径与代码、紧凑但留白的密度、深浅双主题默认跟随系统。CLI 归属用一个字母或色点区分，不用大色块。
- F8.3 **不显示改动视图**：对话里没有「本轮改动」卡片、没有 diff 渲染、没有行内反馈。工具卡片照常显示原生工具事件里的「写入/编辑了哪个文件」，点开只看路径，不算差异。
- F8.4 `Ctrl+K` 命令面板，命令清单按本产品范围重列，不保留任何同步、版本、本地文件相关命令。
- F8.5 有明确的空态：没有项目时引导添加目录；没有会话时引导新建；CLI 不可用时说明原因并给出可执行文件路径覆盖入口。

## 4. 约束

- **绝不自动发请求。** 任何会消耗额度、打到用户配置端点的动作都必须由用户明确点击触发。三档划分：

| 档 | 动作 | 何时发生 |
|---|---|---|
| 一 | `--version`、`--help`、`generate-json-schema`、读会话与配置文件、`fs.watch` | 启动、开页面、刷新列表，随时 |
| 二 | 启动 CLI 检查账号与能力（斜杠命令、模型清单） | **只由「刷新能力」按钮触发**，结果缓存 |
| 三 | 真正发一轮 prompt | 只有用户点发送 |

  「打开新建会话」不算第二档授权。失败降级为「能力未知」，不重试。

- **版本以本机安装为准**，不打包、不锁定、不假设稳定。按能力探测而非版本号判断，不写 `if (version >= x)`。界面常驻显示当前驱动的版本号。探测失败时该 CLI 标记不可用，其余照常工作。
- **单一真相**：会话正文只存在于 CLI 自己的存储里。本产品不落库、不做事件投影缓存、不做导入导出。允许保存的只有会话索引（原生 id、所属 CLI、cwd、标题、最近活动时间）、界面偏好与项目列表。
- **只有一条接入路径**：结构化事件，不嵌 CLI 的终端界面。想用 TUI 就直接用 CLI。
- 不读取 cc-switch 等其他工具的数据库。它们怎么存是它们的事，我们只认原生配置文件和启动环境。
- 后端 Node.js + TypeScript + Fastify + zod；前端 React 19 + Vite + Tailwind 4；终端 xterm；编辑器 CodeMirror。
- 仓库公开，文档与代码中不出现真实服务器地址、端口、用户名或凭据；示例用 `my-server`、`~/projects/demo`。
- 不复制 CloudCLI（AGPL-3.0）或 Pebrel（GPL-3.0）的代码。

## 5. 第一版不做

- 多用户、局域网或公网访问、登录系统
- 多 Agent 编排、内置 IDE、调试器、看板、内置浏览器
- 把 CLI 的 TUI 逐像素复刻，或把终端画面塞进界面
- 同一会话跨 CLI 切换
- 任何形式的代码同步（rclone 双向同步、冲突处理、待确认删除）
- 本地 git 快照、版本历史、恢复
- 本地文件只读镜像与改动视图、行内反馈
- 服务器文件下载
- 网页侧配置覆盖层
- 给 CLI 注入服务器操作工具（Agent→SSH 的 MCP 桥）
- 手机端适配
- 自动安装、升级或调用模型

## 6. 验收标准

| 编号 | 场景 | 通过条件 |
|---|---|---|
| A1 | 打开桌面应用 | 直接出窗口，不需记端口或开浏览器；关窗口后无孤儿进程 |
| A2 | 添加一个含多个 CLI 会话的项目目录 | 左栏出现该项目，展开后按 CLI 分组列出真实会话，每条带 CLI 徽标与最近活动时间 |
| A3 | Claude 与 Codex 会话的正文 | 能完整读出原生历史正文，与本机 CLI 里看到的一致 |
| A4 | Antigravity 会话 | 能列出标题、时间并按 `workspace_uris` 归属；轨迹读不出时正文区显示「不可回放」的明确文案，不是空白，且可以继续对话 |
| A5 | 打开「显示其他目录的会话」 | 列出 `cwd` 不属于任何项目的会话，按规范化绝对路径分组，可一键加为项目 |
| A6 | 在界面里完成一轮 Claude 对话 | 流式显示回复与工具卡片，回本机 CLI 可见同一会话，正文不进入本产品存储 |
| A7 | 对 Codex 重复 A6 | 结果与 Claude 相同 |
| A8 | Claude/Codex 请求需要确认的操作 | 界面弹出审批，批准/拒绝后不重复答复；超时或中断后入口关闭 |
| A9 | Antigravity 的工具被软拒 | 被拒工具跳过、进程 0 退出，**拒绝原因在界面上可见**，不被当作静默失败 |
| A10 | 回合进行中再次对同一会话发送 | 被拒绝并说明原因；其他会话不受影响 |
| A11 | 回合进行中尝试分叉/删除/重命名该会话 | 被拒绝并说明原因 |
| A12 | 修改 `~/.claude/settings.json` 与 `~/.codex/config.toml` 并保存 | 本机 CLI 立刻读到新内容；未知字段与格式保留；语法错误时拒绝保存并定位 |
| A13 | 切换项目后查看项目级配置 | 条目跟着项目走；同一个文件在不同项目下是不同条目 |
| A14 | 项目级定制目录不存在 | 新建时建 `.agents/`；已存在 `.agent/` 等其它写法时优先复用 |
| A15 | 配置里含 API key | 默认掩码折叠，点「显示」可展开；日志与接口响应中始终无明文 |
| A16 | 给 agy 配好 `GEMINI_API_KEY` 与 `GOOGLE_GEMINI_BASE_URL` | 该 CLI 探测从「凭据未配置」变为「可用」；发一轮对话用的是配置的端点 |
| A17 | 删掉 `GEMINI_API_KEY` | 探测回到「凭据未配置」，且磁盘上不再有该值，界面不再显示「已设置」 |
| A18 | 停用某个环境变量后不重启进程 | 当前回合行为不变；重启该 CLI 后退出继承 |
| A19 | 不绑定项目直接开服务器终端 | 可用，默认目录是 `~`；终端、资源、Slurm、文件浏览均正常 |
| A20 | 开着终端时切换项目 | 终端、资源采样、文件浏览都不被打断 |
| A21 | 服务器文件的新建、重命名、移动、复制、删除 | 与现有 ssh console 一致；**界面里不存在下载入口** |
| A22 | 连接一台未知主机 | 提示确认指纹；拒绝后不连接；密钥变化时拒绝静默连接 |
