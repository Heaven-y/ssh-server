# 产品需求

更新于 2026-11-05。本文件定义当前产品方向和验收条件，交付状态以[路线图](../roadmap.md)为准。重整前的 M1 需求与验收编号可用 `git show c686ef2:docs/product/requirements.md` 追溯；旧记录不代表本轮验证结果。

## 1. 定位与范围

AgentDeck 面向在 Windows 本机使用多个 AI CLI 的用户。以 DSH 式桌面工作台集中组织项目、原生会话和对话操作，自有插件承载附加工具。原生对话与配置始终是产品主体，插件不改变各 CLI 的执行语义。

主体负责项目导航、CLI 接入、会话呈现和通用交互。Claude、Codex 与 Antigravity 共用一套工作台和对话界面，来源与实际支持能力各自保留。CLI 仍负责模型调用、上下文、工具、权限规则与原生存储；插件负责附加业务。

不在当前范围：多用户服务、局域网或公网访问、跨 CLI 转换会话、多 Agent 编排平台、内置 IDE、代码同步、本地版本快照与文件镜像。无需安装 DSH 插件包，也不建设 DSH 兼容层。

## 2. 功能要求

### F1 项目与目录

- 项目以本地绝对目录为身份，新增或换目录时校验目录存在；目录暂时离线不应阻止已有项目改名、解绑或移除。
- 移除项目只删除 AgentDeck 中的记录，保留目录、原生会话和独立的服务器档案。
- 当前项目结构为 `{ id, name, dir, server?, remoteDir? }`；服务器和远端目录作为现有 SSH 默认目标必须成对设置或清除，服务器别名须已登记。
- 项目菜单独立提供改名、换目录和确认移除；缺省字段代表不改，显式 `null` 清除可选绑定。会话运行、准备发送或管理期间禁用冲突操作；服务端对目录修改和移除建立原子占用边界。
- 换目录后清理该项目的旧会话选择、模型和能力缓存，再按新目录读取列表。异步操作完成时不得切走用户后来选择的其他项目。
- 首次迁移复制旧产品数据后再转换字段，保留原文件与备份；暂时不可访问的绝对目录仍应保留，不静默丢弃项目。

### F2 原生会话发现与归属

- 会话身份由 CLI 类型与原生会话 id 组成，创建后不能切换成另一种 CLI。
- Claude 和 Codex 以原生 `cwd` 归属，Antigravity 使用 `workspace_uris`。规范化绝对路径后比较目录或子目录；Windows 大小写不敏感，POSIX 保持大小写。
- 多项目命中时取项目配置顺序中的第一个；解析不出或不属于任何项目的记录归入「其他目录」，默认隐藏。只有服务端能确认单一本机绝对目录时，条目才提供预填的添加项目入口；远程 URI、歧义和未知目录不猜测。
- 「其他目录」按需读取，零项目时也能发现原生摘要；新增、换目录或移除项目后同步刷新归属，不让已归属会话仍留在无归属缓存中。
- 列表按最近活动排序，标题缺失显示「未命名会话」；不能按标题猜模型、目录或会话身份。
- 读取、续接和管理操作前复核会话归属。切换选择时取消旧读取，迟到结果不能替换当前会话。
- Claude/Codex 通过官方接口读取历史。Antigravity 目前仅能可靠枚举摘要，历史返回明确的不可回放状态，不生成替代正文。
- 监视已知原生会话目录的变动，仅在列表版本变化或手动刷新时重新读取会话摘要；不自动刷新模型能力或替换当前对话正文。监听不可用时说明降级并保留手动刷新。

### F3 对话主流程

Claude、Codex 和 Antigravity 均已接入对话流程。Antigravity 的历史回放限制不阻止使用原生 id 继续对话；真实账号和模型回合的验证状态仍按来源单独记录。

- 可在选定项目中选择支持对话的 CLI 新建会话，也可打开现有会话继续发送；续接使用原生 id，不把已显示历史重新拼成 prompt。
- 显示助手文本增量、工具执行与结果、错误、原生报告的用量和上下文状态；没有原生数据的字段不编造。
- 发送后建立可中断的运行状态，准备阶段也能停止；结束、失败或取消都应解除占用。不同会话不因共享界面而互相覆盖。
- 同一原生会话一次只能有一个回合；运行中拒绝重复发送和改名、删除、归档、分叉。状态只表示 AgentDeck 自己的占用，不能声称外部 CLI 已被锁定。
- Claude/Codex 原生要求审批时才呈现审批操作；批准或拒绝传回对应回合。Antigravity 按原生机制展示权限模式与 stderr 软拒原因，不伪造回合内批准通道。工作台不自行添加工具放行策略，也不改写原生权限默认值。
- 模型、推理强度及权限等选项按 CLI 能力提供；未显式选择就交给原生默认。运行中的回合不偷偷切换参数，原生拒绝时显示原因，不自动换模型或重发。
- 接入原生分叉、删除、归档等管理动作时遵守各 CLI 的真实语义。分叉只能使用服务端确认的原生结束点，源会话与项目文件保持原样；不支持的动作明确禁用或隐藏。
- 管理入口沿用项目侧栏。Claude 提供重命名、末尾分叉和确认删除；Codex 另有归档与恢复。已归档列表按项目主动展开，条目恢复后才能续聊；Antigravity 暂不显示没有原生接入的管理按钮。操作跨项目时始终使用被操作条目的项目身份，迟到结果不抢占用户的新选择。
- 对话传输允许进程内短期缓冲，但不形成正文持久化副本。刷新后继续接收运行中事件属于需专门验证的能力，不能由 WebSocket 自动重连推断已经具备。

### F4 能力与配置

- 按每个 CLI、每项能力分别核实支持方式。用户级、项目级、目录级或仅运行时的作用域以原生规则为准，不要求三个 CLI 使用同一种层级。
- 模型、命令、Skills、MCP、规则、原生插件和权限能力从该 CLI 的有效接口或配置获得；未知、未支持、无权限和尚未接入应区分。
- `/` 补全只能来自真实能力目录。未知、禁用或歧义命令不能静默当普通消息发送；需要会话的命令在无会话时提示限制。
- 原生文件编辑保留未知字段与原格式，检查文件身份和外部修改；JSON/TOML 按格式校验，规则文本由 CLI 解释。缺失、空白和读取失败分别展示，显式保存才写盘；固定规则和 Skills 根目录支持受控创建。
- 默认目录视图只返回元数据，不预读敏感正文。用户点击显示并编辑后才读取完整文件，正文随编辑器关闭释放，不进入共享缓存或浏览器存储；保存响应、日志和错误不回显正文。该显式原文入口与启动环境的旧值不回传接口分别约束。
- 启动环境只补足原生配置之外的实际需要。按 CLI 白名单管理变量，状态区分继承、显式配置、停用和未设置；修改只对下次启动生效，重启须由用户明确操作。
- 启动环境的敏感值加密保存，不回填旧值；禁止用该入口设置 `PATH`、`NODE_OPTIONS`、`PYTHONPATH` 等加载行为变量。不得读取其他配置切换工具的私有数据库。

### F5 扩展插件

- 提供 AgentDeck 自有接口，工作台新增业务通过插件接入。CLI 原生插件仍属于相应 CLI，不转成工作台插件格式。
- v1 外部扩展采用本地静态页面包，可声明页面命令、自己的设置存储和当前项目摘要权限；不运行外部 Node 后端代码。安装后默认停用，用户检查权限后启用。
- 插件的安装、启停、资源清理和版本兼容须有明确行为；关闭页面与停用插件是不同动作。
- SSH Console 是首个业务插件。优先复用已验证的 SSH 业务和成熟组件，避免为插件化再写一套相同业务。
- 不提供 DSH 插件原样安装、包格式兼容或长期维护的适配层。

### F6 SSH Console

内置 SSH Console 已按现有插件的独立工具体验接入。旧项目绑定业务集中到控制台内的「项目服务器工具」，不再放入对话右栏；两者共享连接基础，保留各自的目标身份与页面状态。

- 从侧栏进入独立主页面；多台服务器保持连接，以标签切换当前目标，页面提供概览、进程、文件和终端。
- 概览展示 CPU、内存、负载、磁盘、GPU 利用率及显存；进程页展示 GPU 与系统进程。缺失值不补零，旧读数标明过期；仅当前可见目标持续采样。
- 文件页只读列目录并预览文本，预览取开头最多 256 KiB；不包含新建、移动、删除、上传或下载按钮。终端仍是用户自己的通用 SSH shell。
- 同台服务器可持有多个 PTY；切换页签、服务器或关闭插件页面后重新打开，应能接回仍存活的终端。真正关闭终端、断开服务器或停用插件才回收相应资源。
- 终端提供本机回滚查找；打开查找和跳转命中不向远端发送命令。输入及输出的结果不确定时不自动重发按键。
- 服务器独立于本地项目，未绑定项目也能使用；项目最多提供默认目标，不承担服务器身份。
- 认证支持已有私钥和密码，必须校验主机密钥。未知主机先确认指纹，密钥变更或吊销明确拒绝；浏览器不能读取私钥内容。
- Slurm、已有文件写操作与旧终端只从控制台内的「项目服务器工具」进入，仍使用项目绑定目标。独立控制台复用服务器档案、主机信任和可选加密密码；停用会结束控制台和项目服务器工具中的终端，确认提示必须明确范围。停用不删除档案、密文、项目或旧任务数据，不关闭其他业务仍使用的共享连接。
- 成功停用后取消旧终端的待绑定操作并清空其标签；重新启用不能凭遗留标签自动创建新 shell。停用失败或用户取消时不提前清理有效终端。

### F7 桌面与通用交互

- 产品入口是 Electron 窗口，本机 Fastify 服务由其管理，单实例运行，退出时清理后端与子进程；浏览器入口用于调试。
- 视觉与信息组织对齐 DSH：左侧工作区、中间对话、可打开的右侧栏；使用中性灰阶、细边框和系统字体，代码与路径采用等宽字体。三个 CLI 不分别设计三套风格。
- 左栏上方提供新建与插件入口，项目下的会话按最近活动混合排列，来源清楚可见；设置和外观在左栏底部。中央标题栏只承担当前会话标题与状态。
- 左栏默认 280px、可调 264–420px，收起为 56px 图标导航；1024px 以下采用窄窗布局。右栏默认 420px、可调 300–720px，每次启动关闭，旧服务器栏的持久展开偏好不复用。
- 当前右栏只显示会话信息与配置入口，不宣称提供 IDE、文件树或独立改动列表。插件占用中央主区，打开/关闭右栏及切插件返回不得清空对话草稿。宽度冲突时协调左右栏，具体边界见[界面约定](ui-layout.md)。
- 加载、空态、读取失败和能力缺失各有可理解的说明；输入法组字时不触发发送或快捷命令。
- 原生事件没有提供的信息不通过扫描整个项目推断；不恢复每轮 Git 快照、独立改动汇总和行内反馈系统。
- 本地分发提供 Windows x64 的 NSIS 与 portable 构建，产品数据与程序分开。当前不签名、不上传发布、不自动更新；生成包、包内启动和实际安装卸载分别验收。

## 3. 请求与数据边界

| 动作 | 触发约束 |
|---|---|
| 本机可执行文件与接口探测、读取配置/会话 | 可随启动、导航或手动刷新执行；仅运行本地操作 |
| 登录/模型/命令能力检查 | 明确的「刷新能力」操作触发；可能鉴权联网，失败不自动重试 |
| prompt 与真实模型回合 | 仅用户明确发送；新建页面、切项目、重连均不等于发送 |

后端自己不调用模型 HTTP 端点，模型请求由 CLI 进程完成。项目、偏好和必要元数据可以保存；对话正文、工具事件和附件不落成独立 transcript。已发送但结果不确定的操作不得通过自动重发掩盖。

后端只监听本机地址，并校验 Host、Origin 与会话 Cookie。凭据、真实服务器信息和用户会话不得进入公开仓库；例子使用 `my-server`、`~/projects/demo` 等虚构值。

## 4. 验收与证据

以下是需要证明的行为，不是自动标记为通过的清单。真实 CLI/SSH、受控夹具和静态检查的结论分开记录。

| 编号 | 场景 | 通过条件 |
|---|---|---|
| A1 | 项目管理 | 无效新目录被拒绝；离线旧项目能改名/移除；换目录清旧会话，忙碌保护有效，迟到结果不抢选择 |
| A2 | 会话归属 | 不同 CLI 按各自目录字段归属；零项目能按需发现其他目录；项目映射变化后不保留错误归属 |
| A3 | 原生历史 | Claude/Codex 正文可读；Antigravity 明确不可回放；切换时迟到数据不串线 |
| A4 | 三个 CLI 新建与续接 | 显式发送后生成或沿用原生 id；各 CLI 单独验证，原生客户端识别同一会话 |
| A5 | 流式回合与中断 | 增量、工具、结果和失败可见；准备与运行阶段均可停止，终态解除占用 |
| A6 | 权限交互 | Claude/Codex 审批答复作用于正确回合；Antigravity 显示原生软拒原因，不假装工具已执行 |
| A7 | 原生参数 | 默认不覆盖原生值；显式选择正确传递；不支持的参数说明原因 |
| A8 | 请求触发 | 启动、打开新会话和重连不发 prompt，也不擅自刷新联网能力 |
| A9 | 配置编辑 | 支持的文件和作用域真实可用；语法错误与外部修改不覆盖原文件 |
| A10 | 插件扩展 | 按实际交付契约安装或启停；页面切换和资源结束语义分别验证 |
| A11 | SSH 插件 | 无项目也可连接，多服务器不串状态，只读文件预览和 PTY 生命周期符合 F6 |
| A12 | 桌面与界面 | 单实例与退出清理正常；首屏右栏关闭且无 SSH 请求；约定宽度、主题和键盘操作可用，切页返回保留草稿与合理焦点 |
| A13 | 刷新与终端查找 | 无目录变更不重复读会话；隐藏时停止版本轮询；查找只操作本机缓冲 |
| A14 | 本地分发 | 本地目标包可生成并完成对应启动检查；未签名与未验收的安装环节明确说明，原生 CLI 不被替换 |
