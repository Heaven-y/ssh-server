# 需求

更新日期：2026-10-05。本文描述第一版的目标行为，不代表功能全部验收；实际进度见 [路线图](../roadmap.md)，选型与取舍见 [设计决策](../engineering/decisions.md)。

## 1. 背景

- 本地是 Windows 电脑，已安装并配置好 Claude Code、Codex。模型、服务商、密钥由本地配置决定（可能经由 cc-switch 切换）。
- 服务器可以联网，但访问不了 LLM 服务；本地通过 SSH 操作服务器。当前使用的 A100 服务器已有免密配置，正式产品也必须支持账号密码登录，不能以已配置私钥为前提。
- 服务器多人共用，同一个账号可能有多人使用，没有 root，没有 git。
- 服务器上的项目目录体积很大（数百 GB 到 TB 级），主要是数据、模型权重、输出文件；代码本身很小（几十 MB）。
- 现有操作需要在本地提交代码、服务器拉取、下载结果，再把结果交给 AI。目标是让这些操作在同一个网页工作区中完成。
- 默认按直接连接服务器的场景设计：SSH 连接目标也是远程命令和资源采集的目标。不预设登录节点与训练节点分离；若通过 Slurm 在其他节点运行任务，当前 SSH 节点的资源指标不能当作计算节点指标。

## 2. 目标

做一个只在本机运行的网页。在网页里和本机的 Claude Code 或 Codex 对话，让它们修改本地代码副本，自动同步到服务器，再远程运行、测试或提交训练任务。用户手动要求查看结果时，Agent 直接从服务器读取所需结果并分析。

主要编辑工作由 AI 完成；用户偶尔在网页里调整脚本。网页同时提供交互终端和持续刷新的服务器资源面板。代码同步与远程运行不要求用户手动提交 git，也不依赖服务器安装 git。

本地网页服务负责协调 Agent、SSH、文件同步和状态显示。统计、绘图及结果处理默认使用服务器已有的 Python / 项目环境，数据留在服务器，只返回分析所需的摘要或小文件。

## 3. 功能需求

### F1 工作区与 SSH 连接

- F1.1 新建工作区时选择三项：本地文件夹、SSH 服务器、服务器目录。服务器既可从 `~/.ssh/config` 读取 Host，也可手动填写地址、端口和账号。
- F1.2 本地文件夹和服务器目录都可以在网页里逐级浏览选择，也可以手动输入路径。服务器目录体积按需计算（点击后才执行），避免对大目录自动扫描。
- F1.3 新建前测试 SSH 认证、连通性和目录是否存在；测试与后续执行、同步、终端使用同一组连接参数和认证方式。
- F1.4 每个工作区有唯一 ID，同名项目互不干扰。
- F1.5 侧栏移除工作区只删除本工具的配置，保留两端文件、Git、原生会话、服务器表和凭据。确认绑定当前配置；对话、同步、未完成文件任务和已登记编辑器须先处理，空闲后仅关闭所属终端和浏览通道。失败可重新核对重试，迟到成功不切走用户新选择。
- F1.6 支持账号密码认证和已有 SSH 私钥认证。已有免密方式可直接复用；密码模式不要求先配置私钥。
- F1.7 支持选择“保存密码”，使用 Windows 当前用户的系统加密能力保存在本机；明文仅在连接需要时进入后端内存。主动断开只关闭连接并清理内存，保留已保存凭据，重连或后端重启后可以复用；取消“保存密码”勾选会删除该目标的已保存凭据并断开连接，不提供独立“忘记密码”入口。凭据绑定实际地址、端口和账号，目标变化时不能复用旧密码；认证失败时提示重新输入。界面区分认证失败、连接失败与主机密钥校验失败。
- F1.8 保持服务器主机密钥校验，不因使用密码就跳过 `known_hosts` 校验；未知主机须提示用户确认指纹，密钥变化须明确提示并拒绝静默连接。

F1连接向导已接入五步配置、手动服务器表、两端分页浏览、实际指纹与一次性验证创建。F5.2预览复用过滤与独立rclone元数据清单；真实SSH创建及首次双向初始化通过，见[向导验收](../guides/workspace-setup-acceptance.md)。F1.5删除入口与生命周期已接入，证据见[移除验收](../guides/workspace-removal-acceptance.md)。A12的真实DPAPI、后端重建、同步和PTY组合通过受控密码网关与真实远端通道验收，边界见[完整链路验收](../guides/real-workflow-acceptance.md)。

### F2 对话与原生 Agent 能力

- F2.1 创建会话时选择 Claude Code 或 Codex；一个会话固定使用一个 Agent，已有会话不能中途切换。需要另一个 Agent 时新建会话，不转换或拼接两种 Agent 的上下文。
- F2.2 流式显示回复、工具调用及结果、文件改动；可以中断正在进行的回复；可以继续历史会话。
- F2.3 Agent 请求需要确认的操作时，在网页上批准或拒绝；提交后等待后端确认，不得重复答复。超时、中断或原生请求取消后关闭审批入口，单次批准不扩大为会话级授权。
- F2.4 模型默认“跟随本地配置”，此时不向官方运行时传任何模型、地址或密钥覆盖参数，cc-switch 切换后新会话采用新默认模型。Codex 续接历史时保留原生会话模型，只有用户显式选择模型才覆盖；重启运行时不应被描述为历史自动换模型。原生目录提供模型和推理强度候选，同时保留手动输入；目录默认项、历史实际模型及默认 effort 不自动写成覆盖参数。
- F2.5 会话中显示实际使用的模型名，用于确认切换是否生效。
- F2.6 上下文组织、历史续接和自动压缩由 Claude Agent SDK / Codex app-server 的官方运行时负责。网页不自行拼装全量历史作为提示词，不另建一套上下文压缩逻辑。
- F2.7 展示官方接口提供的上下文用量和压缩状态；Claude 标明原生估计，Codex 使用原生 last 用量与通知窗口，不将累计计量或配置窗口当作当前占用。仅展示原生直接提供的比例，缺失数据为不可用。手动压缩已有会话，成功必须由本轮原生事件确认，失败、中断及未确认不能标为完成。
- F2.8 在网页里发现和调用当前 Agent 可用的本机 / 项目 skills，以及官方接口支持的 `/` 命令，提供搜索和选择入口。目录按工作区/Agent 隔离，支持刷新和限制说明；前端仅提交稳定 ID，实际原生实例在调用前再次验证，拒绝未知、禁用、过期和歧义项。目录读取失败不阻断普通消息。
- F2.9 需要原生命令行交互、而官方网页接入接口未支持的命令，明确标注不可在网页执行或提示使用本机 CLI；不把输入了 `/命令` 视为已经支持该命令。网页命令面板与 Agent 的 `/` 命令是不同入口。
- F2.10 在设置中直接编辑 Claude Code 和 Codex 的原生配置文件，沿用现有配置格式和未知字段；保存前校验语法、检测文件被其他程序修改并原子写入。更新后后续调用读取新配置，无须重启本项目；运行中的轮次不切换配置，历史会话的模型选择遵循 F2.4 的原生续接语义。配置和模型服务密钥只在本机处理，不进入服务器、日志、Agent 输入或浏览器持久存储。

产品设置已接入新会话Agent/按Agent模型默认值。模型默认留空跟随原生，用户可以保存非空的新会话默认；打开历史清除默认来源，仅保留显式覆盖，已操作草稿和运行轮次不随迟到偏好切换。原生配置和产品偏好分开视图，手动环境检测只读现有工具版本；见[设置验收](../guides/product-settings-acceptance.md)。

### F3 远程执行与结果读取

- F3.1 Agent 能在服务器的工作区目录下执行命令（运行、训练、测试、查看数据），返回标准输出、标准错误和退出码。
- F3.2 Agent 能查看未同步的大文件信息（大小、目录占用、头尾内容），并按用户要求从远程日志、结果表格等文件读取必要内容。大结果不必全部下载，也不必由用户手动上传给 AI。
- F3.3 执行前自动把本地改动同步到服务器，执行后把服务器上新增或修改的同步范围内小文件拉回本地。执行前同步失败、或存在影响本次执行的未处理删除 / 冲突时，暂停远程执行，显示原因；不能继续运行旧代码。
- F3.4 命令黑名单：默认禁止 `sudo`、`su`，对 `/`、`~` 或整个项目目录的 `rm -rf`，`mkfs`、`dd`、`shutdown`、`reboot`、`kill -9 -1`、`chmod -R 777`，改写 `~/.ssh/authorized_keys` 等。每个工作区可追加规则或停用某条默认规则；命中时拒绝执行并在对话中说明原因。
- F3.5 Agent 可以在本地执行命令（如 `git diff`、`grep`、格式化），但项目的运行、训练、测试、查看数据须使用远程执行工具，由注入给 Agent 的指令约束。
- F3.6 长时间任务使用服务器已有的 `nohup` 或 Slurm 等方式提交，返回启动信息或任务 ID；不要求 SSH 工具一直等待整个训练结束。
- F3.7 训练进度、完成情况和结果分析由用户手动发消息触发，例如“看一下这次训练的结果”。不自动检测任务完成，不自动发消息、唤起 Agent 或续跑分析。文件定时同步和 F9 资源刷新不改变此约定。
- F3.8 用户要求统计、绘图或处理结果时，默认通过 SSH 使用服务器已有的 Python / 项目环境；新分析脚本先在本地编辑并同步，再远程执行。大数据保持远程，仅返回必要统计、日志、结果表或小图文件；缺少环境或依赖时明确报告，不自动安装。

F3.4工作区规则管理已接入侧栏：默认启停/恢复、最多20条自定义程序名或命令字符串字面规则，版本保存及执行拒绝贯通。规则区分大小写、不支持正则，只防误操作；坏配置（包括null）拒绝执行，网页终端及已检查在途命令沿用既定边界。[验收](../guides/workspace-policy-acceptance.md)覆盖核心回归、真实SSH无副作用命令和三宽度网页；完整模型/SSH/rclone链路已补齐[独立验收](../guides/real-workflow-acceptance.md)，规则命中仍按各项具体证据判断。

### F4 网页终端

- F4.1 在网页里打开服务器的交互式终端，默认进入工作区对应的服务器目录。服务器已经安装的 `sinfo`、`squeue`、`nvidia-smi`、`nvitop`、`htop` 等命令及全屏程序应正常显示、可交互；不要求这些工具全部存在。
- F4.2 可同时打开多个终端标签，调整终端显示区域大小。终端外观与多标签、分屏等交互参考 [Pebrel](https://github.com/Kuddev/pebrel)，具体布局见界面文档。
- F4.3 终端是用户本人操作，不受命令黑名单限制。
- F4.4 终端是通用 SSH shell，不绑定 `nvitop`，资源概览可以直接使用 F9 面板。

F4 的[网页终端设计](../superpowers/specs/2026-10-04-web-terminal-design.md)和[实施计划](../superpowers/plans/2026-10-04-web-terminal.md)已实施。固定目标、目录确认、独立PTY、背压、标签/分屏、复制粘贴及稳定布局已通过核心回归与本机真实ssh2网页验收，见[验收记录](../guides/web-terminal-acceptance.md)。真实htop/nvitop的绘制、尺寸调整、退出、并发和密码后端重建组合通过；原生OS输入法仍待验，详见[完整链路验收](../guides/real-workflow-acceptance.md)。

### F5 同步

- F5.1 只同步代码和小文件。排除规则由扩展名列表（如 `*.pkl`、`*.pt`、`*.pth`、`*.joblib`、`*.npy`、`*.RData`、`*.zip`）和大小阈值（默认 10 MiB，即 10 × 1024 × 1024 字节）组成，可在网页上调整。
- F5.2 新建工作区时预览：将同步的文件数和总大小、被排除的大文件统计。预览由用户触发，不自动递归扫描全部大数据目录。
- F5.3 同步时机：执行远程命令前后、普通消息或技能轮次结束后、手动点击、工作区打开期间定时拉取；纯上下文查询/压缩命令不编辑项目，不触发结束同步。定时拉取只更新文件，不检测任务完成或触发 AI 分析。
- F5.4 本地 `.git` 不同步到服务器。
- F5.5 不做任何备份或服务器端快照。
- F5.6 防误删：同步前检查本地删除了哪些文件，有删除时暂停该部分同步，在网页上列出，由用户确认后才删除服务器上的文件；用户拒绝则从服务器把文件恢复到本地。
- F5.7 两端同时修改同一文件时不自动覆盖，保留双方版本并提示冲突。
- F5.8 显示最近同步时间、结果和待确认事项。执行后拉回失败时保留远程命令的真实输出、退出码，同时单独报告同步失败。
- F5.9 同步独立于 git 提交：Agent 或用户保存文件后即可按同步时机传到服务器，不需要先“保存版本”。
- F5.10 同步清单名称不拼接双端完整目录，较长配置路径不因状态单文件名超限失败。内部清单布局升级保持实际目标签名；旧基线须确认恢复并保留双方差异，未完成服务器文件任务仍可按原目标恢复。验收见[同步清单短名称](../guides/sync-session-names-acceptance.md)。

### F6 版本记录

- F6.1 本地副本使用本地 git，仓库就在工作区的本地文件夹里。文件夹已经是 git 仓库时直接复用，不新建。
- F6.2 只在用户点击“保存版本”时提交，没有改动不提交；界面显示尚未记录到版本的改动文件数。编辑器的“保存文件”只写文件，不创建 git 提交。
- F6.3 超过大小阈值的文件不提交，并给出提示。
- F6.4 可查看提交历史和 diff，可把单个文件或整次提交恢复回去，恢复后经同步回到服务器。
- F6.5 展示普通轮次启动前与同步收尾后两个本地快照的净差异，区分相对上次保存版本的当前改动；预存未提交内容未变不计入本轮，包含期间外部编辑，不将全部差异归因于 Agent。每工作区保留最多20轮，失败或未采集明确提示，不创建提交、不改 HEAD 或用户索引。
- F6.6 单文件差异支持真实旧/新侧行号反馈，加入当前会话待发送区后随下一条普通消息发送；保留正文，发送失败保留反馈，切换会话清理。最多20条，每条1–3000字符，总评论不超过12000字符；选择技能或命令时须先取消该选择。
- F6.7 放弃单文件须预览并明确确认，恢复当前 HEAD 或删除尚无提交的新增文件；独立暂存改动阻断，外部变化使预览失效。只操作磁盘，编辑缓冲保留，本地完成与服务器同步/删除待确认分别报告。

本轮快照、行反馈与单文件放弃的实现及证据见[改动验收](../guides/conversation-changes-acceptance.md)。本机快照不属于服务器备份；真实模型净变化、Edge版本恢复/放弃及实际SSH/rclone两端结果已补齐[完整链路验收](../guides/real-workflow-acceptance.md)。

### F7 会话记录

- F7.1 网页显示 Claude Code 和 Codex 本地已有的会话记录，按工作区筛选并显示所属 Agent，网页本身不另存对话。
- F7.2 删除会话：Codex 使用官方接口 `thread/delete`；Claude 使用 Agent SDK 的 `deleteSession`。删除须明确确认原生记录及相关子会话的影响；管理与对话准备、运行、同步收尾互斥，操作前验证原生 ID 与工作区目录。
- F7.3 Codex 支持归档列表、归档和恢复（`thread/list(archived: true)`、`thread/archive`、`thread/unarchive`）。归档条目先恢复后才能继续对话或重命名，恢复范围以官方结果为准。
- F7.4 打开历史会话时恢复其原 Agent 和官方会话 ID，通过对应运行时继续会话；显示历史与向运行时续接上下文分别处理。
- F7.5 两类会话均通过官方接口重命名；标题去除首尾空白后为 1–200 个字符。失败保留条目并允许核对重试，操作结果仅更新对应工作区与原生会话。

当前已实现 F2 主对话链路、原生能力目录/按钮选择、模型候选、上下文/压缩和 F7 会话管理，证据见 [Codex 对话验收](../guides/codex-conversation-acceptance.md)、[会话管理验收](../guides/session-management-acceptance.md) 与 [原生能力验收](../guides/native-capabilities-acceptance.md)。输入 `/` 自动补全已接入，见[补全验收](../guides/slash-completion-acceptance.md)。当前Codex0.160.0真实MCP审批、两类Agent编辑/实际SSH/rclone、原ID续接和真实长负载压缩已通过[完整链路验收](../guides/real-workflow-acceptance.md)；A8独立插件/CLI界面刷新仍待验。

### F8 轻量文件编辑

- F8.1 提供本地代码副本的文件列表 / 文件树和轻量编辑区，主要满足偶尔修改脚本、配置文件的需求；主工作方式仍是让 AI 编辑。
- F8.2 复用成熟编辑组件，支持语法高亮、搜索、修改标记和保存文件；不建设完整 IDE、调试器或服务器开发环境。
- F8.3 “本地代码”视图按同步范围浏览和编辑，不自动下载或打开远程大数据、权重和大型输出。被排除文件可通过 F10“服务器文件”视图直接管理，或由 Agent 通过远程工具按需查看；浏览和移动不要求文件先同步到本地。
- F8.4 保存文件写入本地副本，触发同步；成功后才显示文件已到达服务器。失败或待确认时显示相应状态，不要求用户手动 git 提交和服务器拉取。
- F8.5 未保存的编辑器内容与 Agent / 同步对同一文件的修改相遇时，提示用户处理，不静默覆盖；关闭未保存文件时提示保存或放弃。

### F9 服务器资源面板

- F9.1 网页提供持续刷新的资源概览与详细面板，不调用模型，不触发 AI 对话，不依赖 `nvitop`。
- F9.2 展示当前 SSH 服务器的 GPU 型号、利用率、显存已用 / 总量、温度、功耗，以及 CPU 使用率、系统负载、内存已用 / 总量、项目所在磁盘可用空间。
- F9.3 在权限和现有工具允许时，展示进程 PID、命令、CPU / 内存占用、关联 GPU 和显存用量；共享账号下不能仅凭账号区分本人的进程，不能将所有进程都标为当前工作区任务。
- F9.4 本地后端通过 SSH 读取服务器已有的 `nvidia-smi`、Linux 系统信息或命令，解析后推送网页；服务器不安装采集器或常驻监控服务。
- F9.5 显示采集主机、最近更新时间、采集失败或过期状态。缺少命令、权限或某项指标时显示不可用，不把失败显示成资源占用为零。
- F9.6 资源概览或详情可见时按秒级间隔刷新；多个工作区连接同一服务器时共享采样，页面隐藏或断开时暂停 / 降频，避免重复查询。具体刷新参数在实现时验证。
- F9.7 仅展示实际采样节点的数据。Slurm 任务可由用户通过对话或终端查询；第一版不自动遍历计算节点，也不以高频调度器轮询代替节点采样。

资源详情已接入固定目标HTTP、共享只读采样、独立时间/过期/空值和节点进程。默认5秒可见检查，产品设置提供2–60秒间隔及2–30秒超时；真实参数缩短与并发缓存复验见[设置验收](../guides/product-settings-acceptance.md)。真实SSH指标见[资源验收](../guides/resources-acceptance.md)；顶栏持续概览与详情单controller已接入，隐藏/网页断线停止检查，真实入口和布局证据见[导航验收](../guides/workspace-navigation-acceptance.md)。实际Agent执行、双PTY、资源、同步和远端文件任务组合通过[完整链路验收](../guides/real-workflow-acceptance.md)；隐藏状态仍沿用受控网页证据，未新增原生OS隐藏操作证据。

### F10 远端文件管理

- F10.1 文件区提供“本地代码”和“服务器文件”两个视图，后者列出远端实际目录，包含未同步的数据、权重和输出；显示名称、类型、文件大小、修改时间及同步范围标记。目录逐级、分批加载，打开时只取元数据，不读取文件正文或递归计算目录体积。
- F10.2 默认定位当前工作区服务器目录，支持面包屑、返回上级、返回工作区、刷新和路径输入；可前往同一 SSH 目标上当前账号有权限的其他目录，明确标记工作区外。浏览位置与同步范围独立：切换目录不修改工作区绑定的本地/远端目录，不新增同步映射或触发同步。主机和当前路径始终可见，不因切换对话而把已打开面板的操作转向另一目标。
- F10.3 用户可直接新建目录、重命名、移动、复制和删除文件或目录，提供右键菜单、“移动到…”目标选择及拖动移动，保留按钮和键盘替代入口；不要求先向 AI 发消息或另开终端，不产生模型调用。首版处理同一 SSH 目标内的操作，不扩展跨服务器传输。
- F10.4 移动和复制在服务器执行，文件内容不经本机中转。同一文件系统优先使用原生重命名；跨文件系统移动采用服务器已有能力完成复制、核对和移除源，保留失败或中断后的实际结果，不承诺跨文件系统原子性。浏览和移动大文件不改变自动同步阈值。
- F10.5 允许用户明确选择文件后按需下载，下载前展示大小与目标位置；通过流式传输反馈状态，下载结果不自动进入工作区同步目录或 Git，不因浏览、选择或移动触发下载。远端大型文件不自动在代码编辑器中打开。
- F10.6 默认不覆盖同名目标；删除和覆盖须确认具体主机、源路径、目标路径及目录影响范围，目录复制不隐式合并。操作前重新核对对象和目标，陈旧确认失效后要求重新核对。符号链接显示为链接，管理操作作用于链接本身，不隐式递归修改其指向内容；不提供删除或移动已配置工作区根目录的普通文件操作。
- F10.7 源或目标涉及本工具管理的同步范围时，先展示两端路径变化和影响，处理未保存编辑及相关冲突，再与这些工作区的同步串行协调。操作后刷新本地映射和同步状态，不能重新上传旧路径、静默覆盖编辑缓冲或自动生成 Git 提交；远端已完成但同步失败须分别反馈，重试同步不重复执行移动或删除。
- F10.8 源和目标均仅在服务器、且不影响同步范围的操作，不启动文件同步或把大文件拉回本地。移入同步范围的小文件按现有规则协调同步；混合包含代码与数据的目录不能整体视作“仅服务器”跳过检查。
- F10.9 复制、跨文件系统移动和下载展示独立操作状态、可用的进度、取消及结果核对入口；无可靠总量时不伪造百分比。断线、超时或取消不能等同于已回滚；报告已完成和未完成部分，刷新后再决定重试。关闭文件面板不暗中重发或取消已提交任务，不阻塞对话、终端和资源刷新。

F10 的双视图、SFTP 分页浏览、目录外导航、直接操作任务与显式下载已接入；同步范围的路径协调、编辑缓冲保护、持久阻断和不重放恢复已实现。证据见[服务器文件浏览验收](../guides/remote-files-browser-acceptance.md)、[操作阶段验收](../guides/remote-file-operations-acceptance.md)及[同步协调验收](../guides/remote-file-sync-acceptance.md)。真实同/跨文件系统大文件、混合目录迁移及实际rclone、目标冲突/链接/取消与Firefox磁盘下载已通过[完整链路验收](../guides/real-workflow-acceptance.md)；真实权限、预检后对象变化及独立SSH连接中断后的持久重开/核对/不重放已补齐[失败验收](../guides/remote-file-failure-acceptance.md)。Edge系统保存选择器仍未验，独立连接证据不扩大为共享池或全网络故障通过。

## 4. 约束

- 服务器上不存放任何 LLM 配置、密钥或对话记录，也不安装任何软件，只使用已有的 SSH 账号和工具。
- 网页只给本人在本机使用：后端只监听 `127.0.0.1`，校验访问令牌和请求来源。
- 本地后端采用 Node.js + TypeScript + Fastify，负责异步协调；项目为 Python 不要求更换网页后端，选型依据见设计决策 D19、D20。当前按 Node.js 本地启动，独立 `.exe`、安装器、Go 迁移和外部工具打包未作为第一版交付要求。
- 对话、终端、远端文件操作、同步和资源刷新可同时进行，耗时的 SSH / 外部命令不阻塞其他消息处理；同一会话只运行一轮，同一工作区的同步串行，影响相同路径的文件变更协调执行，不增加多用户或吞吐量承诺。
- 不复制 CloudCLI（AGPL-3.0）或 Pebrel（GPL-3.0）的代码；基于官方 Agent 接口和许可兼容的成熟组件实现，参考项目只用于布局与交互。
- 仅在用户通过设置页明确保存时修改本机 Claude Code、Codex 原生配置；普通会话不会改写全局配置，需要的工作区参数按会话注入。skills 与命令沿用对应 Agent 的本机 / 项目发现机制。
- SSH 支持密码和私钥。明文密码不写入工作区配置、磁盘、浏览器持久存储、日志、命令行参数、Agent 输入或对话记录；选择保存时仅允许本机系统加密后的独立凭据文件。模型服务令牌、网页访问令牌与 SSH 认证凭据分别处理。
- 仓库公开，文档和代码中不出现真实的服务器地址、端口、用户名或凭据。

## 5. 第一版不做

- 完整 IDE、调试器、多 Agent 编排、同一会话跨 Agent 切换
- 自动检测训练完成、自动结果分析或 Agent 自动续跑
- 集群全节点监控、服务器监控服务部署
- 多用户、登录系统、数据库
- 服务器端快照和备份
- 接入不兼容 Anthropic / OpenAI 接口的模型
- 手机端适配

## 6. 验收标准

| 编号 | 场景 | 通过条件 |
|---|---|---|
| A1 | 新建工作区后让 Agent 在服务器上执行 `hostname` | 对话中返回服务器的主机名 |
| A2 | 让 Agent 修改一个文件后在服务器上运行它 | 不手动 git 提交 / 拉取，服务器上运行的是修改后的版本 |
| A3 | 工作区包含大于阈值的文件 | 这些文件不因自动同步出现在本地，也不进入 git |
| A4 | 在本地删除一个已同步的文件 | 服务器上的文件在用户确认前保持不变；拒绝后文件恢复到本地 |
| A5 | 点击“保存版本”后恢复某个文件的历史版本 | 本地和服务器上都恢复为该版本 |
| A6 | 用 cc-switch 或本项目设置页更新服务商配置后发起新调用 | 无须重启项目，后续调用重读配置，新会话采用新默认模型；Codex 历史续接保留原模型，显式选择才覆盖，界面显示实际模型；无效语法或外部修改不被静默覆盖，运行中轮次继续原配置 |
| A7 | 对 Codex 重复 A1、A2 | 结果与 Claude 相同 |
| A8 | 在网页上删除一个会话 | 网页、VS Code 插件、命令行中都看不到该会话 |
| A9 | 完成一次完整使用后检查服务器 | 除同步文件及用户明确执行的新建、移动、复制等结果外，不遗留本工具的配置、凭据、常驻服务或隐式缓存；操作失败的残留须明确报告并提供处理入口 |
| A10 | 在网页终端运行服务器已有的交互工具 | 显示正常，可交互、可退出和调整窗口；`nvitop`、Slurm 均不作为安装前提 |
| A11 | Agent 尝试执行黑名单命令 | 命令被拒绝，对话中显示原因 |
| A12 | 未配置私钥时使用账号密码连接，保存后断开并重连或重启后端 | 可测试连接、浏览目录、远程执行、同步和使用终端；已保存密码可复用，取消保存后必须重新输入；明文不落盘、不出现在日志或对话，目标变化不复用旧凭据 |
| A13 | 在网页修改并保存脚本 | 文件写入本地并同步到服务器，保存文件不产生 git 提交；未保存编辑冲突不被静默覆盖 |
| A14 | 在 Claude / Codex 会话中选择 skill 或 `/` 命令 | 使用对应运行时真实能力；不支持的命令明确标注，不伪装成已执行 |
| A15 | 长会话续接与压缩 | 由官方运行时管理上下文；界面显示可获得的压缩状态；手动压缩走官方接口 |
| A16 | 创建和恢复两类 Agent 会话 | 新建时选择 Agent，恢复时保持所属 Agent，已有会话不能切换 Agent |
| A17 | 提交长任务后等待，再手动要求查看结果 | 等待期间不检测任务完成、不自动唤起 AI；用户发消息后可直接读取远程结果，并按需使用已有 Python / 项目环境分析，返回必要内容而非整份大数据 |
| A18 | 在对话 / 终端运行期间打开资源面板并改变服务器负载 | GPU / CPU / 内存指标持续刷新且标明采集主机与更新时间，不产生模型调用；断线或缺少工具时显示不可用 / 过期 |
| A19 | 执行前同步失败或存在待处理冲突 | 远程命令未执行，界面给出阻断原因；处理后可以重新执行 |
| A20 | 在服务器文件视图浏览并移动、复制未同步的数据文件或目录 | 右键/按钮及拖动入口可用；文件留在同一服务器，不经本机中转、不调用模型；同文件系统与跨文件系统路径均核对实际结果，大目录浏览不自动递归扫描 |
| A21 | 在远端重命名或移动同步范围内文件、混合目录，或移入/移出同步范围 | 两端路径和同步状态一致，旧路径不会重新生成，未保存编辑和已有冲突不丢失，不产生自动 Git 提交；远端完成但同步失败可单独恢复同步而不重复执行文件操作 |
| A22 | 远端文件操作遇到无权限、同名目标、符号链接、目标变化、断线或取消 | 删除/覆盖确认绑定实际目标，默认不覆盖或合并；链接不被隐式递归跟随；失败/未确认/部分完成准确显示，重新打开面板可核对结果，其他活动继续响应 |
| A23 | 显式下载一个未同步文件并切换本地/服务器视图 | 仅用户所选文件开始流式下载，可查看进度和取消，结果不自动纳入同步或 Git；普通浏览不传输正文，两视图的目标、路径和状态不混淆 |
