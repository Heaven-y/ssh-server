# 需求

更新日期：2026-10-09。本文描述当前正式规则；实际交付与验证范围见[路线图](../roadmap.md)和[最新验收](../guides/ui-usability-optimization-acceptance.md)，选型与替代关系见[设计决策](../engineering/decisions.md)。文档入口见[索引](../README.md)，旧过程材料不构成当前任务。

## 1. 背景

- 本地是 Windows 电脑，已安装并配置好 Claude Code、Codex。模型、服务商、密钥由本地配置决定（可能经由 cc-switch 切换）。
- 服务器可以联网，但访问不了 LLM 服务；本地通过 SSH 操作服务器。当前使用的 A100 服务器已有免密配置，正式产品也必须支持账号密码登录，不能以已配置私钥为前提。
- 服务器多人共用，同一个账号可能有多人使用，没有 root，没有 git。
- 服务器上的项目目录体积很大（数百 GB 到 TB 级），主要是数据、模型权重、输出文件；代码本身很小（几十 MB）。
- 现有操作需要在本地提交代码、服务器拉取、下载结果，再把结果交给 AI。目标是让这些操作在同一个网页工作区中完成。
- 默认按直接连接服务器的场景设计：SSH 连接目标也是远程命令和资源采集的目标。不预设登录节点与训练节点分离；若通过 Slurm 在其他节点运行任务，当前 SSH 节点的资源指标不能当作计算节点指标。

## 2. 目标

做一个只在本机运行的网页。在网页里和本机的 Claude Code 或 Codex 对话，让它们修改本地代码副本，自动同步到服务器，再远程运行、测试或提交训练任务。用户手动要求查看结果时，Agent 直接从服务器读取所需结果并分析。

主要编辑工作由 AI 完成；用户偶尔在网页里调整脚本。网页同时提供交互终端和持续刷新的服务器资源面板。代码同步与远程运行不要求用户手动提交 git，也不依赖服务器安装 git。

本地网页服务负责协调 Agent、SSH、文件同步和状态显示。统计、绘图及结果处理默认使用服务器已有的 Python / 项目环境，数据留在服务器，只返回分析所需的摘要或小文件。

## 3. 功能需求

### F1 工作区与 SSH 连接

- F1.1 新建工作区时选择三项：本地文件夹、已保存的服务器档案、服务器目录。顶栏“服务器”统一新增、编辑、删除与认证，可从 `~/.ssh/config` 显式导入；未登记Host不能直接用于工作区，不改写SSH config。
- F1.2 本地文件夹和服务器目录可逐级浏览或输入路径；成功浏览的当前目录就是“下一步”的选择，不重复要求“使用此目录”。创建优先草稿路径，无值从home开始；加载或失败时不能沿用旧浏览结果前进。服务器目录体积按需计算，不自动递归扫描。
- F1.3 服务器认证先独立验证连通性；新建工作区再验证两端目录和固定目标。密码档案可以在新增或明确编辑时保存密码，但保存不自动连接、不代表认证成功；连接仍须核对主机指纹。执行、同步、浏览、终端与资源从同一服务器档案解析认证方式，工作区和终端请求不携带认证字段。
- F1.4 每个工作区有唯一 ID，同名项目互不干扰。
- F1.5 侧栏移除工作区只删除本工具的配置，保留两端文件、Git、原生会话、服务器表和凭据。确认绑定当前配置；对话、同步和未完成文件任务须先处理，空闲后仅关闭所属终端和浏览通道。失败可重新核对重试，迟到成功不切走用户新选择。
- F1.6 支持账号密码认证和已有 SSH 私钥认证。已有免密方式可直接复用；密码模式不要求先配置私钥。
- F1.7 支持选择“保存密码”，使用 Windows 当前用户的系统加密能力保存在本机；明文仅在连接和明确编辑流程中按需进入内存。主动断开清理连接内存但保留已保存凭据，重连或后端重启后可以复用；取消“保存密码”会删除该目标的保存项并断开。凭据绑定实际地址、端口和账号，目标变化不能复用旧密码；认证失败提示重新输入，区分认证、连接与主机密钥失败。
- F1.8 保持服务器主机密钥校验，不因使用密码就跳过 `known_hosts` 校验；未知主机须提示用户确认指纹，密钥变化须明确提示并拒绝静默连接。
- F1.9 工作区创建只接受向导验证票，移除只接受绑定当前配置的明确确认；不提供绕过验证的直接创建、通用修改或直接删除入口。持久配置仅文件不存在时视为空，读失败、坏 JSON 或非法条目均阻断，不过滤后覆盖原数据。
  验证票仍为5分钟一次性票，但不显示具体截止时刻。到期就地重验、保留草稿并清除确认，必须重新核对后再次确认创建。自动重验由服务端比较原连接身份、认证代次、输入快照及目录绑定；同别名同路径的实际目标变化也必须拒绝，不能静默续验或自动创建。
- F1.10 多个工作区引用同一服务器时共享连接与凭据状态，管理入口列出受影响工作区。陈旧档案快照拒绝；被引用时不能删除或改变地址、端口、账号和私钥目标。重新认证、断开及档案修改须与活动请求、未解决文件任务和同步收尾互斥，不得在检查后竞态换向。
- F1.11 服务器管理采用可浏览列表，显示友好名称、目标、认证方式、连接/凭据状态及引用数量。选择只查看详情，编辑、连接和断开分别显式触发；不因切换条目重新认证，不新增列表轮询。
- F1.12 点击“编辑服务器”后按需读取已保存密码，默认掩码，可查看、隐藏和修改；确认保存才写入加密凭据。读取与保存绑定档案快照和凭据版本，取消、关闭、换目标后清理表单，迟到结果不得回填其他服务器。普通列表、状态、诊断、日志、URL、浏览器持久存储及长期查询缓存均不得包含明文；已有活动锁、引用限制和本机访问控制不减。

服务器档案与入口契约见[D37](../engineering/decisions.md#d37-本机入口与统一服务器档案2026-10-07)。向导保留两端分页浏览、实际指纹、一次性验证创建与首次同步确认，不维护旧工作区认证字段。

### F2 对话与原生 Agent 能力

- F2.1 创建会话时选择 Claude Code 或 Codex；一个会话固定使用一个 Agent，已有会话不能中途切换。需要另一个 Agent 时新建会话，不转换或拼接两种 Agent 的上下文。
- F2.2 流式显示回复、工具调用及结果、文件改动；可以中断正在进行的回复；可以继续历史会话。
- F2.3 Agent 请求需要确认的操作时，在网页上批准或拒绝；提交后等待后端确认，不得重复答复。超时、中断或原生请求取消后关闭审批入口，单次批准不扩大为会话级授权。
- F2.4 默认模型只有本机原生配置这一来源，不设网页`defaultModels`覆盖层；未显式选择时不向运行时传模型、地址或密钥覆盖。Codex新会话采用当前原生默认，历史续接保留会话模型。模型主菜单只列原生目录真实候选，清除覆盖、手填与刷新位于次级操作，不用候选首项、历史报告或强度推断模型ID。
- F2.5 会话区分Agent运行来源、最近报告的实际模型、原生会话配置和当前显式选择。左侧按Agent分组，仅单行标题与简洁状态；模型证据统一在输入区按需查看，未知值明确未报告，不冒充执行结果。一体圆角输入容器上部为正文，底栏左“+”、右模型/强度/上下文与圆形发送或停止；选项Enter不误发，正文Enter、Shift+Enter和组字保护保留。
- F2.6 上下文组织、历史续接和自动压缩由 Claude Agent SDK / Codex app-server 的官方运行时负责。网页不自行拼装全量历史作为提示词，不另建一套上下文压缩逻辑。
- F2.7 上下文用量和窗口与模型、强度同区，详情按需展开。Claude标明原生估计，Codex使用原生last用量与通知窗口，不将累计计量或配置窗口当作当前占用，不猜未知窗口或比例。手动压缩已有会话，成功必须由本轮原生事件确认，失败、中断及未确认不能标为完成。
- F2.8 技能选择器和`/`补全共用网页可执行筛选，目录按工作区/Agent隔离；已有会话等前置条件仍显示，不可用项与限制按需查看。网页只提交稳定ID，实际原生实例在调用前再次验证，拒绝未知、禁用、过期和歧义项。读取失败明确提示，不伪装空清单，也不阻断普通消息。
- F2.9 区分项目尚未接入、原生接口限制、已有等价网页操作和临时读取失败，不统一写成“请使用CLI”。已有模型、设置、新会话操作指向网页入口；输入`/命令`不代表已经支持。网页“搜索与操作”与Agent的`/`能力入口含义不同。
- F2.10 原生配置只编辑约定的Claude `settings.json`和Codex `config.toml`，保留未知字段与格式，保存前校验语法、revision和外部修改后原子写入。区分缺失、空文件与读取失败；空白内容可插入最小模板，但只改草稿，显式保存才创建。Claude模板为合法JSON，Codex模板为合法全注释TOML，不放假密钥、未核实端点或强制模型。原生登录可能不依赖配置文件；保存不等于登录或模型可用。配置正文不进入服务器、日志、Agent输入或浏览器持久存储。
- F2.11 Claude和Codex的模型/推理强度选择按Agent隔离，初次页面和新会话默认强度为`high`；`low / medium / high / xhigh / max`无需先选模型即可选择，Codex另保留所选目录模型的原生扩展档位。显式“自动”省略`reasoningEffort`并跟随原生，不是网页智能选档。Claude保留SDK合法枚举校验并直接映射`Options.effort`，不以目录读取或明确模型作为前置条件；有效档位由原生运行时判断，真实拒绝正常报错，不静默降级或重试，不改thinking、快模式或权限。

产品设置只提供默认Agent，不再保存或向新会话注入默认模型。初始和新会话的模型覆盖为空，用户显式选择与原生报告分离；已操作草稿和运行轮次不随迟到偏好切换。磁盘读取只定点剔除退休的`defaultModels`字段并保留其他有效偏好，公开API继续严格拒绝该字段及其他非法值。原生配置和产品偏好分开视图，环境检测只确认程序可执行，不判定版本兼容或模型已登录。

产品设置分为“对话与模型、文件同步、服务器资源、运行环境”，共用草稿、revision和保存，切类不丢值。隐藏分类错误自动切回并聚焦，409与未保存离开保护保留。原生配置入口只在“对话与模型”内，分别编辑Claude `settings.json`、Codex `config.toml`，不增加任意文件选择。

### F3 远程执行与结果读取

- F3.1 Agent 能在服务器的工作区目录下执行命令（运行、训练、测试、查看数据），返回标准输出、标准错误和退出码。
- F3.2 Agent 能查看未同步的大文件信息（大小、目录占用、头尾内容），并按用户要求从远程日志、结果表格等文件读取必要内容。大结果不必全部下载，也不必由用户手动上传给 AI。
- F3.3 执行前自动把本地改动同步到服务器，执行后把服务器上新增或修改的同步范围内小文件拉回本地。执行前同步失败、或存在影响本次执行的未处理删除 / 冲突时，暂停远程执行，显示原因；不能继续运行旧代码。
- F3.4 命令黑名单：默认禁止 `sudo`、`su`，对 `/`、`~` 或整个项目目录的 `rm -rf`，`mkfs`、`dd`、`shutdown`、`reboot`、`kill -9 -1`、`chmod -R 777`，改写 `~/.ssh/authorized_keys` 等。每个工作区可追加规则或停用某条默认规则；命中时拒绝执行并在对话中说明原因。
- F3.5 Agent 可以在本地执行命令（如 `git diff`、`grep`、格式化），但项目的运行、训练、测试、查看数据须使用远程执行工具，由注入给 Agent 的指令约束。
- F3.6 长时间任务使用服务器已有的 `nohup` 或 Slurm 等方式提交，返回启动信息或任务 ID；不要求 SSH 工具一直等待整个训练结束。
- F3.7 训练进度、完成情况和结果分析由用户手动发消息触发，例如“看一下这次训练的结果”。不自动检测任务完成，不自动发消息、唤起 Agent 或续跑分析。文件定时同步和 F9 资源刷新不改变此约定。
- F3.8 用户要求统计、绘图或处理结果时，默认通过 SSH 使用服务器已有的 Python / 项目环境；新分析脚本先在本地编辑并同步，再远程执行。大数据保持远程，仅返回必要统计、日志、结果表或小图文件；缺少环境或依赖时明确报告，不自动安装。

工作区规则管理提供默认启停/恢复、最多20条自定义程序名或命令字符串字面规则，版本保存及执行拒绝贯通。规则区分大小写、不支持正则，只防误操作；坏配置（包括null）拒绝执行，网页终端及已检查在途命令不受新增规则追溯影响。

自定义规则默认折叠为“高级：自定义拦截（可选 · N条）”，通常无需配置。教程只解释`program`基本名与`contains`字面串、大小写及误拦风险，不执行示例、不自动添加规则。校验失败自动展开并定位字段，修正时不收起输入区。

### F4 网页终端

- F4.1 在网页里打开服务器的交互式终端，默认进入工作区对应的服务器目录。服务器已经安装的 `sinfo`、`squeue`、`nvidia-smi`、`nvitop`、`htop` 等命令及全屏程序应正常显示、可交互；不要求这些工具全部存在。
- F4.2 可同时打开多个终端标签，调整终端显示区域大小。终端外观与多标签、分屏等交互参考 [Pebrel](https://github.com/Kuddev/pebrel)，具体布局见界面文档。
- F4.3 终端是用户本人操作，不受命令黑名单限制。
- F4.4 终端是通用 SSH shell，不绑定 `nvitop`，资源概览可以直接使用 F9 面板。

终端保持固定目标、目录确认、独立PTY、背压、标签/分屏、复制粘贴与稳定宿主，取舍见[设计决策第5节](../engineering/decisions.md#5-终端参考的使用方式)。原生OS输入法未观察的历史边界不写成通过。

### F5 同步

- F5.1 只同步代码和小文件。排除规则由扩展名列表（如 `*.pkl`、`*.pt`、`*.pth`、`*.joblib`、`*.npy`、`*.RData`、`*.zip`）和大小阈值（默认 10 MiB，即 10 × 1024 × 1024 字节）组成，可在网页上调整。
- F5.2 新建工作区时预览：将同步的文件数和总大小、被排除的大文件统计。预览由用户触发，不自动递归扫描全部大数据目录。
- F5.3 同步时机：执行远程命令前后、普通消息或技能轮次结束后、手动点击、工作区打开期间定时拉取；纯上下文查询/压缩命令不编辑项目，不触发结束同步。定时拉取只更新文件，不检测任务完成或触发 AI 分析。
- F5.4 本地 `.git` 不同步到服务器。
- F5.5 不做任何备份或服务器端快照。
- F5.6 防误删：同步前检查本地删除了哪些文件，有删除时暂停该部分同步，在网页上列出，由用户确认后才删除服务器上的文件；用户拒绝则从服务器把文件恢复到本地。
- F5.7 两端同时修改同一文件时不自动覆盖，保留双方版本并提示冲突。
- F5.8 显示最近同步时间、结果和待确认事项。执行后拉回失败时保留远程命令的真实输出、退出码，同时单独报告同步失败。
- F5.9 同步独立于 git 提交：Agent、外部编辑器或同步流程改动文件后即可按同步时机传到服务器，不需要先“保存版本”。
- F5.10 同步仅维护当前`version=1`、`mirror-v1`目标签名与`combine-v1`清单布局。短逻辑根避免双端完整目录拼入状态单文件名；无基线的首次初始化合法，非空基线缺签名或已有签名但布局缺失/不匹配时明确拒绝，不能借初始化确认迁移或改写旧状态。当前格式的中断恢复和未完成文件任务核对保留，现行裁定见[D36](../engineering/decisions.md#d36-当前实现收敛与范围控制2026-10-07)。
- F5.11 同步及创建前同步预览必须使用 SSH 实际确认的远端目录，不裁剪目录名空白，不把不完整或截断输出当作路径。Windows rclone 无法保留的反斜杠根须明确拒绝，不自动替换分隔符、改名或访问其他目录；普通 SSH 浏览及用户终端不受此工具限制。
- F5.12 产品同步过滤与大小默认只复制给新工作区；已有工作区通过同步“规则”修改自己的规则，不被全局默认覆盖。规则变化继续经过现有重建、删除确认与冲突保护；定时拉取间隔仍是保存后生效的全局偏好。
- F5.13 页面自动文件同步默认及缺失回退为60秒，可设5–300秒；显式保存的自定义值不静默迁移。修改偏好按revision保存并撤销旧计时器，页面隐藏、忙或待确认时暂停。原3秒同步状态查询、手动同步、执行前后及保存后同步不随之延迟，资源采样仍使用独立设置。

### F6 版本记录

- F6.1 本地副本使用本地 git，仓库就在工作区的本地文件夹里。文件夹已经是 git 仓库时直接复用，不新建。
- F6.2 只在用户点击“保存版本”时提交，没有改动不提交；界面显示尚未记录到版本的改动文件数。网页不提供本地保存入口，写盘不创建 git 提交。
- F6.3 超过大小阈值的文件不提交，并给出提示。
- F6.4 可查看提交历史和 diff，可把单个文件或整次提交恢复回去，恢复后经同步回到服务器。
- F6.5 展示普通轮次启动前与同步收尾后两个本地快照的净差异，区分相对上次保存版本的当前改动；预存未提交内容未变不计入本轮，包含期间外部编辑，不将全部差异归因于 Agent。每工作区保留最多20轮，失败或未采集明确提示，不创建提交、不改 HEAD 或用户索引。
- F6.6 单文件差异支持真实旧/新侧行号反馈，加入当前会话待发送区后随下一条普通消息发送；保留正文，发送失败保留反馈，切换会话清理。最多20条，每条1–3000字符，总评论不超过12000字符；选择技能或命令时须先取消该选择。
- F6.7 放弃单文件须预览并明确确认，恢复当前 HEAD 或删除尚无提交的新增文件；独立暂存改动阻断，外部变化使预览失效。只操作磁盘，编辑缓冲保留，本地完成与服务器同步/删除待确认分别报告。

本机轮次快照用于查看净变化，不属于服务器备份；文件保存、版本恢复和服务器同步分别反馈结果。

### F7 会话记录

- F7.1 网页按工作区分别展示Codex与Claude原生会话，每组置顶项优先、其余按更新时间排序；行内仅标题和简洁状态，身份、时间和模型证据保留于可访问名称/详情。网页不另存对话正文。
- F7.2 删除会话：Codex 使用官方接口 `thread/delete`；Claude 使用 Agent SDK 的 `deleteSession`。删除须明确确认原生记录及相关子会话的影响；管理与对话准备、运行、同步收尾互斥，操作前验证原生 ID 与工作区目录。
- F7.3 Codex 支持归档列表、归档和恢复（`thread/list(archived: true)`、`thread/archive`、`thread/unarchive`）。归档条目先恢复后才能继续对话或重命名，恢复范围以官方结果为准。成功空状态显示“暂无归档会话”；中性文案不增加Claude归档能力。
- F7.4 打开历史会话时恢复其原 Agent 和官方会话 ID，通过对应运行时继续会话；显示历史与向运行时续接上下文分别处理。
- F7.5 两类会话均通过官方接口重命名；标题去除首尾空白后为 1–200 个字符。失败保留条目并允许核对重试，操作结果仅更新对应工作区与原生会话。
- F7.6 “更多”先打开菜单，再进入对应单动作表单或确认；不同时展示重命名、删除和归档表单。删除仍须勾选确认，Codex归档/恢复保留；菜单和弹窗支持键盘及稳定触发点焦点恢复。
- F7.7 置顶/取消置顶仅改变当前浏览器的排序元数据，按工作区、Agent、原生会话ID隔离，不修改原生历史；损坏或不可用的本地存储不阻塞会话使用。
- F7.8 复制当前网页可打开的深度链接，包含工作区、Agent和原生ID，不含正文或凭据；首次打开及hash变化严格校验目标，运行或管理中不切走当前会话，迟到历史不覆盖新选择。剪贴板不可用时提供手动复制。未核实的原生URI不猜造，链接不承诺Agent自动读取或注入上下文，不增加“引用旧会话”流程。
- F7.9 会话菜单支持从末尾原生分叉，已结束位置提供“从此处分叉”；指定点只接受服务端`turn_end.forkPoint`。Codex调用`thread/fork.lastTurnId`，Claude调用`forkSession.upToMessageId`，均inclusive；源会话不变、不回滚项目文件。服务端复核点归属、结束状态、新ID和目录，并全程持有源会话锁；请求发出后网页断开不等于撤销。成功刷新对应列表，仅选择代次未变且当前空闲时打开新会话。

A8以网页及官方API/原生记录核对为准，VS Code与CLI界面只是可选检查手段，不是额外交付目标。

### F8 轻量文件编辑

- F8.1 提供本地代码副本的文件列表 / 文件树与只读文件查看，用于核对当前内容；修改由 AI、外部编辑器或同步流程完成，网页不提供本地写入。
- F8.2 复用成熟代码组件提供语法高亮与搜索用于查看；不建设完整 IDE、调试器、保存入口或服务器开发环境。
- F8.3 “本地代码”视图按同步范围浏览和查看，不自动下载或打开远程大数据、权重和大型输出。被排除文件可通过 F10“服务器文件”视图直接管理，或由 Agent 通过远程工具按需查看；浏览和移动不要求文件先同步到本地。
- F8.4 本地文件改动由 Agent、外部编辑器或同步流程写盘后同步；网页只读取当前内容，不显示“已保存”或“已到达服务器”，也不要求用户手动 git 提交和服务器拉取。
- F8.5 本地读取期间文件被改写时丢弃该次快照并提示重新读取，不显示可能混合的正文。
- F8.6 本地与服务器文件列表采用单击选择、双击/Enter打开、方向键导航与右键入口；默认回到所属工作区根。本地仅浏览，不新增独立的新建、移动、删除后端。
- F8.7 文件与资源采用独立停靠分屏，各有顶栏开关与收起入口，可以同时打开，不互相覆盖或改为窄屏modal。调整尺寸、收起、方向切换或切聊天工作区只改变呈现，保留已打开文件、固定文件工作区与PTY；隐藏文件停止目录GET并取消在途请求。关闭文件面板不涉及写入确认。
- F8.8 ≥1600px采用“工作区/会话｜对话｜资源｜文件”，1280–1599px右侧资源/文件上下停靠，960–1279px默认自动收起左栏；允许用户主动展开，不覆盖其持久折叠偏好。分隔线支持鼠标与键盘调节；宽窄工具尺寸与比例分别有界记忆，复位不改变主题或左栏宽度。通常对话最小480px，紧凑窗口主动展开左栏时允许320px，不强塞四列，不提供自由浮窗。
### F9 服务器资源与只读作业

- F9.1 资源独立停靠，不与文件互斥。顶栏仅保留紧凑资源开关，突出所属工作区SSH状态；正常本机WebSocket连接不常驻，异常和重连入口仍可见。≥1280px有工作区时默认打开资源，960–1279px首屏不强开；保留960px最小支持、明暗主题及默认240px侧栏（200–320px）。
- F9.2 GPU逐卡优先展示型号、利用率、显存已用/总量、温度和功耗，其后是CPU、内存、负载和项目所在磁盘可用空间。友好服务器名称与工作区常态可见，目标和采样详情按需核对。
- F9.3 不展示节点进程表，也不根据SSH账号推断“我的任务”。资源与Slurm作业是独立信息，不能将当前SSH节点指标当作作业计算节点指标。
- F9.4 本机后端通过SSH读取已有`nvidia-smi`、Linux系统信息和固定只读命令；不调用模型，不安装采集器或常驻服务，不依赖`nvitop`。
- F9.5 资源采样时间、过期/失败/暂停和不可用字段如实显示；缺少工具、权限或样本不能显示成零，高利用率不自动等同故障。仪表采用明暗蓝、青和少量紫色，橙红仅用于异常，状态不只靠颜色表达。
- F9.6 默认5秒可见检查，间隔2–60秒、超时2–30秒独立可配；资源面板自身隐藏、页面隐藏或网页断线时暂停并取消在途网页查询。打开文件不隐藏资源、不停止资源或Slurm活动；两者的active只取资源自身可见性及页面/连接条件。后端按实际连接与认证共享有界采样，不在顶部或文件面板启动第二套控制器。
- F9.7 Slurm只在首次打开或用户手动刷新时查询当前SSH账号，唯一命令为`LC_ALL=C squeue --noheader --user="$(id -un)" --format="%.18i %.9P %.24j %.8u %.2t %.10M %.6D %R"`。8秒覆盖全程，stdout/stderr合计512 KiB，最多展示200行作业输出；删除JSON解析，不维护双协议或回退，不增加安装、全用户查询、节点遍历、提交、取消或自动作业轮询。
- F9.8 非空输出补固定列头：JOBID、PARTITION、NAME、USER、ST、TIME、NODES、NODELIST(REASON)，保留原生文本对齐，不推导时限或精确作业数。等宽文本区内部双向滚动，独立显示作业更新时间；超过200行明确标“行”，超字节拒绝整份。可用、无警告空输出、不可用和失败分开；成功stderr警告保留通用提示，警告空输出不宣称确定无作业。共享账号可见作业不等于个人任务。
- F9.9 资源和作业绑定固定工作区、真实连接和认证代次；目标变化、取消及迟到结果不能回填新身份。网页只观察公开档案/凭据变化，不接收内部认证摘要；已知变更立即清除旧作业并要求手动刷新。

停靠规则见[D42](../engineering/decisions.md#d42-停靠工作台会话操作与设置收敛2026-10-09)，最终验证统一见[最新验收](../guides/ui-usability-optimization-acceptance.md)；D39–D41历史结果不作为本项通过证明。

### F10 远端文件管理

- F10.1 文件区提供“本地代码”和“服务器文件”两个视图，后者列出远端实际目录，包含未同步的数据、权重和输出。服务器返回的点文件、点目录默认展示，不设隐藏项开关，不改变同步范围。列表紧凑显示名称与大小，其余元数据通过“属性”按需查看。普通浏览只取当前层元数据，不读取正文或递归计算体积；文件夹优先、名称自然排序，在分页前完成有界排序。
- F10.2 默认定位当前工作区服务器目录，支持面包屑、返回上级、返回工作区、刷新和路径输入；可前往同一 SSH 目标上当前账号有权限的其他目录，明确标记工作区外。浏览位置与同步范围独立：切换目录不修改工作区绑定的本地/远端目录，不新增同步映射或触发同步。主机和当前路径始终可见，不因切换对话而把已打开面板的操作转向另一目标。
- F10.3 用户可直接新建目录、重命名、移动、复制和删除文件或目录，提供右键菜单、“移动到…”目标选择及拖动移动，保留按钮和键盘替代入口；不要求先向 AI 发消息或另开终端，不产生模型调用。首版处理同一 SSH 目标内的操作，不扩展跨服务器传输。
- F10.4 移动和复制在服务器执行，文件内容不经本机中转。同一文件系统优先使用原生重命名；跨文件系统移动采用服务器已有能力完成复制、核对和移除源，保留失败或中断后的实际结果，不承诺跨文件系统原子性。浏览和移动大文件不改变自动同步阈值。
- F10.5 允许用户明确选择文件后按需下载，下载前展示大小并由 File System Access API 选择保存位置；HTTP 流逐块写入，文件成功关闭后才显示完成。当前浏览器没有保存 API 时明确不可用，不转交下载管理器或提供另一条下载路径。下载结果不自动进入工作区同步目录或 Git，不因浏览、选择或移动触发下载；远端大型文件不自动在代码查看区打开。
- F10.6 默认不覆盖同名目标；删除和覆盖须确认具体主机、源路径、目标路径及目录影响范围，目录复制不隐式合并。操作前重新核对对象和目标，陈旧确认失效后要求重新核对。符号链接显示为链接，管理操作作用于链接本身，不隐式递归修改其指向内容；不提供删除或移动已配置工作区根目录的普通文件操作。
- F10.7 源或目标涉及本工具管理的同步范围时，先展示两端路径变化和影响，核对已有冲突，再与这些工作区的同步串行协调。操作后刷新本地映射和同步状态，不能重新上传旧路径或自动生成 Git 提交；远端已完成但同步失败须分别反馈，重试同步不重复执行移动或删除。
- F10.8 源和目标均仅在服务器、且不影响同步范围的操作，不启动文件同步或把大文件拉回本地。移入同步范围的小文件按现有规则协调同步；混合包含代码与数据的目录不能整体视作“仅服务器”跳过检查。
- F10.9 复制、跨文件系统移动和下载展示独立操作状态、可用的进度、取消及结果核对入口；无可靠总量时不伪造百分比。断线、超时或取消不能等同于已回滚；报告已完成和未完成部分，刷新后再决定重试。关闭文件面板不暗中重发或取消已提交任务，不阻塞对话、终端和资源刷新。
- F10.10 当前任务记录的 `syncRequired`、`dispatched` 为必填布尔值。记录或目录不可读、格式不支持、ID不匹配均保留原数据并阻断任务及依赖它的移除检查，不忽略记录后放行。
- F10.11 创建向导两端目录和服务器文件按当前层完整快照排序，每页200项，上限10000项或4 MiB元数据。超限明确拒绝不完整列表并提示进入更具体子目录，不把单页排序冒充全局排序。本地代码保留最多扫描5000项、展示500项的边界，先对扫描结果排序再截取，超限标明截断。

浏览、操作与同步协调分别保持固定身份和不重放保护。旧Firefox下载分支不属于当前保存API；OS选择器未观察事实不扩大为已通过，也不把独立连接检查扩大为共享池或全网络故障证据。

## 4. 约束

- 服务器上不存放任何 LLM 配置、密钥或对话记录，也不安装任何软件，只使用已有的 SSH 账号和工具。
- 网页只给本人在本机使用，直接打开本机端口即可。后端仅本机监听；同源自动握手建立HttpOnly/SameSite=Strict会话，API/WS继续校验Cookie、Host与Origin，内部工具使用独立令牌。拒绝跨站握手和外部iframe，不保留带token的登录入口。
- 本地后端采用 Node.js + TypeScript + Fastify，负责异步协调；项目为 Python 不要求更换网页后端，选型依据见设计决策 D19、D20。当前按 Node.js 本地启动，独立 `.exe`、安装器、Go 迁移和外部工具打包未作为第一版交付要求。
- 对话、终端、远端文件操作、同步和资源刷新可同时进行，耗时的 SSH / 外部命令不阻塞其他消息处理；同一会话只运行一轮，同一工作区的同步串行，影响相同路径的文件变更协调执行，不增加多用户或吞吐量承诺。
- 不复制 CloudCLI（AGPL-3.0）或 Pebrel（GPL-3.0）的代码；基于官方 Agent 接口和许可兼容的成熟组件实现，参考项目只用于布局与交互。
- 仅在用户通过设置页明确保存时修改本机 Claude Code、Codex 原生配置；普通会话不会改写全局配置，需要的工作区参数按会话注入。skills 与命令沿用对应 Agent 的本机 / 项目发现机制。
- SSH 支持密码和私钥。明文密码不写入工作区配置、磁盘、浏览器持久存储、日志、命令行参数、Agent 输入或对话记录；选择保存时仅允许本机系统加密后的独立凭据文件。模型服务令牌、本机进程会话秘密与 SSH 认证凭据分别处理。
- 仓库公开，文档和代码中不出现真实的服务器地址、端口、用户名或凭据。
- 首次使用默认浅色，明显的深浅主题按钮记住已有选择；切换不销毁只读预览或PTY。启动有界并行检查Node.js、Claude实际SDK入口、Codex、Git和rclone是否可执行，GET复用报告、手动POST刷新。工具全部可用时主界面不显示成功条或占位，缺失/失败保留设置入口；设置内保留状态、版本和官方指引。版本仅展示；超时、输出截断、非零退出和启动失败不可标为可用。不自动安装、升级或调用模型；既有Git/rclone业务执行要求保持不变。
- 常态提示保持简短，匹配教程、原生配置填写说明等按需展开；精简冗余说明不削弱删除、覆盖、冲突、未保存、目标/认证变化及实际失败的提示和保护。

## 5. 第一版不做

- 完整 IDE、调试器、多 Agent 编排、同一会话跨 Agent 切换
- 自动检测训练完成、自动结果分析或 Agent 自动续跑
- 集群全节点监控、服务器监控服务部署
- 多用户、登录系统、数据库
- 服务器端快照和备份
- 接入不兼容 Anthropic / OpenAI 接口的模型
- 手机端适配
- 旧版本接口、旧状态迁移、多套下载实现，以及把 VS Code / CLI 等外部检查手段建设为产品功能

## 6. 验收标准

| 编号 | 场景 | 通过条件 |
|---|---|---|
| A1 | 新建工作区后让 Agent 在服务器上执行 `hostname` | 对话中返回服务器的主机名 |
| A2 | 让 Agent 修改一个文件后在服务器上运行它 | 不手动 git 提交 / 拉取，服务器上运行的是修改后的版本 |
| A3 | 工作区包含大于阈值的文件 | 这些文件不因自动同步出现在本地，也不进入 git |
