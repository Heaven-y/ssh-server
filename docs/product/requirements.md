# 需求

更新日期：2026-11-04。产品名 **AgentDeck**（原 `ssh-server`）。本文按 M1 已交付的能力描述当前产品；M1.5、M2、M3、M4 的内容单列为后续里程碑，不作为现状。设计依据见[设计文档](../superpowers/specs/2026-11-03-native-cli-workbench-design.md)，取舍见[设计决策](../engineering/decisions.md)，文档入口见[索引](../README.md)。

> M1 是本机网页形态的只读工作台：能看项目、会话列表与原生历史，不能发消息。Electron 桌面壳、输入框、原生配置编辑与启动环境都还没有交付，分别属于 M1.5、M2 与 M3。

## 1. 背景

- 日常在 Windows 本机使用 `claude`、`codex`、`agy` 三个 CLI，会话分别落在 `~/.claude`、`~/.codex` 与 `~/.gemini/antigravity-cli`，管理不同项目的会话要在多个终端窗口间切换。
- 用户要的是桌面工作台形态，不是命令行加参数；但 M1 先把网页外壳跑通，Electron 后补。
- 另有 SSH 需求：连服务器看进程、看资源、看文件、跑终端。这部分沿用已有 ssh console 的能力。
- 服务器上不跑 Agent、不存模型配置，SSH 只是人的工具。

## 2. 目标与形态

- 当前形态：本机后端 + 浏览器界面，后端只监听回环地址；双击即开的 Electron 窗口属于 M1.5。
- 会话与配置仍归各 CLI 所有。本产品不含模型引擎、不存对话正文、不另造配置体系。
- M1 的主路径是「项目 → 按 CLI 分组的会话 → 只读历史」；对话输入与服务器面板的档案化改造留给后续里程碑。

## 3. 功能需求

### F1 项目

- F1.1 项目是 `{ id, name, dir, server?, remoteDir? }`。`dir` 是本地绝对路径，必须真实存在；相对路径与不存在的目录都拒绝。
- F1.2 `server` 与 `remoteDir` **同进同退**：只给其中一个会被拒绝，两个都不给表示纯本地项目。绑定服务器时，`server` 必须是已登记的服务器档案别名。
- F1.3 接口支持新增、改名、改目录与移除。移除只删本工具的配置，不动磁盘文件，也不动 CLI 的原生会话。M1 界面只接入了「添加项目」：改名、移除与绑定服务器的表单都还没做，因此界面新建的项目一律是未绑定服务器的纯本地项目；已绑定的项目只可能来自迁移过来的旧配置。
- F1.4 首次启动做两层旧数据迁移：先把旧目录 `%LOCALAPPDATA%\ssh-server` 的同名配置复制到 `%LOCALAPPDATA%\AgentDeck`，再把旧字段 `localDir` / `sshHost` 改写为 `dir` / `server`，其余旧字段（`sync`、`policy` 等）丢弃。新目录已有同名文件不覆盖，旧目录保留，坏行只跳过该行并备份原文件为 `.bak`。
- F1.5 项目列表不返回密码；服务器绑定只保存档案别名与默认目录。

### F2 会话发现与归属

- F2.1 三个 CLI 各按原生接口枚举只读会话：Claude 用 Agent SDK 的会话方法，Codex 用 `app-server` 的 `thread/list`，Antigravity 读本机 SQLite 的 `conversation_summaries` 表。不导入、不复制、不另存正文。
- F2.2 Claude 与 Codex 按原生 `cwd` 归属，Antigravity 没有 `cwd`，按 `workspace_uris` 归属。比较前把路径规范化为绝对路径、统一分隔符；Windows 路径不区分大小写。候选路径等于项目目录或位于其下都算命中；多个项目同时命中时取项目配置顺序里的第一个。
- F2.3 解析不出归属的会话 `projectId` 为 `null`，界面默认隐藏；打开「显示其他目录的会话」后集中列出，并提供「加为项目」入口。绝不把无归属会话塞进第一个项目。
- F2.4 会话标题为空时显示「未命名会话」；列表按最近活动时间倒序，组内不置顶、不猜模型。会话正文不进入本产品存储。
- F2.5 读取单条历史时复核原生 id 与 `cwd`；不属于当前项目的会话返回「该 Agent 在当前项目目录中没有此会话」，不返回正文。
- F2.6 Antigravity 的历史是私有轨迹格式：列表能给出标题、时间与归属，读取正文固定返回 501 `session_not_replayable`，界面按能力边界说明，不伪造事件。

### F3 会话历史（只读）

- F3.1 M1 主区只有会话头与历史时间线，**没有输入框、发送、停止或审批入口**。发消息、流式回合与中断属于 M2。
- F3.2 Claude 与 Codex 的历史按原生记录渲染成文本、工具调用与工具结果；Antigravity 走 F2.6 的说明页。
- F3.3 不渲染 diff、不做「本轮改动」聚合、不做行内反馈；工具卡片只显示原生事件给出的路径与动作。
- F3.4 加载中、空历史、读取失败与不可回放是四种互斥状态，各自给出可读文案与可用的重试入口；切换会话时取消旧读取，迟到结果不覆盖当前选择。
- F3.5 历史一次渲染全部行，不做虚拟列表与贴底跟随；长会话的渲染成本未优化，属 M1 已知限制。
- F3.5 同一会话的正文只来自 CLI 存储。本产品不落库、不做事件投影缓存、不导出。

### F4 原生配置编辑

> 状态：M3 规划，未交付。当前只有面向 Claude `settings.json` 与 Codex `config.toml` 的局部后端能力，不构成 M1 验收。

- F4.1 M3 直接编辑 CLI 的原生配置文件，覆盖用户级与当前项目两层；文件清单以本节的规划为准，不在 M1 实现。
- F4.2 保留未知字段与格式，保存前校验语法，外部修改后要求重新加载；区分「文件不存在」「空文件」「读取失败」。
- F4.3 配置文件里的密钥字段默认掩码，用户可显式展开；日志、错误与接口响应中始终不出现明文。
- F4.4 不提供本产品侧的配置覆盖层：要么改原生文件，要么不改。

### F5 启动环境

> 状态：M3 规划，未交付。M1 的运行环境页只展示三个 CLI 的探测结果，不注入变量。

- F5.1 每个 CLI 一组可选环境变量，在该 CLI 子进程启动时注入；值用 Windows 当前用户加密保存。
- F5.2 只允许白名单变量名，不接受 `PATH`、`NODE_OPTIONS`、`PYTHONPATH` 这类会改变进程加载行为的变量。
- F5.3 Antigravity 的端点与密钥只能靠启动时注入；`GEMINI_API_KEY` 缺失时探测应报「凭据未配置」。

### F6 服务器控制台

- F6.1 沿用现有 ssh console：多标签/分屏 SSH 终端、资源采样、Slurm 文本查询、服务器文件浏览与新建/重命名/移动/复制/删除、服务器档案管理（密码或私钥、主机指纹确认、Windows 加密保存）。Slurm 查询放在资源视图内，不单独占标签。
- F6.2 M1 的面板入口仍绑定项目：只有同时配置了 `server` 与 `remoteDir` 的项目才能新建终端标签，资源与文件视图也只在绑定后可用；未绑定时面板仍可打开，但终端不能新建标签、资源与文件只显示绑定提示。又因为 M1 界面没有绑定表单（F1.3），实际能用的只有迁移来的已绑定项目；以服务器档案为身份、不绑项目也能用，是 M3 的改造。
- F6.3 服务器文件下载已移除：接口与界面都没有下载入口，文件仍可新建、重命名、移动、复制、删除。
- F6.4 保持主机密钥校验，不因使用密码跳过 `known_hosts`：未知主机提示确认指纹，密钥变化拒绝静默连接。
- F6.5 明文密码不进入项目配置、磁盘普通文件、浏览器持久存储、日志、命令行参数或对话记录；选择保存时只写本机系统加密后的独立凭据文件。
- F6.6 终端是用户本人的通用 SSH shell，不受命令规则限制；命令黑名单已随 MCP 桥删除，不再有 Agent 远端执行通道。

### F7 桌面应用形态

> 状态：M1.5 规划，未交付。当前入口是浏览器访问本机后端。

- F7.1 Electron 主进程在 `apps/desktop` 拉起本机后端并用窗口加载；preload 只暴露窄接口。
- F7.2 后端仍只监听回环地址；关窗后后端退出，单实例运行。
- F7.3 浏览器访问同一地址保留为调试手段，不作为产品入口。

### F8 界面与外观

- F8.1 三段式：左栏项目与会话、主区历史、右侧服务器面板（可收起）。没有第四段，也没有同步、版本或本地文件入口。
- F8.2 视觉沿用 DSH 语气：中性灰阶、细边框、克制高亮、路径与代码用等宽字体、紧凑但留白；默认浅色，可切深色，偏好有界记忆。
- F8.3 没有输入区、没有改动视图、没有行内反馈；这些不是加载失败，而是 M1 的明确边界。
- F8.4 空态要可操作：没有项目时引导添加目录；没有选中会话时说明先选会话；CLI 不可用时说明原因。
- F8.5 `Ctrl+K` 命令面板只保留当前范围的动作：新建会话、打开终端、查看资源、设置、主题、折叠侧栏、切换项目与搜索会话。同步、版本、本地文件相关命令已删除。

## 4. 约束

- **绝不自动发请求**：一档只做 `--version`、`--help`、Codex schema 生成与读配置/会话；二档能力目录只在用户点「刷新能力」时读取并缓存；三档 prompt 只在点发送时发生。M1 没有二、三档入口。
- **按能力探测，不比较版本号**：`--version` 只用于显示；关键选项或 schema 缺失就标「接口变化」，不写 `if (version >= x)`。
- **单一真相**：正文只存在 CLI 存储里；本产品只保存会话索引、界面偏好、项目、服务器档案与加密凭据。
- **只有一条接入路径**：结构化事件，不把 CLI 的终端界面塞进应用；要用 TUI 就直接用 CLI。
- 技术栈：后端 Node.js + TypeScript + Fastify + zod；前端 React 19 + Vite + Tailwind 4；终端 xterm；编辑器 CodeMirror。
- 仓库公开：文档与代码中不出现真实服务器地址、端口、用户名或凭据；示例用 `my-server`、`~/projects/demo`。
- 不复制 CloudCLI（AGPL-3.0）或 Pebrel（GPL-3.0）的代码。

## 5. M1 不包含

| 里程碑 | 内容 |
|---|---|
| M1.5 | Electron 桌面壳、`electron-vite` 开发循环、单实例与退出编排 |
| M2 | 输入框、流式回合、工具卡片实时更新、Claude/Codex 审批、Antigravity 软拒提示、中断、会话级参数 |
| M3 | 原生配置完整编辑、启动环境注入、服务器面板改以服务器档案为身份、命令面板补齐 |
| M4 | 目录监听实时刷新、键盘与可访问性打磨、CLI 升级后重新探测、安装包与自动更新 |

另不包含：多用户或局域网访问、内置 IDE/看板/浏览器、跨 CLI 切换会话、多 Agent 编排、手机端适配。

## 6. M1 验收标准

| 编号 | 场景 | 通过条件 |
|---|---|---|
| A1 | 添加项目目录 | 填入存在且为绝对路径的目录时加入列表；相对路径与不存在的目录被拒绝并说明字段 |
| A2 | 项目绑定服务器（接口） | 只填 `server` 或只填 `remoteDir` 被拒绝；两者同时填写且档案存在时保存成功；都不填时项目仍可正常查看。M1 没有绑定表单，本条按接口验证 |
| A3 | 移除项目（接口） | 只删除本工具里的项目记录；项目目录、原生会话与已保存的服务器档案都不受影响 |
| A4 | 首次启动且旧目录存在 | `servers.json` 与 `workspaces.json` 被复制到新目录；旧字段完成改写，同步/命令规则字段被丢弃，原文件与坏行备份保留 |
| A5 | 展开一个含多个 CLI 会话的项目 | 列表按 Claude / Codex / Antigravity 分组出现，标题、相对时间与数量正确 |
| A6 | 会话归属 | Claude/Codex 的 `cwd`、Antigravity 的 `workspace_uris` 命中项目目录时出现在该项目；解析不出时 `projectId` 为 `null`，默认不显示 |
| A7 | 打开「显示其他目录的会话」 | 无归属会话集中出现，可从这里添加项目；不会混进任意已有项目 |
| A8 | 打开 Claude 或 Codex 会话 | 历史正文与工具事件可读，切换会话后旧请求被取消；本产品磁盘上没有新增正文副本 |
| A9 | 打开 Antigravity 会话 | 标题、时间与归属可见；正文区显示「私有轨迹无法读取」的说明，不是空白或报错页 |
| A10 | 三个 CLI 的探测 | 每个 CLI 得到四态之一，并列出缺失的选项或环境变量；探测只跑本地命令，不请求模型端点 |
| A11 | 只读边界 | 主区没有输入框、发送按钮、停止按钮或审批入口；界面不存在同步、版本、本地文件与改动视图入口 |
| A12 | 打开服务器面板 | 未绑定服务器的项目给出绑定提示，终端不能新建标签；绑定后终端、资源（含 Slurm）与文件视图可用 |
| A13 | 启动应用时观察网络 | 只发生本机探测与配置/会话读取，不启动能力目录、不发起模型请求 |
| A14 | 960 / 1280 / 1600 宽度与明暗主题 | 三段布局可用，左栏 200–320px、服务器面板 360–720px 有界，无整页横向溢出 |
