# 后台任务与手动结果读取验收

日期：2026-10-05。对应 F3、A17、D16/D20 及架构 V17。生产源码沿用 `8041919`；使用实际网页、Codex 原生运行时、MCP、SSH 和服务器已有 Python。本轮只补专项证据，不增加任务监测器、产品代码或单元测试。

## 实际链路

1. 在已授权目标下新建独立随机目录，先将有限 Python 脚本写入临时本地工作区，通过生产向导验证与实际 rclone 首次同步到服务器。
2. Edge 网页新建 Codex 会话，用户要求只调用一次 `remote_exec`，通过 `nohup` 提交脚本并立即结束回复。脚本等待 120 秒后产生小 JSON 结果和 16 MiB 数据文件；原生轮次已正常结束时，独立 SSH 确认后台任务开始且尚未完成。
3. 网页保持打开 150 秒，没有再次发送用户消息。每 30 秒仅检查已经收到的网页协议帧，未出现新 `turn.started`、工具调用或 AI 流式文本。等待结束后独立 SSH 确认任务已自然完成；没有让 Agent 查询或轮询任务。
4. 用户再次在网页明确要求查看结果。同原生会话 ID 通过实际 `remote_exec` 和已有 `python3` 读取小 JSON，返回随机标记与必要统计字段；工具调用 ID 与结果绑定，网页展开工具卡展示真实结果。
5. 同步回到 `ready` 后，16 MiB 数据文件仍未进入本地。两轮正常收尾、无页面错误，本机原生源配置摘要保持，新增配置副本与本次随机远端根清理通过。

## 证据边界与决策

该观察补齐“先提交后台任务、等待期间不自动唤起 AI、用户再发消息读取远端结果”的具体行为。普通小文件同步及独立资源采样仍按各自规则进行，不能把同步小 JSON 等同于自动结果分析。等待期间的 SSH 开始/结束检查由验收程序执行，不属于产品完成检测；产品没有任务完成观察器。

采用有限 `nohup` 任务，避免安装服务或依赖服务器拥有 Slurm。不把 150 秒观察扩大为任意时长、所有调度器或训练环境的运行保证；超时/输出限制和多活动组合继续见[完整链路验收](real-workflow-acceptance.md)。本次模型身份检查未包含用户禁止的模型，没有续接历史代理。

后台程序仅操作本次随机目录，自然结束后才清理；不停止用户训练进程，不读取既有项目数据。实际连接、原始消息和截图只保留 ignored，聚合记录保留两次用户轮次、两次真实工具调用、同原生 ID、等待窗口、数据留远端和收尾证据。此前被自动策略拒绝清理的旧副本未触碰。
