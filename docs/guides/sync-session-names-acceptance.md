## 证据边界与裁定

- 选择固定版本 combine 单上游，放弃已证明无效的 alias，以及至少需要两个上游的 union。不改变两端实际文件位置。
- 目标签名继续 mirror-v1，布局独立保存为 combine-v1；旧状态可读取，只有成功回写才记录新布局。旧服务器任务不因内部布局变化被误判为目标改变。
- 映射每次按实际固定镜像或任务镜像构造，CSV 内双引号翻倍，反斜杠原样保留；复制的子进程凭据在 finally 清除。
- Windows rclone fspath.Parse 会把远端根中的反斜杠转成斜杠。真实该目录探测停在原 workspace lsjson，返回 directory not found，属于既有路径工具边界；不标为 combine 传输通过。
- 旧升级探针与特殊字符、任务探针使用独立根。未解决冲突原路径可能不存在，不能拿它直接做后续重命名探针；调整 fixture 后重新验证相关场景。
- 只运行受影响同步和文件任务验证；核心 Review 后集中补最少回归，不重跑双 Agent、浏览器或未受影响全量基线。
- 被自动策略拒绝的原生界面读取和早期配置副本清理不重试，不换工具绕过。A8、原生 OS 输入法及 Edge 系统保存选择器保持未验；整个 Goal 继续进行。

## 核心 Review 与回归

本阶段仅派一次新的独立核心 Reviewer（gpt-6.1-sol/high），无 Critical 或 Minor；一项 Important 是旧待删除入口先清空状态、后触发布局门禁，丢失临时批准。修复前批准/拒绝两项回归 RED，修复后 GREEN；不复审。

裁定批准/拒绝先检查布局，保留删除列表与摘要，明确提示请求尚未处理，恢复会重新拉取，之后须重新核对删除。这样不自动把删除点击变成初始化授权，代价是旧待删除场景升级后需再次确认删除。真实SSH复验通过。

Review 后集中增加五项核心回归：普通升级门禁/失败不保存布局、旧持久任务与真实目标变化、旧待删除批准/拒绝、CSV映射与凭据副本成功/异常清理。旧源码全部五项 RED，恢复修复后两文件38项 GREEN；相关同步/任务/HTTP 共85项通过。单轮修复自检另补一项“待删除缺少目标签名不得读取/删除”的保护回归，修正共享检查的严格绑定要求，RED→GREEN后两文件39项通过。共六项新增核心回归。旧源码探针未移动HEAD或索引，finally还原源码并核对字节一致。

阶段完整 `npm run check` 退出0：108个测试文件通过、1个既有跳过，733项通过、5项既有跳过。类型、lint、格式、重复率和覆盖率门槛通过；语句85.64%、分支79.05%、函数86.51%、行89.21%，重复行0.35%。随后缺签名保护只增量验证关联测试、服务端类型和lint，最终完整门禁交由PR/main的双平台CI核对。没有降低门槛或重复未受影响的GUI/双Agent验收。
