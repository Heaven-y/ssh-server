# 本机入口与统一服务器档案验收

日期：2026-10-07。设计依据：[D37设计](../superpowers/specs/2026-10-07-local-entry-server-profiles-design.md)、[实施计划](../superpowers/plans/2026-10-07-local-entry-server-profiles.md)。

## 交付范围

按用户“尚未使用，只维护一个版本”的确认直接替换接口和结构，不保留旧令牌登录、工作区认证字段、隐式SSH config连接或旧主机列表接口，不迁移旧配置。D36的数据保护、当前格式恢复、显式Agent与唯一下载路径继续有效。

| 目标 | 当前实现及检查结果 |
|---|---|
| 纯端口进入 | 打开 `http://127.0.0.1:4317/`，同源 `POST /api/local-session {}` 获取HttpOnly、SameSite=Strict Cookie；成功后才挂载业务API与WS，失败可重试 |
| 集中服务器管理 | 顶栏及向导共用同一管理窗口；支持新增、显式导入SSH config、编辑、确认删除、私钥/密码认证及保存密码 |
| 工作区只选目录 | 只保存登记服务器alias、本地目录和远端目录及现行业务选项；验证票与首次同步确认仍必需，不携带密码或authMode |
| 共享保护 | expected陈旧、引用目标改变、活动任务及未完成持久状态均受保护；固定终端/浏览绑定核对中央认证指纹和代次 |
| 浅色首次体验 | 默认浅色，顶栏明确显示切换目标“深色/浅色”，刷新保留选择；CodeMirror沿用主题订阅，xterm切换不重建PTY |
| 启动依赖提示 | main启动与网页共用环境报告；GET复用、POST手动刷新；缺失提供官方安装/配置指引，不阻止服务器管理 |

## 安全与数据边界

- 自动握手不是匿名开放API：继续本机监听、精确Host/端口、Origin、Fetch Metadata、Cookie与内部Bearer边界；页面及错误响应禁止外部iframe嵌入。
- 旧 `/auth` 和 `/api/ssh-hosts` 返回404；未知字段被严格拒绝。秘密不出现在启动URL、响应正文、工作区配置或Agent输入中。
- 服务器存储按档案当前格式严格读取，坏JSON/条目/读取错误阻断并保留原文；没有清空或迁移兜底。
- 工作区快照→活动排他→档案写队列按同一顺序取得；档案提交回调不重入前置队列。删除以已核对身份清除凭据，清理失败保留档案，不假报删除成功。
- 主动断开保留磁盘密码；取消保存和删除档案清除保存项。新增不同alias但实际目标相同，不能恢复已删除凭据。
- 环境检测只证明程序可执行。未知版本可显示“版本未知”，不会判为不兼容；不检查登录、不调用模型、不自动安装、升级或修改原生配置。Claude沿用SDK实际原生入口，Codex沿用实际启动解析。

## 集中审查与定向修复

本轮仅一次集中只读审查，发现两项P2，均先复现再修复：

1. 密码留空且保存状态未改变时，网页仍发送savePassword，误触发重认证保护。现仅在输入新密码或保存选项变化时发送该字段；普通检查取消也不关闭共享连接。
2. 删除档案只断开连接，磁盘密码未清除。现先以锁内已核对的身份失效内存和保存凭据，再提交档案删除；不重新解析目标或重入档案队列，凭据清理失败时保留档案。

浏览器另发现浅色终端底部滚动层默认黑色，已用现有主题变量局部修复并通过原失败断言复验。没有因这些问题重新进行第二轮广泛审查。

## 未检查及既有边界

- 未调用真实Claude/Codex模型，未测试真实用户服务器、训练任务或大数据传输；本轮不重复此前未受影响的业务验收。
- 终端为真实SSH协议配合合成shell输出，不等同外部Linux交互程序、输入法或操作系统控件验收。
- 已引用且配置专用keyFile的档案不能切换为密码，因为同时会改变受保护的私钥目标；页面有明确说明。
- 锁覆盖本进程正式入口，不新增多进程共同编辑同一配置目录的OS级锁。
- 旧验收中的token入口、工作区认证和默认深色仅为当时事实；当前流程以本记录与D37为准。
