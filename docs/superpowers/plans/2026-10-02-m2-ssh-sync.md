# M2：SSH 认证与同步实施计划

> 执行方式：本会话内联实施，按测试失败 → 实现 → 验证推进；用户已要求直接开发并在完成阶段时提交，不再次请求执行许可，不推送。

**目标：** 本地编辑自动进入远端执行链路，支持私钥与内存密码认证，并安全处理同步失败、删除与冲突。

**架构：** 同一个 SSH 参数解析器供连接池与 rclone 使用。按工作区串行调度同步/执行事务，通过 REST 状态和 MCP 工具反馈到网页。

**技术栈：** Node.js 22、TypeScript、Fastify、ssh2、rclone 1.75.1、React。

**设计：** [M2 设计](../specs/2026-10-02-m2-ssh-sync-design.md)。

## 全局约束

- 中文输出，UTF-8/LF，真实连接信息不进入仓库。
- 本阶段连接使用内存密码；独立 Windows 加密存储核心已验证，保存、复用与取消保存选项按[后续实施计划](2026-10-02-local-credentials-agent-settings.md)接入。明文不写配置、日志、argv、Agent 或浏览器持久存储。
- 保持 known_hosts 校验，不在服务器安装软件或生成工作区以外文件，不创建备份/快照。
- 每次真实验证使用调用时提供的专用目录，先检查空目录与安全边界。
- 当前功能分支已有隔离，不修改 `.pi/`；外部验证工具和诊断放会话临时目录。

## 重点验证条件

1. Host 指向的地址/账号发生变化：旧密码和连接不能继续使用。
2. 同步失败或待确认：SSH 命令不能执行；后同步失败仍返回真实退出码。
3. 删除确认期间文件重新出现或远端修改：不得删除新文件或覆盖新本地内容。
4. 相同文件双边修改、大小过滤变化、状态损坏：保留数据并停止自动覆盖。
5. 并发同步与可见性变化：同工作区不重叠，其他工作区和 HTTP 保持响应。

## Task 2：连接路由与网页入口
