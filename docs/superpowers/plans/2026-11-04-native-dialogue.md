# 原生对话主线实施计划

> 执行方式：使用 subagent-driven-development 分配独立任务；主控整合并验证。用户已授权继续实施和按阶段提交，不推送。模型与推理强度继承当前会话。

**目标：** 完成三种 CLI 的新建、续聊与可控回合，先交付主功能，再做插件。

**架构：** 复用已有对话视图和回合管理器；独立增加 Antigravity 运行器，统一本机可执行程序解析。界面保持各原生能力的差异。

**技术栈：** Electron、Node.js 22+、TypeScript、Fastify、React 19、Vitest。

**设计依据：** [原生对话接入](../../engineering/native-dialogue.md)。

## 全局约束

- 先整理有效文档并保留 `c686ef2` 历史锚点，再实现核心对话。
- 不改 SSH 或实现插件，不发送真实模型请求，不写用户原生配置。
- 所有新文本使用中文；示例采用合成身份；测试路径用临时目录或相对路径生成。
- 能力刷新只能由用户点击；默认模型/强度不覆盖原生配置。
- 不同工作项只编辑分配文件；主控分阶段提交，合并用 `--no-ff`。

## 审查重点

1. 打开界面、菜单、输入斜杠时是否误发能力发现请求。
2. 新会话原生 id 回填后是否错清草稿或混入另一会话事件。
3. 读取历史失败、Antigravity 不可回放是否被错误等同。
4. 停止、断线、非法参数是否留下无法结束的回合或进程。
5. 未选模型/强度、CLI 自升级或缺失时是否静默覆盖/回退。
