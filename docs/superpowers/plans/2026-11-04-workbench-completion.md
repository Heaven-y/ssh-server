# 工作台整体交付计划

> 按 subagent-driven-development 分配独立文件，继承当前模型与推理强度。用户已要求完成现行整体计划，授权本地分支、提交及整合；2026-11-04 明确只交付本地安装包，暂不发布。

**目标：** 完成三 CLI 原生配置、自有插件及独立 SSH Console，并交付可安装的 Windows 本地版本。

**架构：** CLI 保持原生数据与权限语义；工作台通过固定资源描述和受控启动环境提供配置入口。插件采用自己的安装清单、生命周期与页面接口，首个内置插件复用现有 SSH 业务。桌面端管理服务生命周期并包含前端产物。

**技术栈：** 现有 TypeScript、Fastify、React、Electron、ssh2、xterm，采用成熟打包组件。

**依据：** [产品需求](../../product/requirements.md)、[现行决策](../../engineering/decisions.md)、[路线图](../../roadmap.md)。

## 全局约束

- 优先配置，再插件与 SSH，最后打磨和本地安装包；各阶段以独立小分支提交并 --no-ff 合入大功能分支。
- 不复制原生会话，不覆盖 CLI 默认模型，不强造三 CLI 通用配置层级，不兼容 DSH 包。
- 本机目录/会话正文/秘密不得进入公开产物；原生配置正文只在显式打开时返回，离开视图即清理。
- 原生文件原文、语法、revision 和路径身份校验继续保留；服务端仅接受已知资源身份。
- 启动环境按 CLI 白名单保存、用系统加密保护、接口不回填旧值；运行中不悄悄重启。
- 插件关闭页面与停用分开；真正停用必须清理资源，失败不能标记为成功。
- 不触碰用户的真实会话或远端写入来代替隔离验证。真实端点验收单独记录，不由模拟结果推定。
- 本轮不发布、不推送、不要求签名证书；线上签名和更新发布按用户要求暂缓。

## 审查重点

1. 配置作用域与真实 CLI 一致，缺失和未知不是空文件，也不能因保存而静默覆盖外部修改。
2. 配置列表与错误不泄露秘密，启动环境不接受加载器变量或跨 CLI 注入。
3. 项目切换、页面关闭和插件停用分别执行正确的资源生命周期，不杀掉仍在使用的终端。
4. 多服务器及多个 PTY 的身份不依赖当前项目；主机密钥失败时不能提前发送认证材料。
5. 安装包在没有仓库源码或 node_modules 的环境中能启动，退出清理；不会自动请求模型或发布。
