# 工作台后续功能实施计划

> 执行：按任务持续完成，独立模块可并行开发，整合后审查。用户已授权自主制定方案并执行，账号登录验证暂缓。

**目标：** 合并会话复制入口，完善连接恢复与原生工具实测，对齐 SSH Console 更新。

**架构：** 保留 React、Fastify、Electron 和各 CLI 原生会话。恢复事件只在后端内存暂存，浏览器只保存不含正文的恢复身份；SSH 沿用自有内置插件和现有连接池。

**范围依据：** 本轮用户要求及现行需求、原生接入和插件文档。参考插件只读，不建设 DSH 兼容层。

## 全局约束

- 账号登录、公开发布、版本升级和新安装包制作暂缓，按现有 URL/Key 进行有界验证。
- 不改用户配置、真实会话正文或运行实例；真实模型使用新建隔离目录和合成内容。敏感配置不输出、不入库。
- 功能分支开发，验证后按既有授权合入本地 main，不推送。
- 仅新增核心回归，先复现再修复，分范围验证。跨模块整合补类型、规范、文档和构建。
- 原生未提供的数据保持未知；全应用退出仍清理子进程，不暗中引入后台常驻服务。

## 设计决定

- 菜单保留一个“复制会话链接”，原生 ID 在详情中可选中；复制内容继续是包含 CLI、工作区和 ID 的稳定引用。
- 连接恢复采用浏览器页签身份与后端有界事件缓存。短暂断线保留回合和审批，重连去重接收，刷新重建本轮；不可恢复时明确引导重读原生历史，不自动重发用户消息。
- 长期断开、缓存超限和退出应用明确收尾，不把缺失输出伪装完整。恢复权限沿用本机会话认证，其他页签不能接管原回合。
- SSH 同步全磁盘与剩余空间、负载时间窗及每核数值，核对文件导航、分屏焦点和查找高亮差异；已有 GPU 与多终端能力保留。

## 审查重点

1. 旧连接迟到消息、并行回合与重复恢复不会串会话或重发操作。
2. 审批断线后仍待用户决定；超时和停止后不能复活。
3. 缓存淘汰或后端重启不会导致永久忙态、假成功或泄露给其他页签。
4. 磁盘缺失、空格挂载点与 CPU 核数缺失不产生假零值或错误比例。
5. 文件导航、分屏及搜索的异步结果不覆盖后来选择的目标。
