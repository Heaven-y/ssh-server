# M2：SSH 认证与同步设计

本设计落实已确认的需求 F1、F3、F5，继续 Node.js + TypeScript + Fastify。用户已明确要求直接开发、验证并在完成阶段时提交，沿当前功能分支内联执行；不推送。测试参数仅在本地验收时提供，本文使用通用示例。

## 1. 目标与边界

- 支持已有 Host 的私钥和账号密码认证；提供测试连接、重新认证和主动断开入口。
- 本阶段连接密码保留在后端内存，不进入工作区 JSON、浏览器持久存储、Agent、日志或命令行参数。可选系统加密保存、主动断开后复用及取消保存勾选按[本机凭据设计](2026-10-02-local-credentials-agent-settings-design.md)继续接入。
- 引入 rclone 1.75.1，通过 SFTP 同步代码和小文件，默认上限 10 MiB，固定排除 `.git`，默认排除数据、权重和压缩包扩展名。
- 执行前同步成功且没有待处理删除、冲突后才执行；执行后与轮次结束同步，后置同步失败不抹掉真实命令结果。
- 手动同步、工作区可见时定时同步不调用模型，不检测训练完成。
- 手动连接参数、完整目录浏览与网页指纹确认在 M5 完成；本阶段未知主机仍提示先通过本机 SSH 核对指纹，密钥变化与吊销拒绝连接。
- 不在服务器安装软件、放置标记、配置、凭据、对话或备份；测试只在用户指定的测试目录内创建自己的小文件。

## 2. 认证与连接

工作区新增可选 `authMode: 'key' | 'password'`，旧记录默认私钥。后端 `SshTarget` 包含 Host 与认证方式。连接参数由同一个 resolver 读取本机 SSH config、私钥与 known_hosts，供 exec 和 rclone 使用。

密码按 Host 存在内存 vault，替换或清除时递增认证代次并关闭旧连接。缓存还包含解析后的地址、端口、账号及认证方式，防止修改配置后继续使用旧目标。密码模式不尝试私钥、不静默降级；未认证、认证失败、连接失败、未知/变化/吊销主机密钥分别返回明确状态。错误不包含密码或底层完整连接配置。

连接测试使用工作区目录内的只读命令，核对目录存在且可进入。工作区表单包含认证方式、临时密码和测试入口；现有工作区有重新认证与断开入口。删除工作区不删除项目文件。

## 3. rclone 调用

- 外部可执行文件由 PATH 或 `SSH_SERVER_RCLONE` 选择，缺失时明确失败；不自动降级为未同步执行。
- 通过独立子进程环境 `RCLONE_CONFIG_WORKSPACE_*` 定义 SFTP remote，`--config` 使用空配置路径，不写全局 rclone 配置。
- 明确传入 known_hosts 路径、关闭自动信任和密码询问；禁止跟随远端符号链接。密码经 stdin 调用 `rclone obscure`，混淆值只放子进程环境，混淆不是加密存储。
- 参数不含密码/私钥内容；原始 stderr 不直接给 Agent 或公开日志。进程有超时、输出上限和清理逻辑。
- 使用 `bisync`，状态、过滤文件及本工具的成功清单保存在本机配置目录的工作区子目录。传输源为固定 `mirror` 小文件副本，保留文件内容与 mtime；复制期间源发生变化则暂停，同步后应用结果前重新检查项目文件身份与摘要，保留同步过程中发生的新编辑或删除。
- 普通同步使用 `--conflict-resolve none --conflict-loser num` 并区分本地/远端冲突后缀，保留两个版本；不使用备份目录或 `--check-access`。
- 断开、替换凭据或退出取消活动子进程；每个结果检查其认证代次，过期认证失败不能清除更新的凭据。普通 `.git` 文件及目录在任意层级均排除。

## 4. 初始化、删除与冲突

首次本地目录为空时拉取符合规则的远端文件，再建立 bisync 基线。非空本地目录不得自动 `--resync`；提示确认初始化，并先检查同名差异，保留双方版本后建立基线。初始化失败不允许普通执行。

成功清单由本工具保存，后续对比本地清单找出删除路径，不依赖解析 rclone 内部清单格式。rclone 官方说明：更改 `--filters-file` 会要求 resync；用其他临时过滤跳过文件也可能使其被判为删除。因此本阶段待确认删除暂停该工作区整次同步事务，其他工作区独立运行，不能为继续同步而自动 resync。确认后仅删除已列出的安全相对路径；拒绝后从远端恢复，远端已改动时恢复最新版本。决策期间重新检查，不操作路径越界、符号链接或已经重新出现的本地文件。

普通冲突保留双方版本并记录待处理事项；用户将选定版本恢复为原路径并确认后解除执行阻断。修改过滤规则需要受控重建基线，不能把新排除文件当作删除传播。状态文件损坏、rclone 部分失败、目录目标变更均停下来报告，不自动清空状态或选择一端覆盖。

## 5. 调度与执行

每个工作区一条异步同步队列；不同工作区不共用锁。远程命令的前同步、执行、后同步位于同一个工作区事务内，避免另一同步在命令运行时改变代码。单个命令有既有超时/输出上限，其他工作区和对话流保持响应。

状态包含未初始化、运行中、成功、待确认、失败，最近成功时间、删除路径和冲突路径。HTTP 提供状态、同步、初始化、删除决策、冲突确认、过滤设置。MCP 新增 `sync_now`；Agent 指令改为说明真实同步语义、执行阻断、用户手动查看结果与远端已有 Python 环境。

定时同步仅在工作区页面可见且没有同步请求进行时触发，刷新间隔先取 15 秒；隐藏页面停止定时请求。不自动发对话消息。

## 6. 验证

- 先写失败测试：密码隔离与清除、认证模式不降级、known_hosts 拒绝、连接配置变化、过滤与路径边界、同工作区串行/不同工作区并行、删除拒绝恢复、冲突阻断、前失败不执行、后失败保留退出码。
- 使用本机受控 SSH/SFTP fixture 验证密码认证，不需要用户提供真实服务器密码。
- 用户指定的专用目录中验证私钥、首次同步、双向小文件、排除大文件/权重/`.git`、删除确认和拒绝、冲突双版本、同步失败阻断及已有 Python 执行。不访问或修改其他远端目录。
- 浏览器验证登录、工作区表单、认证/同步状态、工具卡、审批、中断、历史与黑名单；截图仅放会话临时目录。
- 运行 `npm.cmd run check`、网页构建、真实 M1/M2 验收，文档仅记录匿名结论与未验证部分。
