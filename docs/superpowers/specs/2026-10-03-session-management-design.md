# 原生会话管理

继续已授权的 M4：补齐需求 F7.2/F7.3 和界面已有目标中的重命名。保持双 Agent 原生存储与现有对话体验，不创建网页对话数据库。基线为 164175e。

## 操作与原生接口

- Claude 重命名/删除使用 SDK `renameSession` / `deleteSession`，固定传入工作区目录，操作前读取原始 metadata 验证 ID 和 cwd。
- Codex 使用 `thread/name/set`、`thread/delete`、`thread/archive`、`thread/unarchive`。操作前用 `thread/read` 验证 ID/cwd，并拒绝已知 active 状态和内部子代理。不通过手工删除 JSONL 实现产品功能。
- Codex 归档列表通过 `thread/list(archived: true)` 获取，保留现有分页、工作区过滤和子代理排除。普通列表仍只读未归档项；Claude 不提供归档入口。
- 原生删除会影响相关子会话；Codex 归档也可能归档其派生子会话。确认文案说明这些影响。恢复以官方返回为准，不假称自动恢复所有后代。
- 官方依据：[app-server](https://developers.openai.com/codex/app-server/) 已抓取文档与本机 0.156.1 导出协议；Claude 以当前安装 SDK 类型及真实隔离存储实验为依据。

## 并发与边界

- 在 TurnManager 现有 `(agent, sessionId)` 锁上增加 `withIdleSession`，原生操作从验证前到结果返回始终占锁；同 ID 的另一 Agent 不互相阻塞。
- 正在运行、准备、同步收尾或已有管理操作时返回 409，不中断或删除它。对话启动也不能抢占管理操作的锁；finally 只释放自身占用。
- 身份和目录校验在后端执行，不能只相信网页列表。所有操作失败只返回匿名可操作错误，不回显原生配置诊断。
- 删除请求必须携带 `confirmed: true`；重命名标题去首尾空白后为 1–200 个字符。未识别 action、Claude 归档和非法 ID 拒绝。
- 管理请求一旦发给原生运行时，网页断开不把“取消等待”当作回滚；继续等待原生结果并释放锁。网页重新读取可确定实际状态。
- 本后端可保证自己持有的轮次互斥；其他客户端对同一原生记录的并发不伪装成可统一控制。验收区分真实原生存储更新与插件界面实际刷新。

## 界面与状态

- 沿用中性深色列表，条目增加带无障碍名称的“更多”按钮；使用已有原生 dialog 模式承载重命名、归档/恢复和删除确认，默认焦点在非破坏性控件。
- 列表顶部切换“会话 / 已归档”，归档视图只查询 Codex；普通视图继续独立加载两类来源。按需查询，不为每个条目额外请求。
- 已归档条目可删除、恢复，恢复后从普通列表继续或重命名；不直接发送消息隐式恢复归档。本机 0.156.1 实验确认 `thread/name/set` 不接受归档记录，因此不在归档视图提供改名，也不为改名隐式恢复。
- 操作中禁止重复提交并显示状态。后端失败保留条目与错误，成功后刷新对应工作区/Agent 的列表；不乐观假装成功。
- 删除/归档成功时仅清空仍匹配该工作区、Agent、ID 的当前对话；切换到其他会话后迟到结果不得清空新选择。当前目标管理操作期间禁止发送，同步后端互斥。

## 验证与交付

先实现并 review 核心目标，再补少量核心测试：同 ID 跨 Agent、运行/管理互斥、失败释放、越界阻断、确认校验、归档列表和迟到前端结果。类型、lint、格式、定向测试/覆盖率、构建按实际影响范围验证。

真实无模型验收使用临时合成 Claude/Codex 原生会话，执行重命名、归档/恢复与删除，验证官方读取/列表及文件存储结果。绝不删除用户原生历史，也不需要真实模型或 SSH。浏览器检查菜单、确认、错误、归档恢复和三种桌面宽度。A8 的 VS Code 插件实际界面若未观察到，不标全项完成。
