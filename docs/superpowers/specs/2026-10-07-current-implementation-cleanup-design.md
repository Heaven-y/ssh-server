## 2. 现行单一路径

### C01 工作区与Agent请求

工作区 POST 只接受已验证向导票据，DELETE 只走已确认的移除服务；删除通用 PATCH，修改同步/规则继续用专用串行接口。应用装配缺少对应服务时明确不可用，不能退回直接存储CRUD；测试可以注入服务，但产品不再为旧夹具实现备用写路径。

聊天WS和会话HTTP请求必须明确Agent。新会话默认Agent属于产品设置，不是网络协议缺字段时猜测Claude。前端删除旧createWorkspace封装，列表/历史/查询键要求显式Agent。

### C02 运行时与内部契约

- TurnManager只接收runners注册表，main显式组装Claude/Codex；删除runTurn旧注入入口及管理器内隐式Claude默认。
- 固定Claude SDK的close、supportedCommands、supportedModels、getContextUsage，以及原生会话rename/delete和provider.mutate使用必需契约。删除“旧替身没实现方法”的分支，补齐测试替身；保留运行失败、超时、空数据、缺cwd的合法读取和管理拒绝。
- 会话操作锁是管理服务的必需依赖；保留两类官方运行时不同事件/审批结构。
- SSH内部目标统一为`{ alias, authMode }`；工作区默认私钥在workspaceTarget集中解释，不保留裸字符串重载。
- 资源采样只接受`{ signal, timeoutMs }`；rclone版本检查只保留一份实现，成功缓存和失败重试不变。
- Codex官方npm发行的JS入口和平台二进制定位是当前安装机制，不是已证实无用的旧协议，保留。CodeMirror legacy-modes同理。

### C03 持久状态不迁移、不丢失

只读取当前格式。同步状态仍使用version=1、mirror-v1目标签名和combine-v1布局；正常未初始化状态可没有基线。已有基线缺少或不同布局时明确不支持，不提供“确认升级”路径，不改写旧文件。当前格式中断恢复、删除确认和冲突保留继续工作。

远端任务持久记录必须有syncRequired和dispatched；不自动为旧缺字段记录补值。任务目录非ENOENT错误、坏记录、对象ID不一致不能视为无任务，也不能允许新操作或工作区移除。原文件保留，错误匿名且可操作；不得在启动时产生未处理Promise拒绝。当前任务的取消/结果核对/同步恢复不重放仍保留。

工作区配置只有ENOENT表示首次空配置。读错、坏JSON/错误结构不返回空列表，不过滤掉坏条目继续保存，也不自动备份后重置；明确拒绝读写并保留原文件。此规则是本轮发现的数据保护修复，不是新增迁移工具。

### C04 下载

仅保留File System Access API的“选择保存位置→读取HTTP流→逐块写入→关闭后确认成功”实现。浏览器缺少该能力时明确说明不可用，不切换到下载管理器，不开始网络传输。仍支持进度字节数、取消和关闭清理；取消选择器不触发下载。不声称受控测试验证了OS选择器本身。
